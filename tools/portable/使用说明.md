# AI 浏览器工作台：Windows x64 便携测试包

日期：2026-11-05。版本：0.1.13 开发验证版。本包包含当前已实现程序及全部自有工程源码；完整产品计划尚未全部完成。根目录[文档入口](文档入口.md)提供复盘测试、详细操作、运行环境和开发编译及API等文档。

## 快速使用

把整个目录或 ZIP 复制到 Windows 10/11 x64 电脑，ZIP 先完整解压到本机可写目录。测试电脑无需安装 VS、Python、Node 或 VC 运行库；匹配的 Release VC142 DLL 和固定 Chrome for Testing 已包含在包内。不要只复制某个 EXE，也不要从压缩包内直接运行。

1. 双击 `Start-Workbench.cmd` 或 `workbench.exe` 打开桌面。
2. 输入环境名称和待测试站点的 HTTP(S) 地址，创建环境，启动，再打开地址。
3. 输入 CSS 选择器，例如 `#username`、`#password`，定位后填写；选择 `#login`、`#register` 点击，再读取结果元素确认业务是否成功。站点选择器以实际网页为准。
4. 双击 `Self-Test.cmd` 运行离线自检。结果显示在窗口并保存在 `test-results/run-*/report.json`；自检不需要公网，不操作真实网站账号。

自检核对逐文件 SHA-256，运行核心、SQLite、真实窗口测试，再启动随机回环端口夹具，经包内 CLI/浏览器完成填写、点击及服务器确认，验证 MCP 握手和工具列表、实际加载包内VC运行库、从无关工作目录启动时的数据位置。它是便携运行检查，不等于全部产品用例或第二台干净机已验收。重建或修改source后会导致初始哈希不匹配；开发中可显式用Self-Test.ps1 -SkipHashCheck运行行为检查，正式复制请使用原始ZIP。

默认数据根探针在test-results内独立运行，自检可在桌面已打开时执行，不占用或修改正在使用的桌面data目录。已修复新建多环境后列表选错环境、异常协议输入以及中文CSS长度问题；实际版本以capabilities或package-manifest.json为准。

## 文件与数据

| 路径 | 用途 |
| --- | --- |
| workbench.exe | 原生桌面界面 |
| workbench-cli.exe / Start-CLI.cmd | JSONL 自动化入口 |
| workbench-mcp.exe / Start-MCP.cmd | AI 客户端 MCP stdio 入口 |
| Start-API.cmd | 本地鉴权HTTP API，独立data/api，令牌见local-api.json |
| workbench-admin.exe / Start-Admin.cmd | 独立后台与中文门户，首次初始化无默认密码 |
| workbench-node.exe / Start-Node.ps1 / Stop-Node.ps1 | 签名出站执行节点，使用私有配置 |
| awb-core-tests.exe / awb-storage-tests.exe | 核心与数据库测试程序 |
| *.dll | 匹配的 VC2019 x64 Release 运行库 |
| browser/chrome-win64 | 保持官方目录结构的固定开发测试浏览器 |
| data | 首次启动后创建的环境、元数据与站点数据；桌面默认 data/desktop，脚本 CLI/MCP 分别独立 |
| source/AIBrowserWorkbench.sln | 完整原生 VS2019 解决方案及全部当前源码 |
| licenses / browser/runtime-origin.json | 来源、版权声明和固定运行时校验信息 |
| package-manifest.json | 不含自身和后续用户数据的初始逐文件校验清单 |

程序按自身目录定位浏览器和 data；从快捷方式或其他工作目录启动也可用。`portable.mode` 是便携标志，保持内容不变。CLI 和 MCP 直接启动 EXE 时可用 `--root` 显式选择独立目录；同一个数据根不允许多个服务同时占用。已有用户目录不会被自动接管。

data 内可能包含登录态和站点秘密。跨机器复制程序用于测试时，使用原始 ZIP 中不含用户数据的版本；本包未承诺 Windows 加密的 Cookie/凭据能够跨机器迁移。请勿将日常使用后的整个 data 当作公开测试包。

JSONL 示例：启动 `Start-CLI.cmd` 后输入下面一行，再按回车；关闭输入或退出程序会关闭其管理的浏览器。

```json
{"id":1,"command":"capabilities","arguments":{}}
```

AI 客户端配置见 `mcp-config.example.json`，将 PACKAGE_DIRECTORY 替换为解压后的绝对目录，路径可使用 `/`。桌面和 MCP 使用不同根，测试环境也分别创建。

## 开发和限制

开发电脑安装 VS2019 16.11 的“使用 C++ 的桌面开发”、v142 14.29.30133、Windows SDK 10.0.19041.0。打开 `source/AIBrowserWorkbench.sln`，选择 x64 / Debug 或 Release，默认启动项目为 workbench。也可双击 `source/Build-VS2019.cmd`；产物在 `source/build/native-vs2019/x64/配置`。自有代码保持 C++14，函数附中文用途和日期。完整 CMake 构建入口仍保留。

该工程包含当前所有实际模块和本地有界流程；完整后台、跨frame录制/高级画布及商业功能仍未完成；本轮已增加凭据/调试/模型/知识包和双SDK。官方支付/企业登录/单协调器多节点的操作和真实外部验收边界见文档45；其余完整产品范围见 `source/docs/13_执行记录与验收台账.md`。包内浏览器供用户要求的复制开发测试，保留官方 ABOUT/版权信息和 chrome://credits、chrome://terms；它不是自有内核或商业分发发行包。系统浏览器和系统设置不会被替换。

如果无法启动，先运行自检并带回 report.json 与相应日志；目录需位于本地可写盘，系统需支持所附 Chrome 版本。企业策略、杀毒拦截、网络盘、Windows Server 和实际第二台干净机器仍需分别测试。开发测试包暂未做代码签名、安装器和自动更新。

## 后台与商业管理（0.1.12）

双击 `Start-Admin.cmd` 启动独立后台及中文门户，首次初始化密钥位于 `data/admin/bootstrap.key`。工作台菜单“环境库与本地后台 → 后台账号与授权（表单）”可登录、查询额度并打开门户。关闭后台运行 `Stop-Admin.ps1`。详细的收款、续费、席位、时长、退款及配置流程见 `source/docs/42_后台支付席位与计时实现测试及操作指南.md`。

0.1.12历史版本的支付渠道默认未配置，可使用线下实际收款后的人工核实流程；当时只提供自有网关签名适配协议。0.1.13新增的官方渠道、OIDC与多机节点见下一节，真实服务需填写参数并联调。回环监听前使用可信HTTPS入口。


## 官方支付、企业SSO与多机节点（0.1.13）

新增 workbench-node.exe。先看source/docs/45_官方支付企业登录与多机自动化操作部署指南.md。参数模板在source/examples/deployment。后台首次启动自动生成关闭状态的支付/OIDC配置；配置为空明确拒绝相关调用。节点可用Start-Node.ps1 -Config 完整路径启动，Stop-Node.ps1按同一配置停机；每台机器独立私有root，先在门户注册并批准。正式跨机使用HTTPS，可选mTLS。不要复制data中的账号、支付密钥或DPAPI节点身份。

# 流程执行器、输入校验与检查点

日期：2026-11-04。版本：0.1.5-poc。本文记录本地受管浏览器流程增量，后台、支付、中央额度、完整画布和高级指纹继续按原台账执行。

## 1 已实现功能

发布定义使用 DSL `schemaVersion: "1.0"`，与文档04的旧0.1设计示例分开。C++14解释器支持 navigate、fill、click、select、assertText、condition、loop、call、end。点击必须包含文本后置断言；选择与填写会复用浏览器实际结果检查。定位使用当前受管页面主文档的唯一CSS，执行前重新定位，不将旧ref存入流程。

流程经同一个服务入口供桌面、JSONL CLI、MCP和鉴权HTTP调用。8个新增工具是 workflow_validate、workflow_publish、workflow_list、workflow_get、workflow_run、workflow_runs、workflow_status、workflow_control。共39个共享工具。异步运行返回runId，客户端连接中断不取消任务；响应丢失可通过workflow_runs找回记录，不能盲目再次调用workflow_run。

发布版本按规范JSON内容计算SHA-256，以随机workflowId保存不可变版本；相同内容再次发布返回existing=true。改草稿不会修改已经发布或正在运行的定义。记录有内容校验和，重启会重新验证；校验和不替代发布签名或同用户恶意篡改防护。

## 2 输入、表达式和资源边界

输入采用显式命名的 `awb-bounded-draft07-v1` 子集，仅支持闭合object、有界string/integer/array、boolean、required及标量enum。所有string必须声明maxLength，integer必须有minimum/maximum，array必须声明items/maxItems。未知关键字、远程$ref、format、pattern、组合Schema和其他方言均明确拒绝。该实现不声称是通用draft-07验证器。

表达式支持字符串/整数/布尔字面量及 `{"input":"/mandatory/field"}`。路径只能引用已声明的必填对象属性；不支持可选字段、数组动态索引、`${...}`插值或任意宿主脚本。fill仅接受输入引用，口令不应写入发布文件；其他节点的秘密值同样应经输入引用传递。比较支持eq/ne/lt/le/gt/ge，布尔支持and/or/not；顺序比较要求整数且左右静态类型一致。

图检查覆盖重复ID、缺失目标、隐式循环、不可达节点、未使用子流程、递归调用、类型和能力。显式loop按maxIterations计算最坏预算，即使运行时count为0，定义也必须合法。子流程共用顶层输入，暂不支持返回值或运行时变量赋值。

| 边界 | 实际限制 |
| --- | --- |
| 导入JSON | 文本256KiB、深度32、节点16384；本地记录读取上限1MiB |
| 单流程/总步骤定义 | 每个flow最多128步，整个定义最多256步 |
| 子流程 | 最多32个定义、调用深度8；禁止递归 |
| 条件AST | 深度8，and/or每组1至8项 |
| 循环 | 显式整数计数，单loop上限100 |
| 最坏执行步数 | maxSteps为1至1024，覆盖控制/end及子流程步骤 |
| 运行时长 | maxDurationMs为1至300000毫秒；到步骤边界停止后续派发，已发CDP消息按自身截止排空 |
| 版本/运行元数据 | 每个本地数据根各最多256条，达到上限明确拒绝；暂不提供归档/删除入口 |
| 本地活动执行线程 | 最多5个，不构成中央免费额度或商业并发策略，也不是带排队的调度器 |
| 作用域 | 流程与Profile的规范化allowedOrigins必须完全相同；沿用现有动作范围限制，不是网络出口防火墙 |

CLI/MCP/HTTP在解析阶段先限制JSON深度64并拒绝重复字段；桌面流程文件深度32、输入深度16，随后再执行流程预算和类型校验。协议测试包含错误后继续合法请求，避免深层导入在语义校验之前耗尽栈。

机器可读的[编辑器结构Schema](schemas/workflow-v1.schema.json)符合draft-07；C++额外完成图、路径类型、作用域与预算等语义检查。结构Schema不承担运行时通用Schema能力。正式单源生成及OpenAPI映射仍归T115。

## 3 控制、持久化与未知结果

同Profile最多一个活动流程。暂停不自动释放Profile所有权；暂停完成后仍拒绝交互页面动作，取消或终态后才允许其他控制器操作。browser_status、lease_revoke、browser_stop始终保留；每一步及每条CDP消息都重新检查原租约，恢复也不能绕过撤销或TTL。

pause先返回pausing，已领取步骤排空后在下一步前进入paused；resume只接受paused。cancel返回cancelling，停止后续步骤，已发操作不会回滚。若排空时业务结果不明，最终状态为outcome-unknown，不以cancelled掩盖未决提交。终态、重启中断和未知任务都不能resume。

检查点位于私有数据根的workflows/runs，发布文件在workflows/versions。派发前原子持久化executing意图，确认后写succeeded。元数据仅包含版本摘要、Profile/run/步骤标识、类型、深度、状态、重放分类和固定错误码；输入值、租约、页面正文、CSS、ref不进入运行记录。发布文件仍包含用户明确提供的非秘密定义，不能在名称、断言、enum、URL或选择字面量中放口令。

类型分为page-effect-no-replay、read-only、control-only。导航、填写、选择、点击都不自动重试；点击已发但后置断言失败进入outcome-unknown。写前或写后检查点失败即停止后续派发，checkpointDurable=false，保留上一份磁盘记录供重启核对。

服务重启不保存或恢复租约/输入：未完成的网页写意图变成outcome-unknown，纯观察/控制意图变成interrupted，不重建业务执行。调用方应核对目标业务状态，必要时人工另起新任务。当前尚未实现完整intent/dispatched/verified阶段日志、业务核对适配器、持久队列、人工确认后的断点恢复或补偿事务，因此T035/T095/T098仍有未关闭边界。

## 4 操作方法

先启动自有夹具：

```powershell
python tests/fixtures/web_app.py --port 3000
```

桌面新建来源为http://127.0.0.1:3000的环境并启动。把“CSS / 流程文件”框改为[注册登录示例](../tests/fixtures/workflow-register-login.json)的完整文件路径，点击“校验流程”“发布流程”。隐藏值框输入以下JSON，再点击“运行流程”；输入框随后清空。请使用专用测试账号，不复用真实凭据。

```json
{"user":"example-workflow-user","password":"example-test-password"}
```

点击“流程状态”查看实际步骤；“暂停流程”后反复查看状态，达到paused才使用“恢复流程”。“取消流程”停止后续派发，不能撤销已经注册的账号。默认本地租约五分钟，超时后流程会失败；当前不自动续租。桌面按Profile记住本次发布和runId，重开后可通过CLI/MCP的workflow_list/workflow_runs查询持久ID。

CLI先创建/启动Profile并lease_acquire。随后发送以下JSONL；definition为完整JSON对象，不是文件路径：

```json
{"id":1,"command":"workflow_validate","arguments":{"definition":{"schemaVersion":"1.0","name":"验证输入","version":1,"inputSchema":{"type":"object","properties":{},"required":[],"additionalProperties":false},"policy":{"allowedOrigins":["http://127.0.0.1:3000"],"maxSteps":1,"maxDurationMs":10000},"entry":"done","steps":[{"id":"done","type":"end"}]},"input":{}}}
```

发布：workflow_publish({definition})。运行：workflow_run({workflowId,profileId,lease,input})。查询：workflow_status({runId})，找回任务：workflow_runs({})。控制：workflow_control({runId,operation:"pause"|"resume"|"cancel"})。HTTP使用POST /v1/tools/同名工具，并携带本地API认证；MCP工具参数相同。

## 6 问题与处理

| 问题 | 处理与验证 |
| --- | --- |
| 恢复后可能直接执行end而未再次核对原租约 | 所有步骤边界增加租约/原浏览器检查；暂停中撤销后恢复必须失败且无新步骤 |
| 租约核对期间收到暂停，存在领取下一步的窗口 | 领取步骤的引擎锁内再次核对暂停/取消，迭代返回边界等待 |
| 文件替换曾发生一次非预期失败 | 保留workflow-debug-r2失败报告；新增固定API/系统错误诊断；仅MoveFileEx共享/访问冲突对相同检查点字节最多重试3次、合计60毫秒。原失败未捕获底层错误号，不能断定其具体外部占用者。后续全量/部署回归再次验证；持续占用仍必须冻结，不会重放网页 |
| 发布和状态操作不携带profileId，桌面无法关联返回结果 | 增加仅UI内部的上下文Profile关联，不给工具参数添加未登记字段 |
| 原子写中断留下的临时文件识别长度错误 | 修正为32位ID+.json+点+32位随机ID+.tmp共74字符；增加部分JSON临时文件重开测试，只保留证据，不当作发布文件导入 |
| 中文深路径流程目录枚举 | 使用扩展路径枚举和读取，文件仍保持UTF-8无BOM/LF，旧文件编码不变 |

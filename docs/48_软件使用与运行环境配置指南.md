# AI 浏览器自动化工作台软件使用与运行环境配置指南

更新日期：2026-11-25。适用版本：0.1.13-poc，Windows x64 开发测试版。本文按“解压、自检、操作网页、制作流程、接入后台和多机”的顺序说明。当前功能范围见[功能说明](47_软件功能说明.md)，开发人员另看[源码编译指南](49_源码编译环境搭建指南.md)。

## 1 运行前准备

### 1.1 需要安装什么

| 场景 | 需要准备 | 无需额外安装 |
| --- | --- | --- |
| 本机桌面、CLI、MCP、Local API | 完整便携包、普通 Windows 用户、可写本地目录 | VS、Python、Node.js、IIS、Docker、外部数据库 |
| 本机后台 | 同上；回环端口可用 | 外部 Web 服务器和数据库服务 |
| 多机节点 | 每台 Windows 完整包、独立数据目录、可访问后台的网络 | 节点入站命令端口 |
| 附带练习网站与 Python 自动化示例 | 另装 Python 3.12，并加入 PATH | 不影响不使用示例的普通用户 |
| 正式支付/SSO/跨机 HTTPS | 商户或 IdP 配置、域名、证书及可信反向代理 | 这些外部服务不随软件自动开通 |

已测试系统为 Windows 11 x64（10.0.26200）。Windows 10 x64 是目标运行平台，第二台物理机和干净机仍需验收。建议至少 8GB 内存，并在完整解压包之外保留 2GB 以上可写空间；这是初始使用建议，不是多并发性能承诺。浏览器数量、附件和历史数据增加后应扩大容量。

包内含匹配的 VC142 Release DLL 和固定版本 Chrome。保留全部相邻文件，不能只复制一个 EXE。使用普通用户即可；不要将数据目录放到只读目录、受限的 Program Files 或不可靠网络共享中。

### 1.3 本文命令的目录约定

解压到自己的本地目录后，打开 PowerShell，先执行以下命令。后面的示例沿用这些变量；路径应替换为实际目录。

```powershell

```

命令中的 `example.com`、空字符串和示意路径需要实际配置；不要把示意值当作有效商户、企业登录或节点服务。

## 2 第一次启动及数据目录

1. 完整解压 ZIP，双击 `Self-Test.cmd`。应得到 `Self-test: passed`，报告位于 `test-results/run-*/report.json`。失败时先读报告，不以窗口出现代替通过。
2. 双击 `Start-Workbench.cmd`，进入原生工作台。程序随后启动的网页窗口是独立受管 Chrome for Testing。
3. 测试自己的系统前，先保证该 Web 服务可以访问，准备一个测试帐号和可判断成功的结果元素。
4. 需要组织、订单、支付或节点管理时，再启动 `Start-Admin.cmd`；本地离线测试不要求先购买套餐。

| 启动入口 | 默认数据根 | 用途 |
| --- | --- | --- |
| `Start-Workbench.cmd` | `data/desktop` | 桌面人工操作 |
| `Start-CLI.cmd` | `data/cli` | JSONL 脚本服务 |
| `Start-MCP.cmd` | `data/mcp` | MCP stdio 服务 |
| `Start-API.cmd` | `data/api` | 本机 HTTP 接口 |
| `Start-Admin.cmd` | `data/admin` | 后台数据库及配置 |
| `Start-Node.ps1 -Config ...` | 配置中的 `root` | 节点身份、任务与环境 |

这些是不同数据库和环境库。不要期待桌面建的环境自动出现在默认 CLI 根中。多个进程不能同时使用同一根；需要统一环境时通过一个服务入口调用，或停止旧服务后再使用相同根。

便携模式由包内 `portable.mode` 标记启用。手工指定根可用 `--root`，节点则在配置文件内指定；根的父目录应先存在。根必须是软件新建/认可的数据目录，不能指向日常 Chrome 用户目录。

常用端口：后台 `127.0.0.1:17861`；Local API 默认动态回环端口；注册登录练习站 `3000`；内容练习站 `3010`。协议、主机、端口共同决定来源，`localhost` 与 `127.0.0.1` 不等价。

## 3 从零测试帐号注册与登录

### 3.1 启动练习站

本节需要 Python 3.12。另开一个 PowerShell，在解压包的 `source` 根中运行以下命令并保留该窗口：

```powershell
Set-Location -LiteralPath 'D:\Apps\AI-Browser-Workbench-0.1.13-win64-integrations-r1\source'
python -X utf8 tests/fixtures/web_app.py --port 3000
```

练习地址是 `http://127.0.0.1:3000/login`，注册页为 `/register`。练习帐号保存在服务器内存中，重启站点后会丢失；浏览器保留 Cookie 不代表新启动的站点还认识旧会话。

### 3.2 在桌面中操作

| 顺序 | 具体操作 | 预期结果 |
| --- | --- | --- |
| 1 | 环境名称填“注册登录测试A”，地址填练习地址，点击“新建环境” | 左侧选中新环境 |
| 2 | 点击“启动”，再点击“打开地址” | 受管 Chrome 显示练习页，取得桌面控制租约 |
| 3 | “网页操作”中 CSS 填 `#username`，隐藏值框填新测试帐号，点击“填写” | 网页帐号框填入；桌面值框清空 |
| 4 | CSS 改为 `#password`，值框填测试密码，点击“填写” | 网页密码框填入；结果不回显密码 |
| 5 | CSS 改为 `#register`，点击“点击” | 提交注册 |
| 6 | CSS 改为 `#result`，点击“读取文本” | `registered` |
| 7 | CSS 改为 `#login`，点击“点击”；再读取 `#result` | `logged-in` |
| 8 | 读取 `#identity` | 精确显示本次测试帐号 |
| 9 | 停止、重启同一环境并打开相同地址，读取身份 | 站点未过期且未重启时复用原登录态 |
| 10 | 新建“测试B”，启动并打开相同地址，读取身份 | `anonymous`，验证环境隔离 |
| 11 | 切回A并点击 `#logout`，读取结果及身份 | `logged-out`、`anonymous` |

若异步结果尚未出现，只重复读取。不要因等待不足重复点注册或发布。自动化脚本可用 `page_wait_text`，其含义为精确文本相等，单次等待范围是 1–10000ms。

负向检查：使用 `.duplicate` 定位应得到 `LOCATOR_AMBIGUOUS`；隐藏/禁用元素应拒绝操作。这些保护行为不算故障。

### 3.3 换成自己的系统

先把地址替换成真实测试 URL，用“探查高亮”或“元素拾取（预览）”取得并核对帐号、密码、提交及成功标识的 CSS。定位必须唯一。录制、动作和语义快照主要针对当前主文档，跨 iframe/OOPIF、封闭 Shadow 等复杂控件不属于完整支持范围。

对于登录后跳到其他域名的系统，应在停止环境后配置全部确切来源。只有主机相同而端口不同也属于不同来源。流程与环境的规范化来源集合需要一致，不能只放行起始登录页。

## 4 桌面常用操作与安全接管

| 分组/菜单 | 常用入口 |
| --- | --- |
| 网页操作 | 定位、填写、点击、读取文本、语义快照、探查高亮、预览点击、选择选项 |
| 页面与诊断 | 页面列表、新页面、切换、关闭选中页、页面事件、显式重连、开始/读取/停止诊断 |
| 流程与数据 | 校验/发布/运行流程、状态、暂停/恢复/取消、Schema 提取、动作批次 |
| 环境管理 | 保存名称、归档、回收站、恢复、永久删除 |
| 凭据与调试 | 管理当前环境凭据、首节点暂停调试、打开调试器、查找功能、定位修复草稿、只读状态诊断 |
| 模型与知识包 | 模型配置和预算、生成流程草稿、知识包差异预览/导入/列出/导出 |
| 环境库与本地后台 | 后台账号与授权、环境库管理等表单 |

CSS 输入框也用作流程 JSON 文件路径框；隐藏值框也用作流程运行输入。切换分组后检查字段含义，JSON 参数是完整对象。密码等填写提交后值框会清空。

“接管/撤销”使旧自动控制租约失效；人工处理完成后点“取控制”。桌面租约最长 5 分钟，长时间停顿后可能需要重新取得。接管、暂停、取消和停止都不能撤回已经到达网站的提交。

标签页下拉框选中后需点“切换”才改变后续目标。导航或切页后重新定位，不复用旧 `ref`。显式重连只恢复连接，不重发先前业务。

### 4.1 代理、区域与环境库配置

分组、模板、历史回滚、配置导入导出和批次结果可进入“环境库与本地后台→环境库管理（表单）”操作。先检查批次每项结果，再归档；配置导出不包含可跨用户使用的凭据和完整登录态迁移能力。

代理和区域配置使用 `profile_create/profile_update` 或 Local API 环境路由。先停止环境，读取当前 revision；修改时提交 `expectedRevision`。可选字段如下：

| 字段 | 示例与规则 |
| --- | --- |
| `allowedOrigins` | `http://127.0.0.1:3000` 等确切来源的数组；不是带路径 URL 的白名单规则 |
| `proxyServer` | `http://代理主机:端口` 或 `socks5://代理主机:端口`，无认证、无路径，端口明确 |
| `runtimeSettings.userAgent` | 自己测试系统需要的 UA 字符串 |
| `runtimeSettings.languages` | 例如 `zh-CN`、`zh` 的数组 |
| `runtimeSettings.timezone` | 例如 `Asia/Shanghai` |

`profile_update` 的 `proxyServer` 设空字符串清除代理，`runtimeSettings` 设空对象清除区域覆盖。启动后核对 `runtime.requested/effective`，并在自己的站点检查实际行为。代理出口与泄漏、弹窗/Worker 的区域一致性未完成完整验收，不能只根据配置成功就认定通过。

### 4.2 文件、下载与数据提取

单文件上传先唯一定位文件输入框，再调用 `page_upload`，传当前 `profileId/lease/ref` 与节点本机的 `path`。上传动作绑定本地文件，网站是否接收仍需验证页面结果。

下载先调用 `page_download_config` 指定当前环境的下载目录，再点击下载入口，调用 `page_download_wait` 按精确 `fileName` 等待完成；单次超时范围 1–10000ms，核对事件和文件。多机路径指执行节点本机，不能把操作者电脑的文件路径当成远程文件。

结构化读取使用 `page_extract` 的 Schema，动作批次使用 `page_batch`，完整对象格式以当前工具契约为准；桌面“按Schema提取”“执行动作批次”读取 JSON 文件。批次最多 16 个动作，逐项查看结果；结果未知会停止后续派发，不回滚此前成功写入。

## 5 制作并回放自动化流程

### 5.1 先使用已提供的流程

1. 保持练习站运行，选中允许 `http://127.0.0.1:3000` 的环境并启动。
2. 在“流程与数据”的 JSON 文件路径框，填入解压目录下 `source/tests/fixtures/workflow-register-login.json` 的完整路径。
3. 点击“校验流程”，确认校验通过；再点击“发布流程”，记录返回的版本/工作流 ID。
4. 运行输入框填下列对象，帐号每次使用新名称，点击“运行流程”。

```json
{
  "user": "manual-test-20261105-001",
  "password": "LocalLab-Only-2026!"
}
```

5. 查看“流程状态”直至 `succeeded`，检查中间注册、登录、身份断言均通过。示例最后执行退出，所以最终页面显示 `anonymous` 属于预期。

示例密码仅用于本地练习。正式流程应改用当前用户受保护凭据/SecretRef，或由私有输入提供秘密。不要把真实密码提交到源码或分享给别人。

### 5.2 自己录制并编排

1. 打开目标页面，菜单“网页录制（预览）→开始录制当前主页面”。
2. 在真实浏览器填写和点击；需要排除操作时选择“暂停录制”，之后“恢复录制”。
3. 选“读取录制与缺项”，再选“停止并生成草稿”。核对 `complete`、`captureIssues`、`requiredConfiguration` 和 `draft`。录制不保存输入内容，只生成参数槽。
4. 选择“打开录制草稿画布”，或进入“可视化流程编辑器”。补上起始导航、来源范围、输入槽对应关系和每次写操作的后置断言。
5. 拖入需要的动作、分支、循环或子流程并连线，编辑 JSON 属性后点击应用；保存草稿。没有应用的属性不会进入自动恢复内容。
6. 校验、发布不可变版本，使用测试输入运行；若有失败先打开诊断和调试器定位。
7. 修改产生新草稿并重新发布，不直接改变原发布版本。保存好版本、输入摘要和测试记录。

画布的自动恢复保护编辑成果，业务执行崩溃后不会自动续点。发现 `unknown` 或结果未知时，先到网站确认真实状态，再决定后续新任务。

### 5.3 调试与凭据

菜单“凭据与调试→下次流程从首节点暂停调试”后运行，可打开当前运行调试器，查看脱敏变量、断点及当前步骤，再选择单步、stepOver、stepOut 或恢复。暂停在步骤边界生效。

“管理当前环境凭据”用于建立、轮换和删除受保护凭据。使用秘密后截图可能被禁止，应通过状态断言验证结果，不关闭保护来截取密码页面。失败定位可生成修复草稿，核对候选元素后再发布。

## 6 登录后自动发布文章、搜索与互动

本节提供本地可操作网站，避免先面对复杂外站。所有写操作仍经浏览器工具完成。

### 6.1 启动内容练习站

另开 PowerShell，在包内 `source` 根运行并保留服务窗口：

```powershell
Set-Location -LiteralPath 'D:\Apps\AI-Browser-Workbench-0.1.13-win64-integrations-r1\source'
python -X utf8 examples/content-lab/server.py --port 3010
```

### 6.2 运行完整脚本

回到已设置 `$awbPackage/$awbSource/$awbBrowser` 的 PowerShell，执行：

```powershell
Set-Location -LiteralPath $awbSource
$awbRunOutput = Join-Path $awbPackage ('practice-results\content-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
python -X utf8 examples/content-lab/runner.py `
    --executable (Join-Path $awbPackage 'workbench-cli.exe') `
    --browser $awbBrowser `
    --output $awbRunOutput --headed
```

输出目录必须尚不存在；每次使用新目录。`--headed` 显示真实浏览器，便于观察。要改文章输入，可复制并编辑 `examples/content-lab/inputs.example.json`，再加 `--inputs '自定义JSON绝对路径'`。

| 阶段 | 核对内容 |
| --- | --- |
| 登录 | 网站身份为预期作者 |
| 发布 | 标题、正文、换行、分类与输入一致，发布状态明确 |
| 搜索 | 关键词、列表数量和翻页结果符合预期 |
| 点赞 | 指定文章 ID 的点赞状态正确 |
| 评论/回复 | 指定文章和父评论 ID 正确，正文准确，提交次数符合预期 |
| 输出 | `report.json` 显示通过、工作流 `succeeded`，并有 `browser.png` |

`workflow-publish-search.json` 是登录、发布和第一页搜索的 19 步流程；分页及点赞/评论/回复由 Python runner 继续调用浏览器工具完成。示例互动目标明确为 `seed-a`，父评论为 `comment-a`，不是自动对所有搜索结果批量操作。

迁移到自己的网站时，需要替换来源、唯一定位器、文章输入、分页与成功判断。菜单“查找功能（选择器框输入名称）”可辅助寻找“发布”等候选，再用高亮确认。普通网站没有服务端幂等支持时，软件不能保证任意网络故障下恰好提交一次；超时先核对业务记录。

## 7 AI 与其他软件接入

### 7.1 MCP 客户端

将下面示例的目录改为实际解压目录，加入支持 MCP stdio 的客户端配置。包中也提供 `mcp-config.example.json`。

```json
{
  "mcpServers": {
    "ai-browser-workbench": {
      "command": "D:/Apps/AI-Browser-Workbench-0.1.13-win64-integrations-r1/workbench-mcp.exe",
      "args": [
        "--root",
        "D:/Apps/AI-Browser-Workbench-0.1.13-win64-integrations-r1/data/mcp"
      ]
    }
  }
}
```

重启或重连客户端后，确认服务版本和 97 个工具。由客户端完成 MCP 初始化。MCP 服务连接本身不需要模型密钥；AI 客户端的模型设置在该客户端完成。产品内“生成流程草稿”的模型配置是另一套独立配置。

建议首次任务描述包含：测试站来源、使用哪个测试身份、允许写入的目标、每步预期结果，以及失败后的停止条件。例如要求“登录后核对身份，再填写测试文章，发布一次并核对标题和状态”。

### 7.2 CLI 与 SDK

`Start-CLI.cmd` 启动 JSONL 服务，每行一条请求：

```json
{"id":1,"command":"capabilities","arguments":{}}
```

随后按以下顺序读取真实结果再调用，不能硬编码租约或元素引用：

```text
profile_create → browser_start → lease_acquire → browser_navigate
→ page_locate → page_fill / page_click → page_wait_text → browser_stop
```

CLI 请求使用 `id/command/arguments`，MCP 则使用对应 MCP 协议，不能混用信封。关闭 CLI 标准输入会退出服务并清理其受管浏览器。Python/TypeScript SDK 源码在 `source/sdk`，准确参数和示例以[当前生成契约](contracts/tools-v1.json)为准，旧报告中的工具数量不适用于当前版本。

流程接口中 `workflow_publish` 接收 `definition` 对象，不是文件路径；调用方先读取 JSON。`workflow_run` 需要 `workflowId/profileId/lease/input`；返回后轮询运行状态，断开连接不代表取消。`workflow_control` 的操作为 `pause/resume/cancel/step/stepOver/stepOut`。

### 7.3 Local HTTP API

先双击 `Start-API.cmd` 并保持运行。在包根的 PowerShell 中执行：

```powershell
$awbEndpoint = Get-Content -LiteralPath (Join-Path $awbPackage 'data\api\local-api.json') -Raw | ConvertFrom-Json
$awbHeaders = @{ Authorization = 'Bearer ' + $awbEndpoint.token }
Invoke-RestMethod -Uri ($awbEndpoint.url + '/v1/health') -Headers $awbHeaders
Invoke-RestMethod -Uri ($awbEndpoint.url + '/v1/tools') -Headers $awbHeaders
Invoke-RestMethod -Method Post -Uri ($awbEndpoint.url + '/v1/tools/capabilities') `
    -Headers $awbHeaders -ContentType 'application/json' -Body '{}'
```

所有路由包括健康检查都要 Bearer 令牌；每次重启重新读取端点文件。仅供本地程序调用，拒绝浏览器 Origin，不开放 CORS。不要把令牌嵌入网页。

工具请求地址为 `POST /v1/tools/{工具名}`，正文直接是该工具的参数对象。成功检查 `ok:true/result`；错误检查 `error.code` 和 `outcomeUnknown`。详细路由、If-Match 和报文限制见[Local API 参考](20_本地HTTP_API参考.md)。

### 7.4 配置软件内的模型与知识包

如果只用外部 AI 客户端经 MCP 调用网页，可以跳过本节。需要软件自己生成流程草稿时：

1. 用 `model_status` 或“模型与知识包→查看模型配置与预算”读取当前 revision 和预算。
2. 远程 HTTPS 模型须先用 `credential_create` 创建 `purpose:model` 凭据，`allowedOrigins` 只包含模型端点来源，`profileIds` 使用空数组，保存返回的凭据 ID。不要把 API Key 放进模型配置 JSON。
3. 创建私有配置 JSON，字段按下表填写。把完整路径填入桌面 JSON 文件路径框，选择“从JSON文件配置模型”；也可调用 `model_configure`。

| 字段 | 配置含义 |
| --- | --- |
| `expectedRevision` | 上一步读取的当前 revision，首次也先查询 |
| `endpoint` | 完整兼容接口地址，例如 `https://model.example.com/v1/chat/completions`，不是只填域名 |
| `model` | 服务实际提供的模型标识 |
| `credentialId` | 真实模型凭据 ID；远程 HTTPS 必需 |
| `timeoutMs` | 100–30000，单次请求超时 |
| `maxCalls` | 1–1000000，持久调用预算 |
| `maxOutputTokens` | 128–32768，单次输出预算 |
| `maxTotalTokens` | 1024–1000000000，总预算 |

4. 准备包含 `task`、`allowedOrigins` 的 JSON，通过“从JSON文件生成流程草稿”或 `model_generate_workflow` 请求。目标来源必须是预期测试系统；不发送实际密码、Cookie 或支付密钥作为任务文字。
5. 核对生成草稿和校验结果，补全定位、参数及后置断言，人工审阅后发布。失败不自动重试；预算按持久保守计量，不能当成供应商最终计费账单。

端点必须支持非流式兼容 `chat/completions` 请求和 JSON 对象输出；远程 HTTPS 正常校验证书，本机 HTTP 仅用于本地服务/测试。未配置时返回 `MODEL_NOT_CONFIGURED`，仍可手工编辑流程。

站点知识包先通过菜单预览差异，再导入不可变版本；代码接口 `site_package_import` 还需要真实 `expectedLatestVersion`。导入后列出版本，按指定版本导出。知识包是数据，不会因导入而自动执行流程。

## 8 启动后台与管理免费/付费权益

### 8.1 初始化后台

1. 双击 `Start-Admin.cmd`，脚本默认启动 `127.0.0.1:17861` 并打开门户。
2. 第一次使用“初始化平台管理员”，填写邮箱、至少 12 字符密码、组织/昵称，以及 `data/admin/bootstrap.key` 中的初始化密钥。没有默认帐号密码。

4. 进入“概览与套餐”“成员与席位”“订单与账务”“设备/运行槽/用量”“平台运营”“多机自动化”“账户安全”查看相应功能。

端口冲突时，在包根执行以下命令，`-NoBrowser` 表示只启动服务：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Admin.ps1 -Port 17862 -NoBrowser
```

实际 URL 见启动输出或 `data/admin/admin-endpoint.json`；日志为 `startup.log`、`startup-error.log`。正常停止使用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Stop-Admin.ps1
```

### 8.2 桌面连接组织

先停止桌面正在运行的纯本地浏览器，再打开“环境库与本地后台→后台账号与授权（表单）”。填写后台地址、帐号和密码并登录，核对组织、设备、角色、席位和权益。退出或切换账号前先停止该连接跟踪的浏览器。

免费组织默认 10 环境、10 并发、1 席位，跨项目/设备/节点合计。RPA、AI/Web 测试、Local API 和用户自有节点不要求购买；超容量或额外资源才按套餐扩展。免费政策允许代理，实际支持仍为实验无认证 HTTP/SOCKS5。

### 8.3 后台日常操作

| 需求 | 操作路径和核对 |
| --- | --- |
| 邀请成员 | “成员与席位”分配角色、生成邀请；手动交付令牌，被邀请人接受后核对占用 |

## 9 配置支付、企业登录和公开 HTTPS 入口

### 9.1 配置文件

后台首次启动会生成以下文件。先停止后台，再编辑真实字段并重启加载；原始文件是可解析模板，优先编辑程序生成的模板。

| `data/admin` 文件 | 用途 |
| --- | --- |
| `payment-config.json` | 通用支付网关配置，默认关闭 |
| `official-payments.json` | 支付宝、微信、Stripe 官方渠道，默认关闭 |
| `oidc-config.json` | 企业身份服务，默认关闭 |
| `server-config.json` | 正式公开来源、节点传输证明 |
| `bootstrap.key` | 首次初始化密钥，私有保存 |
| 数据库及端点文件 | 业务状态、服务端点，不能发到源码仓库 |

没有真实服务时保持 `enabled:false` 和空参数。`PAYMENT_NOT_CONFIGURED`、`OIDC_NOT_CONFIGURED` 是未配置的正确结果，不能以模拟成功替代。

### 9.2 HTTPS 基础配置

后台本身始终监听回环 HTTP。跨机器部署使用可信 HTTPS 反向代理，参考[部署模板](../examples/deployment/Caddyfile.example)。Caddy 不随产品自动安装；需要自行安装并准备可验证的域名证书。

`server-config.json.publicOrigin` 是精确 HTTPS origin，例如 `https://portal.example.com`，不带路径。正式外部登录与付款应使用 HTTPS，并保持 Windows 服务端证书校验。不要将后台回环 HTTP 直接当公网入口。

### 9.3 官方支付参数

| 配置对象 | 主要字段与含义 |
| --- | --- |
| `alipay` | `enabled`、`appId`、`sellerId`、PKCS8 `privateKeyPem`、支付宝 SPKI `publicKeyPem`、`baseUrl`、`notifyUrl` |
| `wechat` | `enabled`、`appId`、`merchantId`、`merchantSerial`、PKCS8 `privateKeyPem`、32 字节 `apiV3Key`、`platformKeys`（序列号到平台公钥）、`baseUrl`、`notifyUrl` |
| `stripe` | `enabled`、`secretKey`、`webhookSecrets` 数组、`liveMode`、`apiVersion`、`baseUrl`、`successUrl`、`cancelUrl` |
| 顶层测试开关 | `allowLoopbackTest` 仅用于本机协议夹具；正式保持 `false` |

官方基础地址分别为 `https://openapi.alipay.com/gateway.do`、`https://api.mch.weixin.qq.com`、`https://api.stripe.com`。按模板使用允许的官方地址，支付宝沙箱也必须使用代码允许的官方沙箱入口。Stripe 模式要与密钥、Webhook 和订单一致。

对外回调路径分别为 `/payments/alipay/notify`、`/payments/wechat/notify`、`/payments/stripe/notify`，前面加实际公开 HTTPS 来源。代理保留原始通知正文及验签所需标头，不能重新序列化正文。

配置后在门户创建订单，到“订单与账务”选择订单及渠道，执行创建/查询/退款/退款查询。核对实际渠道交易、整数人民币分、币种和商户。二维码/付款链接或跳转成功都不能代替到账验证。

只支持 CNY 和全额退款。预付秒数的退款会先冻结可退额度；`unknown` 时先查询并保留冻结，不通过换业务键重复发起。真实商户联调及生产资金验证尚未完成。

### 9.4 OIDC 与桌面单点登录

1. 在 IdP 注册授权码客户端，启用 S256 PKCE、RS256/JWKS，登记精确回调 `https://portal.example.com/auth/callback` 和退出回跳 `https://portal.example.com/`。
2. 填写 `oidc-config.json` 的 `enabled/issuer/clientId/clientSecret/redirectUri/tokenAuthMethod`。`issuer` 必须与发现文档及令牌一致。
3. `tokenAuthMethod` 支持 `client_secret_basic`、`client_secret_post`、`none`。其他端点来源只有明确加入 `allowedEndpointOrigins` 才接受；正式保持 `allowLoopbackTest:false`。
4. `allowAutoProvision:true` 可为已验证邮箱的新主体建立普通本地组织；已有同邮箱账号不自动合并。先登录原账号，在“账户安全”显式绑定当前企业身份。
5. 门户点击“通过企业身份服务登录”。完成后核对本地组织及角色，不把 IdP 组等同平台管理员。
6. 在“账户安全”生成 120 秒单次桌面连接码。桌面账号表单的后台地址填门户 HTTPS 地址，邮箱填 `sso`，密码填连接码后登录；代码入口是 `account_connect_code`。
7. 连接码过期重新生成，不转发给其他人。“退出企业身份登录”先撤销本地会话，再进入 IdP 退出；IdP 可能另要求确认。

OIDC 自动创建账号默认禁用本地密码。MFA、目录同步、企业 IdP 兼容性和账号恢复仍需实际企业环境验收。

## 10 配置独立执行节点及多机运行

### 10.1 本机先走通，随后部署另一台机器

1. 门户“多机自动化”创建项目，来源例如 `http://127.0.0.1:3010` 或实际测试系统 HTTPS origin。
2. 为项目生成 5 分钟一次性节点注册码。
3. 节点机器完整解压相同版本程序。复制[节点配置示例](../examples/deployment/node-config.example.json)到私有目录，再填写下面字段。

```json
{
  "root": "D:/WorkbenchNode/data/node-a",
  "browser": "D:/WorkbenchNode/browser/chrome-win64/chrome.exe",
  "url": "",
  "name": "Windows执行节点A",
  "enrollmentToken": "",
  "headless": false,
  "clientCertificateThumbprint": ""
}
```

`root/browser` 是节点本机绝对路径；先创建 root 的父目录。`url` 本机演练填 `http://127.0.0.1:17861`，跨机器填实际 HTTPS 节点入口。`enrollmentToken` 填本次注册码，`headless:false` 便于观察。

**每台机器的 `127.0.0.1` 都指自己。** 跨机器运行流程时，不能继续把另一台机器上的练习站写成回环地址，须换成节点实际可达来源并同步调整流程和项目范围。

4. 在节点包根启动，配置文件使用绝对路径：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Node.ps1 `
    -Config 'D:\PrivateWorkbench\node-a.json'
```

5. 查看配置旁启动日志，门户中核对节点名称、公钥、版本和能力，批准 `pending` 节点。
6. 在项目中分配环境，固定所属节点、所属账号及配置。环境登录态保留在该节点，不跨机搬迁。
7. 在门户发布已校验的不可变流程定义，选择环境、版本、输入 JSON 和超时提交任务。提交者应使用分配给自己账号的环境。
8. 刷新查看 `queued/dispatched/accepted/running/succeeded/failed/cancelled/unknown`。按目标网站结果和执行回执共同判断成功。

节点容量不提高组织配额。中央免费档仍按组织跨设备/节点合计 10 环境、10 并发、1 席位计算。

### 10.2 取消、未知结果及停机

先在门户将节点置为维护，等现有任务完成；或明确取消任务，再执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Stop-Node.ps1 `
    -Config 'D:\PrivateWorkbench\node-a.json'
```

也可用 `workbench-node.exe --config '配置路径'` 前台运行，或 `--stop --config '配置路径'` 请求停止。配置及 DPAPI 身份必须属于当前运行 Windows 用户。

失联或重启可能留下 `unknown`，系统不重放旧业务。节点确认浏览器/Job 已停止后才释放槽；门户只有确认已停止后才允许人工核对业务结果。到目标网站核对文章、订单等是否已经产生，填写结果说明，不盲目重新派发。

### 10.3 可选 mTLS

参考 Caddy 模板使用独立门户域名和节点域名。仅 `node.enroll/open/poll/ack/complete/event` 六个执行协议接口走节点证书入口；`node.enrollment.create`、`node.state` 等门户管理接口仍由用户登录权限保护，不能把所有 `node.*` 路由一律拦到证书入口。

后台 `server-config.json` 设置 `requireNodeTransportProof:true`、至少 32 字节随机 `nodeTransportSecret`；与代理私有环境变量 `AWB_NODE_PROXY_SECRET` 一致。代理覆盖节点证明标头，公开门户删除来路同名标头，防止绕过证书入口。

节点证书导入运行 Windows 用户的“个人/MY”库，需有私钥及客户端认证用途。`clientCertificateThumbprint` 填 40 位证书指纹；WinHTTP 按此选证书并正常验证服务端证书链。PFX 密码不写进节点 JSON。

证书轮换前维护并排空节点，先部署新信任和证书，再改指纹、重启、验证心跳，最后撤旧信任。代码及模板已提供，真实 TLS/mTLS 握手和第二台物理机尚未验收。

## 11 备份、迁移和故障处理

### 11.1 备份与升级

- 停止相关任务和进程后，完整备份其数据根及私有配置。不要在运行时直接复制 SQLite 主文件当作完整备份。
- 浏览器用户目录、后台数据库、DPAPI 身份和密钥都属于私有运行数据。分发给其他测试人员使用原始空 data ZIP。
- DPAPI 密文不能当作跨 Windows 用户/跨机器通用凭据备份。节点换机重新注册并分配新环境。
- 新版本先备份再迁移验证；不要把迁移后的数据库直接交给旧版本使用。当前本地存储 schema 为 7，不代表所有独立组件都共用一个 schema 编号。
- 不覆盖正在运行的 EXE；新版本用独立目录。当前没有完整签名安装器、自动更新和自动回滚体系。

### 11.2 常见问题

| 现象/错误 | 处理 |
| --- | --- |
| EXE 无法启动、缺 DLL | 完整重新解压包，核对系统 x64、运行库和浏览器资源；运行自检 |
| `ROOT_IN_USE` | 停止同根旧进程或换独立根，不删锁文件绕过 |
| `UNMANAGED_ROOT` | 使用新的空目录，不指向普通 Chrome 配置 |
| `API_BIND_FAILED` / 后台端口占用 | 停旧服务或改端口，读取真实端点 |
| `ORIGIN_DENIED` | 检查协议/主机/端口及跳转来源，停止后修正环境与流程范围 |
| `WORKFLOW_SCOPE_MISMATCH` | 使流程和环境的规范化来源集合一致 |
| `LEASE_BUSY` / `LEASE_REVOKED` | 核对控制者，必要时接管/撤销后重新取控制，先处理已有任务 |
| `ELEMENT_NOT_FOUND` / `LOCATOR_AMBIGUOUS` | 核对页面、主文档与唯一 CSS，检查页面是否尚未就绪 |
| `STALE_ELEMENT_REFERENCE` | 导航/切页/DOM 变化后重新定位 |
| `REVISION_CONFLICT` | 重新读取当前 revision，核对意图再修改 |
| `PROFILE_RUNNING` / `PROFILE_REFERENCED` | 停止环境或处理实际引用，不绕过保护 |
| 使用秘密后截图失败 | 属于秘密保护，改用受保护状态/断言验证 |
| `PAYMENT_NOT_CONFIGURED` / `OIDC_NOT_CONFIGURED` | 保持关闭，或填真实参数并重启；不以假成功绕过 |
| 节点 pending/不派发 | 审批身份、检查维护状态、项目来源、成员权限、环境归属和全局槽 |
| 页面动作/支付 `unknown` 或 `outcomeUnknown:true` | 先只读查目标业务或官方交易，不自动重复写入 |
| 自检清单不一致 | 核对是否修改了包内文件；开发修改后生成新包，不能把旧清单当新包清单 |

报告问题时记录版本、入口、环境/任务 ID、发生时间、错误码和脱敏步骤。不要发送令牌、密码、支付密钥、完整 Cookie 或带秘密的数据库。

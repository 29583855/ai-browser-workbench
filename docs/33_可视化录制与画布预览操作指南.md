# 可视化录制与画布预览操作指南

日期：2026-11-04。版本：0.1.9-poc。当前面向普通主文档表单。需要先配置参数、来源和点击后置条件；复杂站点适配和可视化断点尚未实现。[实际测试及边界](32_可视化RPA实施与测试记录.md)与[整体操作说明](16_功能操作说明.md)配合使用。

## 1 准备与启动

完整解压0.1.9便携包，双击Self-Test.cmd完成离线自检，再双击Start-Workbench.cmd。打开自己的测试Web服务；桌面程序没有内置Web业务服务器。练习完整内容站可参照[文档30](30_内容网站脚本自动化实测与操作指南.md)启动examples/content-lab，该Python服务需要开发环境中的Python。

第一次建议用普通HTML表单：帐号框、密码框、登录按钮，登录后显示固定身份或状态元素。确认站点地址、测试账号及可读取的成功提示。iframe、封闭Shadow、Canvas等不属于本轮录制验收范围；若complete:false，先看captureIssues，不能将草稿当完整流程运行。

## 2 录制一遍人工操作

1. 输入环境名与站点完整URL，点击“创建环境”，核对左侧选中环境。
2. 点击“启动浏览器”，再点击“打开地址”。先导航完毕再开始录制；启动会取得此环境控制租约。
3. 顶部录制菜单选择“开始录制”。在实际浏览器内手工填写帐号、密码并点击登录；录制不替用户再点击一次。
4. 如需暂时操作不纳入流程，选择“暂停录制”，完成后“恢复录制”。期间不要换标签、关闭页面或发起另一个流程。
5. 选择“读取录制”检查事件，选择“停止录制”解绑。所有输入值均不保存，只留下input_1、input_2等参数槽。记录inputSchema中各槽与表单输入的对应关系。
6. 查看complete、captureIssues、requiredConfiguration及draft。draft:null、超预算或丢事件必须处理后重新录制；输入值不在草稿里属于设计行为。
7. 选择“录制草稿进入画布”。本轮草稿保存在当前进程按环境的缓存；停止后及时在画布另存。

录制只生成操作草稿，不会自动识别“已经以正确身份登录”或文章是否公开。文章发布、搜索和互动应继续补业务对象、权限及后置检查，完整通用模板仍按计划开发。

## 3 在画布配置与发布

画布左侧为9类节点库，中间是节点与连线，右侧是JSON属性和结果。单击节点，编辑右侧JSON后点击“应用属性”；未应用的文字不会进入模型、校验、发布或自动恢复。

1. 单击navigate节点，将url填成实际完整地址。顶部“流程属性”中的policy.allowedOrigins须包含该来源，端口也属于来源。
2. 核对fill节点selector及value输入引用，例如`{"input":"/input_1"}`。流程属性中的inputSchema声明必填、类型和最大长度；不要把真实密码填到节点的静态value里。
3. 单击click节点，补全实际业务后置条件。例如登录后身份元素为`#identity`、显示测试用户名：

```json
{
  "selector": "#identity",
  "expected": "test-user",
  "timeoutMs": 5000
}
```

该对象放在click节点的postcondition字段。选择能证明预期业务结果的元素；HTTP完成、菜单出现或按钮按下都不能自动证明发布成功。

4. 核对顺序和入口。选中来源节点，选next/then/else端口，点“连接到…”再点目标节点；Escape取消。选择首节点并点“设为入口”。loop/call必须引用已建子流程；不允许任意回边作为循环。
5. 点击“校验”，结果valid:true后再“保存草稿”与“发布”。校验失败时查看errors，修正属性/连线；不能直接忽略错误。
6. 发布成功会回填打开画布时选中环境的流程版本。回到主窗口，选择该环境，切到“流程与数据”分组，在流程参数框填运行JSON：

```json
{"input_1":"test-user","input_2":"test-password"}
```

7. 点击“运行流程”，点击“查询状态”直到succeeded或明确失败；运行输入会从隐藏值框清空。再次核对网页身份、记录数量及服务器数据，避免只看工具返回。

本机自动化已验证录制→画布补URL/断言→发布→主窗口运行，真实表单仅提交一次。外部程序也可使用共享workflow_publish/run/status接口；参见[API参考](20_本地HTTP_API参考.md)。发布只保存定义，不保存这次运行的密码。

## 4 拖拽、历史与恢复

| 操作 | 方法 |
| --- | --- |
| 插入节点 | 从节点库拖入画布；也可双击节点类型或Enter插入 |
| 移动/选择 | 拖动节点；Ctrl增选；空白区域拖出框选 |
| 平移/缩放 | 中键拖动/鼠标滚轮，缩放10%–400% |
| 键盘 | 画布箭头移动、Delete删除、Ctrl+Z/Y撤销/重做、Ctrl+D复制选区 |
| 剪贴板 | “复制/粘贴/剪切”或画布Ctrl+C/V/X；使用专用节点格式 |
| 子流程 | 下拉切换主/子流程；“新建子流程”后配置call/loop引用 |
| 保存与导出 | awbdraft保存模型+布局；导出JSON须校验通过，布局不会写入执行定义 |

粘贴重新分配节点ID并重建选区内部连线；指向选区外的连线留空，需手动补齐。跨流程粘贴不复制输入Schema或被调用子流程，缺依赖会由校验拒绝。复制整个项目请使用保存/导入。历史合计最多100项/8MiB，超过预算丢弃最远历史。

自动恢复文件位于实际数据根的flow-drafts，扩展名awbrecovery，每窗口单独保存。每5秒保存已应用内容；恢复数量上限50，单份1MiB，满额会在结果区报错，应先审阅/另存后清理旧恢复文件。

程序意外退出后重新打开画布，点击“恢复草稿”，在默认恢复目录选择文件；核对节点和布局后使用“另存草稿”。恢复不绑定原草稿保存路径，不能静默覆盖另一编辑器的新revision。恢复文件是普通本地JSON，可以按修改时间检查；不要导入来源不明文件。

明确确认关闭编辑器会删除本窗口恢复文件，提示含“已手动保存，或放弃”；如果尚需保留就取消关闭并先保存。0.1.10起，主工作台退出前会先保存全部仍打开画布的已应用模型；只要一份保存失败，就保留主窗口和全部画布，在主窗口结果区显示错误。FLOW_RECOVERY_FULL表示已达到50份上限，请先审阅、另存并清理旧恢复文件；WINDOWS_ERROR可能是文件被占用，请解除占用后重试。已自动保存的文件被删除后，下次计时或正常退出会重新保存。文件对话框未关闭时，须先取消或完成对话框才能退出主工作台。仍只保存已应用属性，未应用文字不会保存。详见[复盘与故障测试](34_项目功能复盘与回归测试报告.md)。

## 5 元素拾取与常见问题

在工作台启动浏览器并取得租约后，从顶部拾取菜单开始拾取，在网页选择目标，再读取拾取结果。拾取到的唯一CSS回填主窗口选择器；退出后才恢复普通点击。拾取点击不会提交表单，退出也不会补发。需要把选择器写到画布节点时，当前需在JSON属性中手动填写，直接插入步骤仍待开发。

| 情况 | 处理 |
| --- | --- |
| 登录没有自动运行 | 填齐URL、来源、inputSchema、输入参数、click后置条件，并先校验/发布 |
| 主窗口提示没有流程 | 选择打开画布时的环境，重新发布；重启后需重新关联发布版本 |
| RECORDING_ACTIVE/PAGE_LOCKED | 先停止录制，再执行流程或换页面 |
| LEASE_REVOKED/过期 | 在主窗口重新取得控制权；旧持有者不能继续写 |
| valid:false | 查看具体错误；草稿不完整允许保存，但禁止发布/导出运行定义 |
| FLOW_REVISION_CONFLICT | 原草稿被另一编辑器更新或删除；使用新文件名另存，核对差异后决定 |
| frame/Shadow/富文本操作漏录 | 本轮不支持对应范围，不能补猜步骤；保留测试失败及场景交后续适配 |
| 提交后结果未知 | 先检查服务器是否已产生文章/评论；不直接重复提交 |

跨站点AI发现、自动修复定位、凭据库、运行变量、可视化断点与单步尚未提供，仍在专项台账中保持未完成状态。

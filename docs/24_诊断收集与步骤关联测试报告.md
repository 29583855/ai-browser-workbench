# Console、异常与网络诊断收集

日期：2026-11-04。版本：0.1.6-poc。本轮推进T039，其他任务和发布门继续按原台账验收。

## 1 实现范围

新增三个共享工具：browser_diagnostics_start、browser_diagnostics_read、browser_diagnostics_stop。桌面、CLI、MCP和鉴权HTTP共42个工具。桌面增加“开始诊断”“读取诊断”“停止诊断”按钮；启用后再点击网页或运行流程，观察器在动作之前注册。每个浏览器实例独立收集，已有和后来创建的受管页面都可产生记录。

Console记录级别、参数个数及前16个参数类型；异常记录类别、代码行/列。网络记录请求开始、响应状态、HTTP错误、完成、传输失败和重定向链；缓存及Service Worker响应带来源标记。请求使用本地随机requestId；方法、资源类型、异常类别和错误码都按固定枚举输出。不会因为HTTP404就声称网页点击未执行，也不会将没有完成事件的请求视为成功。

记录省略Console内容、异常描述、Cookie/Authorization、请求/响应正文、URL查询及片段。路径默认显示[omitted]；调用方可以在开始时通过routePaths显式允许展示最多32个精确路径，例如/api/login。白名单路径必须以/开头，最长512字节，不得包含查询、片段、反斜杠或控制字符。仅收集已管理会话及获授来源的诊断；这项过滤不限制浏览器实际网络出口。

该版本提供元数据诊断，尚未提供原始Console内容、响应正文查看器、HAR、Mock、源码调试或持久诊断包。这些属于T060/T071/T084/T096/T107等工作包，不把当前内存查询当作完整DevTools。

## 2 步骤关联与边界

交互动作关联actionId和command；流程动作关联runId、flow、stepId及ordinal。只把标识放入上下文，输入值、CSS、租约和DOM内容不进入诊断。请求的开始上下文保留到延迟响应和重定向，避免下一条断言覆盖发起步骤。

Console和异常标为observed-during-context；响应标为request-start-context-not-proven-cause。它们表示观察窗口或请求起点关联，不能证明并发轮询、第三方脚本或另一个标签的请求由某次点击唯一引起。独立页面带pageId，不将另一页错误归为当前页。浏览器屏障不能提供所有会话的严格因果顺序，因此后续业务响应断言仍须T071的动作前匹配器。

| 资源 | 限制和行为 |
| --- | --- |
| 诊断事件 | 每实例512条；输出limit为1至100，溢出返回gap和droppedEvents |
| 未决请求关联 | 最多128条；丢弃时增加droppedPendingRequests，不补造完成结果 |
| 上下文来源映射 | 最多256条；关闭会话时回收，无法确认来源的Console/异常计过滤数 |
| 游标 | epoch和after绑定本次收集；跨实例、重新开始或错误序号拒绝 |
| 生命周期 | 内存保存；停止后保留可读，重新开始清空并更换epoch；程序退出不保存 |
| 连接中断 | 显式重连显示connection-gap，丢失的未决关联计数；不重放网页业务 |
| 控制 | 三工具均核对原租约；活动流程允许只读诊断查询，开始/停止仍遵守Profile排他权 |

重连时Runtime.enable可能重新发送历史Console事件。初始化期间仅维护上下文来源，不把这些历史内容重复记为新诊断；连接间隙在初始化后写入。停止只停止收集元数据，不改变网页请求、不撤销业务；Network观察域可能保持启用，未启用Fetch拦截。

## 3 操作说明

桌面启动环境后，点击“开始诊断”，再打开地址、点击按钮或运行已经发布的流程。“读取诊断”显示首批最多50条元数据；完整分页请使用CLI/MCP/HTTP。“停止诊断”保留当前记录；再次开始会清空旧记录。建议需要保留的报告由调用方先导出保存。

CLI/MCP参数示例，profileId和lease用实际值替换：

```json
{"id":1,"command":"browser_diagnostics_start","arguments":{"profileId":"PROFILE_ID","lease":{"owner":"test","token":"TOKEN","generation":1},"routePaths":["/api/login","/api/register"]}}
```

start返回epoch。read接收profileId、lease，以及可选epoch/after/limit；首次after=0，后续原样使用返回cursor。停止接收profileId/lease。HTTP统一使用POST /v1/tools/同名工具，仍需本地认证、Host和Origin检查。来源、租约或游标错误均有明确错误码。

## 4 测试过程与缺陷

[真实浏览器验收脚本](../tests/integration_diagnostics.py)以自有[诊断夹具](../tests/fixtures/diagnostics.html)触发Console error、TypeError、404、302重定向和连接失败。异步503响应故意晚于点击步骤，核对其runId/stepId/ordinal仍指向原始提交步骤。另创建第二页面和外域请求，验证页面归属及来源过滤。

600条Console事件验证512条预算、分页不重不乱和gap；140个同时发起的只读请求验证128条未决关联预算。再测试显式重连、无业务重放、停止后记录数不变、重新开始换epoch、旧游标拒绝和撤销租约后三个入口拒绝。秘密哨兵同时置于Console参数、异常、URL查询和响应正文，导出的元数据报告必须不含这些哨兵或租约令牌。

| 发现的问题 | 解决与复测 |
| --- | --- |
| 诊断测试自定义流程入口沿用了默认open，导致图验证失败 | 测试定义明确entry=submit；产品原验证正确拒绝，不放松图规则 |
| 重连初始化接收历史Console事件，可能挤掉连接间隙记录 | 暂停初始化期间的新诊断采集、保留来源映射，并在初始化完成后记录间隙；重连复测验证 |
| 重定向可能在下一步骤被观察，原始关联可能被覆盖 | 重定向继承初始请求上下文；响应明确保留起点关联及因果限制 |
| 页面关闭后上下文映射占用预算 | 明确回收该session的上下文及未决关联，丢失请求计数而不报成功 |

最初两次失败报告保留在本轮证据目录的retained-failures中。旧0.1.5候选的CDP12017仍未定位；本轮不将其与历史Console问题混为同一原因。

# VC++2019 工程与独立便携测试包

日期：2026-11-04。范围：当前实现的完整工程、可运行 Release 产物和复制测试工具。产品计划中的未开发功能保持原状态。

## 原生工程

根目录 [AIBrowserWorkbench.sln](../AIBrowserWorkbench.sln) 直接由 VS2019 打开，包含 7 个相对路径 `.vcxproj`；不依赖开发机器的 E 盘路径，也不要求先安装 CMake。

| 项目 | 类型/用途 |
| --- | --- |
| awb_sqlite | 上游 SQLite C 静态库 |
| awb_core | 自有 C++14 核心静态库，平台/浏览器/服务/存储 |
| workbench | 默认启动项目，原生 Windows 桌面 |
| workbench-cli | JSONL stdio 自动化程序 |
| workbench-mcp | MCP stdio 程序 |
| awb-core-tests | 核心测试 |
| awb-storage-tests | SQLite事务、迁移、恢复和故障测试 |

安装 VS2019 16.11 的 C++ 桌面工具、v142 14.29.30133 和 SDK 10.0.19041.0；公共配置见 [Workbench.Common.props](../vs2019/Workbench.Common.props)。自有 C++14、Unicode、W4/WX、UTF-8、DEP/ASLR，高熵 x64；所有库同配置 MDd/MD，第三方 C 单独保留上游字节和告警设置。源码、第三方依赖和头文件已在仓库内；当前基础工程不需要在线拉取源码才能编译。

双击根目录 `Build-VS2019.cmd`，或执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-vs2019.ps1 -Configuration Both
```

脚本通过 vswhere 发现 VS2019，支持不同安装盘和 Community/Enterprise/Build Tools；也可传 `-VsRoot`。产物在 `build/native-vs2019/x64/Debug` 和 `Release`。每次运行保留 MSBuild 日志及测试报告。原有 CMake 构建仍保留，两种入口使用相同源码。

## 打包与复制

测试包是一个独立目录，另有同内容 ZIP 及 SHA-256 文件。包内包含 5 个 Release EXE、匹配的 app-local VC142 x64 DLL、完整固定 Chrome for Testing 目录、当前全部源码与原生工程、来源说明、逐文件哈希、启动脚本和离线自检。测试机无需安装开发工具、Python、Node 或 VC 运行库。Windows 10/11 x64、系统组件和可写本地目录仍是运行条件。

在开发机器生成新包：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/package-portable.ps1
```

脚本先真实构建 Release 并运行核心、存储和窗口测试，然后从已经校验的 `build/runtime/chrome-win64.zip` 解压原始运行时，从 VS 的 VC Redist 目录复制运行库并核对 x64 PE。输入运行时的来源、大小和 SHA-256 必须与 runtime-origin 一致，第三方源码必须与依赖锁一致。每次使用新输出路径，不覆盖已有用户目录。

可用 `-OutputDirectory`、`-VsRoot`、`-Python`、`-BrowserArchive` 指定开发环境；打包工具使用 Python 3.12，测试机不需要 Python。完整源码在包的 `source` 目录，编译即可使用；打包所需的大浏览器压缩包不重复放进源码子目录，重新打包时显式传官方已校验归档。打包脚本优先读取build/runtime的来源记录，复制源码下可回退至包内相邻browser/runtime-origin.json；不要求原开发目录存在。

上轮交付目录为 `dist/AI-Browser-Workbench-0.1.0-win64-portable`。0.1.1复盘版本为 `dist/AI-Browser-Workbench-0.1.1-win64-reviewed`，同级提供 `.zip` 和 `.zip.sha256.json`；新结果见[复盘报告](15_测试复盘与缺陷修复报告.md)。运行目录直接双击 `Start-Workbench.cmd`，需要传到另一台机器时复制完整ZIP并解压，不只复制EXE。源码快照位于包内 `source`；最终压缩后追加的制品验收记录保存在主工程证据目录。

用户操作说明见 [包内使用说明](../tools/portable/使用说明.md)：完整解压后双击 Start-Workbench.cmd 或 workbench.exe；CLI/MCP 有独立脚本和数据目录。按自身模块路径寻找包内浏览器，`portable.mode` 启用 data/desktop，不依赖当前工作目录。包内程序不用管理员权限、不替换系统浏览器。

## 验证与边界

已通过的本机工程与复制验证见[本轮证据汇总](execution/evidence/2026-11-04-portable/summary.json)：原生Debug/Release七项目零警告/零错误；CMake双配置每配置3项CTest通过；复制出的source在中文/空格目录Release重建通过。复制后的包内程序完成122条真实浏览器回归请求、HTTP代理正常/断线验证、官方MCP SDK的16个工具互操作；桌面启动脚本正常创建主窗口并关闭。

离线自检使用Windows PowerShell/.NET，不依赖Python/Node：逐文件SHA-256、核心/存储/窗口、包内浏览器定位/填写/点击/服务器确认、CLI/MCP、实际app-local Release CRT和从C:\WINDOWS启动的默认便携数据根。Windows PowerShell 5.1的中文注释解码和测试服务器有界清理已实测修正，源文件仍保持UTF-8无BOM/LF。14个自有EXE/运行库的dumpbin记录核对为x64，未含Debug CRT导入。官方SDK和Python浏览器回归只用于开发验收，不要求终端用户安装SDK。

自检只生成回环测试数据。初始 ZIP 不包含开发机用户环境、Cookie、口令或 .run/build 数据；运行后 data 和 test-results 会增加真实数据，应使用原始 ZIP 再复制给其他测试机。完整会话和 Windows 加密凭据的跨机器迁移不由该包实现。

本轮本机复制验证不等于第二台干净 Windows 节点验收，也不完成 T061 安装/签名/更新或 T003 干净机/CI 全门。T003/T061/T065 的新增实施证据按实际结果写入台账，不勾选尚未通过的条件。CfT 保持官方版权和 chrome://terms、chrome://credits，仅用于此次开发复制测试，未声称完成商业再分发准入。

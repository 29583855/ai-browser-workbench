# 结构化提取与动作批处理测试报告

日期：2026-11-04。版本：0.1.7-poc。对应T029；已按原验收标准完成独立模块验收。完整产品仍按234条台账执行。

## 1 功能与调用入口

新增page_extract和page_batch，桌面、JSONL CLI、官方MCP及鉴权HTTP共44个共享工具。桌面新增“按Schema提取”“执行动作批次”，使用“CSS / JSON文件”框中的UTF-8 JSON完整路径。文件只包含下述工具参数；当前Profile及其租约由工作台加入，文件不能替换profileId或lease。单文件最多256KiB，解析深度16；产品协议继续使用既有消息预算。

page_extract显式声明输出Schema及每个字段的CSS绑定，不接受任意脚本。page_batch先检查整批结构、参数预算及所有导航来源，再持有当前Profile排他锁按序执行；每条CDP派发仍校验租约。它是同步、有界批次，没有回滚或持久恢复。长任务应使用已发布流程及其状态接口。

## 2 Schema提取

提取方言名为awb-scalar-extraction-v1，使用draft-07中下列有界子集，未知关键字直接拒绝。它不表示完整draft-07、嵌套数组/对象、正则、引用或外部Schema已经实现；这些由T089继续承担。

| 项目 | 实际约束 |
| --- | --- |
| 根Schema | type=object；properties、required、additionalProperties=false必须提供；可选$schema只能为http://json-schema.org/draft-07/schema# |
| 字段 | 1–16个；名称1–64 ASCII字母、数字或下划线，拒绝__proto__/constructor/prototype；每个字段恰有一个绑定 |
| 标量 | string、integer、number、boolean；布尔不能冒充整数；文本转数值必须为完整合法JSON数值，拒绝12abc、溢出与错误类型 |
| 字符串约束 | minLength/maxLength为0–4096整数，按Unicode码点计数；单字段读取最多4096码点，超限报错而不截断后假称完整 |
| 数值约束 | 有限minimum/maximum；可选enum有1–32个类型匹配且不重复的值 |
| 读取源 | text、count、checked、attribute；CSS最多2048码点；count无需唯一匹配，其余要求唯一 |
| 属性 | 只允许title、aria-label、data-testid；不读取value、Cookie、URL查询或任意data属性 |
| 控件秘密 | 拒绝input/textarea/select值与可编辑内容；text读取还拒绝含这些控件的容器；checkbox/radio仅返回checked布尔值 |
| 文档与执行域 | 当前受管页面主文档；使用单独隔离世界，主世界篡改querySelectorAll不影响读取；前后校验frame/loader与来源 |

提取返回valid、data、errors、missing和partial。必填字段缺失使valid=false；可选字段缺失不放入data，仍报告missing/partial。字段歧义、非法选择器、类型及约束失败均明确列出field/code/required；错误中不包含被拒绝的原始值。有效字段保留在data。不能只看协议ok或HTTP200，必须检查valid和partial。

页面公开文字仍可能包含用户数据，data属于调用方显式请求的内容；程序不会把提取值写入API审计。当前没有持久证据分级系统。提取反映读取时的DOM，并非跨请求、跨frame或网站后端的一致事务快照。

最小工具参数示例，profileId/lease由调用方补充：

```json
{
  "schema": {
    "type": "object",
    "properties": {"identity": {"type": "string", "minLength": 1}},
    "required": ["identity"],
    "additionalProperties": false
  },
  "bindings": {"identity": {"selector": "#identity", "source": "text"}}
}
```

## 3 动作批处理与失败边界

page_batch参数actions包含1–16条动作，可选onError=stop/continue，默认stop。支持navigate(url)、fill(selector,value)、select(selector,values)、assertText(selector,expected,timeoutMs)、click(selector,postcondition)。全部字段严格检查，不支持嵌套批次、任意命令或隐式重试。

点击必须提供postcondition，包含selector、expected和1–3000ms的timeoutMs；它与assertText使用同一只读文本断言。点击实际派发后断言未确认，记BATCH_POSTCONDITION_UNCONFIRMED/outcome-unknown并强制停批。填写或选择被网页事件改写、传输中断等未知结果同样强制停止，onError=continue不能覆盖。

continue只对明确的定位/可操作条件/选项及只读断言失败继续；撤销租约、来源拒绝、失效连接及未知错误均停止。30秒预算在动作边界检查，当前CDP调用仍可能耗用其8秒截止；调用方超时应覆盖完整预算。HTTP当前串行处理请求，后到的撤销请求会排队；桌面工作线程允许“接管/撤销”直接通过派发门中断后续动作。完整异步取消、排队与跨Space控制仍由T025/T030/T040承担。

返回每条index/type/state及错误码，state为succeeded/failed/outcome-unknown/not-run；汇总给出succeeded/failed/notRun、stopped、outcomeUnknown、automaticRetryAllowed=false、atomic=false、rollbackPerformed=false。失败不会撤销已经填入的字段或已提交的业务。每次批次使用独立batchId，诊断关联具体ordinal；结果不包含输入值或CSS。断开连接后不自动重发批次；进程退出后没有批次恢复记录，应核对网站事实。

```json
{
  "actions": [
    {"type": "fill", "selector": "#username", "value": "fixture-user"},
    {"type": "click", "selector": "#login", "postcondition": {
      "selector": "#identity", "expected": "fixture-user", "timeoutMs": 3000
    }}
  ],
  "onError": "stop"
}
```

真实登录仍须按站点填写密码并满足其业务条件；该示例只说明结构。秘密输入通过内存参数提供，当前桌面导入文件不会替用户安全保存密码；凭据库/SecretRef仍属T049。

HTTP通过POST /v1/tools/page_extract和POST /v1/tools/page_batch调用；MCP/CLI同名。结构错误返回既有INVALID_ARGUMENTS等错误；已执行批次的部分或未知结果放在result中，HTTP200表示请求有结构化结果。API审计仅记录validation-failed/partial/outcome-unknown等固定摘要码，不把部分结果记成passed。官方MCP的isError同样用于调用层错误，客户端仍须检查结果。

## 4 测试、发现与处理

[真实浏览器脚本](../tests/integration_extraction.py)和[夹具](../tests/fixtures/extraction.html)覆盖公开文字、属性、计数、勾选、中文emoji边界、必填/可选缺失、重复节点、非法CSS、密码和容器拒读、超长值、非法/溢出数字、范围/enum反例及未知Schema关键字。故意篡改主世界DOM读取方法，提取仍由隔离世界完成。

批次测试先放入合法点击再追加非法动作/越界来源，核对点击计数保持0；随后验证导航、填写/选择事件、业务点击、默认停批、明确继续及未执行记录。点击实际发生但断言故意错误，后续点击保持未执行；另通过真实服务器提交后阻塞渲染，核对提交仅1次、CDP未知结果及不重放。桌面在批次只读等待期间撤销租约，核对后续写入未派发；HTTP和官方MCP测试使用同一提取及批次定义。

| 发现 | 处理与实际边界 |
| --- | --- |
| 批次完成后外层诊断还发送一次CDP，租约撤销会覆盖已生成的逐项结果 | 批次改为只使用逐项诊断屏障，结果返回不再派发新CDP；桌面撤销用例验证部分结果保留 |
| 选择值重复原先直到该步骤才被拒绝，无法满足整批参数预检 | 在批次预检阶段拒绝重复值；首条合法点击之后追加重复选择的反例验证点击数仍为0 |
| HTTP审计原来把所有有结构化结果的请求记passed | 增加固定validation-failed/partial/outcome-unknown摘要，验证未知批次审计码；不记录数据 |
| MCP测试导入定义构造器时连带导入Pillow | CLI驱动改为执行测试main时才导入；不增加MCP运行时或测试虚拟环境的无关依赖 |
| 一次原生链接遇到LNK1104，目标EXE暂时不可打开 | 保留构建日志；停止测试后按构建→测试串行冻结，再次构建通过不表示已定位文件不可打开的外部原因 |
| 0.1.6-r2桌面登录服务端成功但页面仍匿名 | 保留原失败；新增固定夹具状态/元数据诊断及服务端身份观察。后续10次独立复测通过，原因仍未确认，不标为修复 |

0.1.5旧候选CDP12017与上述匿名显示故障均未证明同源，继续由T018/T013故障与长稳工作包跟踪。0.1.6-r2的9项部署及13套非桌面回归通过，但完整包验收存在桌面失败，不能写为14套全通过。

## 6 长目录匿名显示的定位与修正

r1包的9项部署检查与14套非桌面回归通过，桌面仍出现服务器registrationCount=1/loginCount=1、页面anonymous。新增固定阶段诊断后，在相近长目录稳定复现`cache-open:UnknownError`；HTTP登录已经成功，程序没有补提交。原失败、阶段观察及对照结果均保存在[失败证据目录](execution/evidence/2026-11-04-extraction/retained-failures/r1-package-summary.json)。r1完整包验收记失败，不能用其他套件通过覆盖。

对当前固定CfT进行独立路径对照：标准Profile长度90/110/125时CacheStorage.open成功，135/145/155时返回UnknownError。仅改用Windows扩展路径能让CacheStorage成功，却导致ServiceWorker注册AbortError，因此该方案被拒绝，失败探测证据保留。这些是本机/固定内核的观察阈值，不作为所有Windows/浏览器的统一保证。

最终BrowserDataPath对超过100个UTF-16单元的规范Profile路径建立私有短路径连接。连接位于当前用户LocalAppData/AWB-Paths，以完整目标路径摘要定位；创建/复用后校验重解析类型与精确目标，持有禁止写入替换/删除的连接句柄及禁止目录替换的目标句柄。Cookie和所有浏览器数据始终位于原目录，不复制登录态、不改原路径边界，也不接受用户提供的连接当作Profile。退出只移除连接本身，绝不递归删除目标；异常退出遗留连接下次须再次核验。同名普通目录/不同目标拒绝，短别名不可获得时明确报错。

原生及CMake双配置均验证160/200/240字符中文带空格目录的实际注册/登录、Cookie、LocalStorage、IndexedDB、CacheStorage、ServiceWorker、页面重开和进程重启。桌面在原长目录条件下登录及后续功能通过。核心测试验证连接确实读取原文件、运行中不能替换、普通SafeAbsolute仍拒绝重解析路径、冲突对象保留以及清理不删除目标。另用旧r1程序创建登录态，再用新程序以别名重开，身份及全部存储保留，注册/登录总计仍各1次，见[旧数据升级](execution/evidence/2026-11-04-extraction/storage-legacy-upgrade/report.json)。

本轮CMake首次链接awb-storage-tests.exe再次发生LNK1104，失败日志保留；当时未发现该名运行进程且目标文件已不存在，尚无证据确定外部原因。随后重新构建及双配置全套回归通过，不把该构建现象写为已定位/已修复。0.1.6旧匿名失败缺少同级阶段记录，旧CDP12017也未证明与本次CacheStorage故障同源，继续由T013/T018跟踪剩余故障矩阵与长稳门。

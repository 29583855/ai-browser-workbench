# AI 浏览器自动化工作台源码编译环境搭建指南

更新日期：2026-11-25。适用源码：0.1.13-poc。目标平台：Windows x64；语言标准：C++14；编译工具链：Visual Studio 2019 / v142。

普通用户无需安装本手册中的开发工具，直接看[软件使用与运行配置](48_软件使用与运行环境配置指南.md)。功能与交付边界见[功能说明](47_软件功能说明.md)。本文说明可复现的搭建方法。2026-11-06 已完成 VS2019 Release 构建及包内源码独立重建；2026-11-25 的 GitHub 发布复用该冻结包，产品源码未变更，发布信息见[GitHub 发布与下载说明](52_GitHub发布与下载说明.md)。

## 1 开发环境分层

| 层次 | 必需工具 | 可以完成 |
| --- | --- | --- |
| 原生 C++ 最小开发环境 | Windows x64、VS2019 C++ 工作负载、固定 v142 与 Windows SDK | 打开解决方案，编译全部 9 项目，运行原生测试 |
| CMake 和源码质量检查 | 上述环境、CMake/CTest ≥ 3.20、Python、clang-format | CMake 构建、契约生成检查、格式与源码审计 |
| 浏览器/后台集成测试 | Python 3.12、完整 Chrome 运行时，按测试安装依赖 | 真实浏览器、支付/OIDC 协议和本机节点测试 |
| TypeScript SDK 开发 | Node.js 22+、TypeScript 5.9.3 | 编译薄 SDK 并进行跨语言调用验证 |
| 便携包生成 | Release 工具链、Python 3.12、匹配 VC142 CRT、原始浏览器 ZIP | 新建独立部署目录、清单、ZIP 和 SHA-256 |

原生工程编译不需要先安装 Python、Node、CMake、OpenSSL、Qt、CEF、IIS 或外部 SQLite 数据库服务。支付与 OIDC 的产品实现使用 Windows 原生能力；Python 密码学包仅供协议测试夹具。

## 2 安装并核对 VS2019

### 2.1 固定工具链

| 项目 | 当前工程要求/实测值 |
| --- | --- |
| Visual Studio | 2019 16.11；本机验证为 Enterprise 16.11.53，Community 安装相同组件也可构建 |
| 工作负载 | 使用 C++ 的桌面开发（Desktop development with C++） |
| 平台工具集 | MSVC v142，工具目录版本 `14.29.30133` |
| 编译器 | 本机 `cl` 版本 `19.29.30159` |
| Windows SDK | 固定 `10.0.19041.0` |
| 目标架构 | x64；当前没有 Win32/x86/ARM64 交付 |
| 标准 | `/std:c++14`，禁止擅自升级到 C++17/20 |
| 自有 C++ 参数 | `/W4 /WX /permissive- /utf-8 /Zc:__cplusplus /EHsc` |
| CRT | Debug `/MDd`；Release `/MD` |

在 Visual Studio Installer 中勾选工作负载，并在“单个组件”核对上述版本。需要走 CMake 路径时加装“用于 Windows 的 C++ CMake 工具”；需要源码审计时确认 VS 的 LLVM/clang-format 可用。

不要在首次打开时直接接受“重定向到最新工具集/SDK”。工程明确固定 v142 补丁和 SDK，安装缺失组件比静默改变目标更容易复现。不同 VS2019 Edition 的安装目录可以不同，用 `-VsRoot` 指明即可。

### 2.2 核对文件和命令

打开 PowerShell，以下变量按本机目录修改。本手册后续构建命令沿用这组变量：

```powershell
$awbSource = 'E:\project\webexploer_codex'
$awbVs = 'D:\Program Files (x86)\Microsoft Visual Studio\2019\Enterprise'
$awbBin = Join-Path $awbSource 'build\native-vs2019\x64\Release'
$awbBrowser = Join-Path $awbSource 'build\runtime\browser\chrome-win64\chrome.exe'
Set-Location -LiteralPath $awbSource
Test-Path -LiteralPath (Join-Path $awbVs 'MSBuild\Current\Bin\MSBuild.exe')
Test-Path -LiteralPath (Join-Path $awbVs 'VC\Tools\MSVC\14.29.30133\bin\Hostx64\x64\cl.exe')
Test-Path -LiteralPath (Join-Path $awbVs 'VC\Tools\Llvm\bin\clang-format.exe')
```

在“x64 Native Tools Command Prompt for VS 2019”中执行 `cl`，核对版本和 x64 目标。普通 PowerShell 未初始化开发环境时找不到 `cl` 不等于 MSBuild 不可用，本项目脚本使用 VS 的绝对工具路径。

如果从便携包取源码，`$awbSource` 应改为包内 `source`；`$awbBrowser` 改成包根 `browser/chrome-win64/chrome.exe` 的绝对路径。源码编译本身不要求浏览器，只有运行网页和集成测试时需要。

## 4 路径一：原生 VS2019 工程构建

### 4.1 IDE 操作

1. 双击 `AIBrowserWorkbench.sln`。
2. 选择 `Debug | x64`，生成解决方案；再生成 `Release | x64`。
3. 应得到 9 项目成功，检查输出窗口，没有错误且自有代码警告为零。
4. 产物目录为 `build/native-vs2019/x64/Debug` 和 `build/native-vs2019/x64/Release`。

仅点击 IDE“生成”不自动代表完成全部测试。需要测试时用下一节脚本或手动运行测试程序。普通测试机分发 Release，Debug 依赖开发运行库，不应混装 Release CRT。

### 4.2 PowerShell 一键构建和基础测试

在源码根执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build-vs2019.ps1 `
    -Configuration Both -VsRoot $awbVs
```

也可双击根目录 `Build-VS2019.cmd`，脚本通过 `vswhere` 查找 VS2019。`-Configuration` 支持 `Debug`、`Release`、`Both`。

默认每个配置编译后执行核心/流程、存储和 Win32 smoke 测试，日志在 `build/evidence/native-时间/`。脚本失败会返回非零，先修复错误，再继续后续步骤。`-SkipTests` 仅供明确跳过测试的局部开发，不能据此报告测试通过。

构建前关闭使用这些输出 EXE 的产品和测试进程，避免 `LNK1168`。不需要关闭用户普通浏览器；应确认关闭的是当前构建产物及其受管进程。

## 5 路径二：CMake 构建

先安装 Python 并使 `python` 在 PATH 可用，因为配套脚本还执行契约与审计。完整脚本路径：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build.ps1 `
    -Configuration Both -VsRoot $awbVs
```

输出在 `build/vs2019-x64/Debug`、`build/vs2019-x64/Release`，与原生工程输出目录不同。脚本执行 CTest、契约检查和源码审计；VS 需要包含 CMake/CTest/clang-format。

也可手动配置和运行最小 CTest：

```powershell
$awbCmake = Join-Path $awbVs 'Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe'
$awbCtest = Join-Path $awbVs 'Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\ctest.exe'
& $awbCmake -S . -B build/manual-vs2019 -G 'Visual Studio 16 2019' -A x64 `
    -T 'v142,version=14.29.30133' "-DCMAKE_GENERATOR_INSTANCE=$awbVs" `
    '-DCMAKE_SYSTEM_VERSION=10.0.19041.0'
if ($LASTEXITCODE -ne 0) { throw 'CMake configure failed' }
& $awbCmake --build build/manual-vs2019 --config Release --parallel 4
if ($LASTEXITCODE -ne 0) { throw 'CMake build failed' }
& $awbCtest --test-dir build/manual-vs2019 -C Release --output-on-failure
if ($LASTEXITCODE -ne 0) { throw 'CTest failed' }
```

CTest 当前包含 `core`、`storage`、`win32-shell` 三项，不等于所有真实浏览器和支付/节点集成测试。不要在已有不同 VS/生成器缓存目录中切换工具链，使用新的构建目录。

## 6 配置并运行自己编译的程序

下面以原生 Release 产物为例。确认 `$awbBrowser` 指向完整 Chrome 目录内的真实文件，并先建立根的父目录：

```powershell
New-Item -ItemType Directory -Path (Join-Path $awbSource '.run') -Force | Out-Null
& (Join-Path $awbBin 'workbench.exe') --root (Join-Path $awbSource '.run\desktop') --browser $awbBrowser
```

桌面为交互式程序。后台前台调试入口：

```powershell
& (Join-Path $awbBin 'workbench-admin.exe') --root (Join-Path $awbSource '.run\admin') --port 17861
```

CLI 和 API 分别使用独立根：

```powershell
& (Join-Path $awbBin 'workbench-cli.exe') --root (Join-Path $awbSource '.run\cli') --browser $awbBrowser
```

退出 CLI 后，若要使用 HTTP 模式再执行：

```powershell
& (Join-Path $awbBin 'workbench-cli.exe') --root (Join-Path $awbSource '.run\api') --browser $awbBrowser --http 0
```

`--http 0` 自动选回环端口，读取该根的 `local-api.json` 获得本次令牌。MCP 使用 `workbench-mcp.exe --root ... --browser ...`；节点使用 `workbench-node.exe --config '绝对配置路径'`，不以 `--root` 替代节点配置。

这些开发数据目录不进入源码交付。真实支付/OIDC 配置由后台首次启动生成，默认空且关闭；填写与 HTTPS/mTLS 部署见[运行配置手册](48_软件使用与运行环境配置指南.md)。

## 7 门户资源、契约与 SDK 更新

### 7.1 门户资源

后台 Web 源文件在 `src/admin/web/index.html`、`src/admin/web/portal.js`。修改后先重新嵌入资源，再编译后台：

```powershell
python -X utf8 tools/embed_admin_portal.py
python -X utf8 tools/embed_admin_portal.py --check
```

只修改 HTML/JS 而不更新嵌入资源，EXE 可能仍包含旧界面。`--check` 用于检查漂移，不改文件。

### 7.2 工具契约

工具注册以核心 `Service::Tools` 实现为源。编译最新 CLI 后执行：

```powershell
python -X utf8 tools/generate_contract.py --executable (Join-Path $awbBin 'workbench-cli.exe')
python -X utf8 tools/generate_contract.py --executable (Join-Path $awbBin 'workbench-cli.exe') --check
```

检查生成工具 JSON、OpenAPI 和 Python/TypeScript 契约是否同步；当前是 97 个工具。用旧 EXE 生成会把契约回退，应先构建。增加入口时不能只改按钮或某一种协议而遗漏共享校验、契约及 SDK。

### 7.3 TypeScript SDK

本机已验证 Node.js 23.9.0；建议 Node.js 22+，固定 TypeScript 5.9.3。以下操作只影响开发目录：

```powershell
npm.cmd install --prefix build/sdk-tools --ignore-scripts --no-audit --no-fund --save-exact typescript@5.9.3
node build/sdk-tools/node_modules/typescript/bin/tsc `
    sdk/typescript/client.ts sdk/typescript/contract_v1.ts `
    --target ES2022 --module commonjs --strict --outDir build/sdk-compiled
```

工具变更后重新生成契约并重新编译 SDK。过期的 `build/sdk-compiled` 可能正确拒绝新契约，不能将这种拒绝当成可以绕过的版本检查。

## 8 Python 测试环境与回归

### 8.1 基础环境

本机验证 Python 3.12.3。打包脚本使用 Python 3.12 的路径接口，建议统一安装 3.12 x64。创建独立虚拟环境：

```powershell
python -m venv .venv
$awbPython = Join-Path $awbSource '.venv\Scripts\python.exe'
& $awbPython -m pip install --requirement tests/official-requirements.lock.txt
& $awbPython -m pip install Pillow==12.2.0
```

官方协议锁当前固定 `cryptography==48.0.0`、`cffi==2.0.0`、`pycparser==3.0`；Pillow 用于图像相关测试。只运行不依赖这些包的测试无需全部安装。

官方 MCP SDK 验收另建隔离环境，按 `tests/mcp-sdk-requirements.lock.txt` 安装，不必污染普通开发环境。该锁文件及协议测试包均不是产品运行依赖。

### 8.2 常用测试入口

下例假定已完成原生 Release 构建，并设置 `$awbBin/$awbBrowser/$awbPython`。每次输出都使用全新目录：

```powershell
$awbEvidence = Join-Path $awbSource ('build\evidence\manual-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $awbEvidence | Out-Null
& $awbPython tests/integration_commerce.py --binary-dir $awbBin --browser $awbBrowser `
    --output (Join-Path $awbEvidence 'commerce')
if ($LASTEXITCODE -ne 0) { throw 'Commerce integration failed' }
& $awbPython tests/integration_official_oidc_nodes.py --bin $awbBin --browser $awbBrowser `
    --output (Join-Path $awbEvidence 'official-oidc-nodes')
if ($LASTEXITCODE -ne 0) { throw 'Official/OIDC/node integration failed' }
& $awbPython tests/integration_backend_extensions_edges.py --bin $awbBin --browser $awbBrowser `
    --output (Join-Path $awbEvidence 'backend-edges')
if ($LASTEXITCODE -ne 0) { throw 'Backend edge integration failed' }
```

| 测试文件/入口 | 参数和用途 |
| --- | --- |
| `tests/integration_commerce_edges.py` | `--binary-dir --browser --output`，账务/权限/计量边界 |
| `tests/integration_browser.py` | `--executable --browser --output`，真实网页基础操作 |
| `tests/integration_api.py` | 同上，Local API、鉴权和报文边界 |
| `tests/integration_sdk.py` | 同上；先编译 TypeScript SDK |
| `tests/integration_credentials_debug.py` | 同上，凭据、流程与调试保护 |
| `tests/integration_node_launchers.py` | `--package --output`，完整包节点启动/停止脚本 |
| `tests/integration_package.py` | `--archive --output`，可选 `--vs-root`，新解压包核对 |
| `Self-Test.cmd` | 部署包自检，不要求安装 Python |

`--executable` 场景通常指当前 `workbench-cli.exe`，不要传桌面 EXE。具体套件按变更选择，参数名 `--bin` 与 `--binary-dir` 不通用。测试输出写入不存在的新子目录，保留失败报告，再在新目录复测。

本地官方协议服务检验请求签名、回调与异常处理；OIDC 使用真实浏览器；节点套件启动同机多个真实节点。这些测试不能替代真实商户、企业 IdP、实际证书握手和第二台物理机验收。

## 9 源码规范、编码与开发检查

- 自有 C++ 保持 C++14；新增或修改函数加中文用途注释和日期，如 `// 用途：核对任务归属；日期：2026-11-05。`。
- 遵循 `.clang-format`。只格式化本次涉及的自有代码，不格式化 `third_party`。
- 修改前确认文件编码、BOM 和换行；修改后保持原样。当前自有文本主要是 UTF-8 无 BOM/LF，解决方案等文件按各自原格式保留。
- `.gitattributes` 使用 `* -text`，不要依赖 Git 自动转码；避免全仓库统一换行或旧版 PowerShell 默认编码覆盖中文。
- 版本源在 `include/awb/version.hpp`。改版本时同步工程、文档和生成契约，不只改窗口标题。
- 数据库迁移追加新步骤，不能改写已发布迁移 SQL/哈希。用隔离数据根验证迁移、失败恢复和备份。
- 将网站来源、密钥、密码、Cookie、DPAPI 身份与生产数据留在私有运行目录，不能放入测试证据或源码归档。

在源码根执行质量和进度检查：

```powershell
$awbCheckOutput = Join-Path $awbSource ('build\evidence\checks-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $awbCheckOutput | Out-Null
python -X utf8 tools/audit_source.py `
    --formatter (Join-Path $awbVs 'VC\Tools\Llvm\bin\clang-format.exe') `
    --output (Join-Path $awbCheckOutput 'source-audit.json')
python -X utf8 tools/verify_progress.py --output (Join-Path $awbCheckOutput 'progress.json')
```

每条命令检查退出码及报告。计划状态只能根据实际实现和证据更新；源码没有 TODO 不代表所有计划已完成，协议测试通过也不代表完整商业发行已通过。

## 10 生成新的独立可部署包

### 10.1 打包输入

1. Release 全部 9 项目编译和相应测试通过。
2. VS 目录存在匹配的 `VC/Redist/MSVC/14.29.30133/x64/Microsoft.VC142.CRT` DLL。
3. 当前打包脚本读取 VS 的 `Licenses/2052/Redist.txt`；其他语言安装布局应先核对许可文件路径，不能用空文件替代。
4. 准备固定版本的官方 Chrome ZIP，并核对来源及 SHA-256。

浏览器归档信息：

| 项目 | 值 |
| --- | --- |
| 版本 | 156.0.8078.80 / win64 |
| 官方地址 | [chrome-win64.zip](https://storage.googleapis.com/chrome-for-testing-public/156.0.8078.80/win64/chrome-win64.zip) |
| 字节数 | 208152768 |
| SHA-256 | `16edb57d6107bf1c48a7c149b8d78b155fe614410093796dd72441fd6640540f` |

开发工作区默认读取 `build/runtime/runtime-origin.json` 和 `build/runtime/chrome-win64.zip`。包内源码不重复附带大 ZIP，可从 `source` 的相邻 `browser/runtime-origin.json` 读取来源元数据，再通过 `-BrowserArchive` 指定单独保存的原始归档。不能用已经登录运行过的 Chrome 用户目录代替浏览器归档。

### 10.2 打包命令

仍在源码根，给输出取全新目录名，不能覆盖冻结制品：

```powershell
$awbNewPackage = Join-Path $awbSource ('dist\AI-Browser-Workbench-0.1.13-win64-manual-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
$awbBrowserArchive = Join-Path $awbSource 'build\runtime\chrome-win64.zip'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\package-portable.ps1 `
    -VsRoot $awbVs -Python $awbPython -BrowserArchive $awbBrowserArchive `
    -OutputDirectory $awbNewPackage
```

脚本先运行 Release 原生构建及基础测试，再调用 `tools/package_portable.py`。脚本组装 7 个 EXE、Release DLL、完整浏览器、启动/停止/自检脚本、源码和文档，生成初始清单、同级 ZIP 及哈希文件。工作区原始浏览器归档不存在时，先取得并核对上节归档，再修改变量。

打包前工具会核对版本、依赖哈希和证据目录中的私有文件。不要把真实商户配置或运行数据库放在 `docs/execution/evidence`。打包程序拒绝已有目录/ZIP，不要靠删除现有交付绕过它，改用新名称。

### 10.3 新包验收

1. 从新 ZIP 解压到另一个新目录，保留中文及空格路径覆盖。
2. 确认初始 data 为空，核对 `package-manifest.json`、同级 SHA-256 和全部运行资源。
3. 运行 `Self-Test.cmd`，启动桌面、CLI、MCP、API、后台和节点的相关入口。
4. 执行注册登录和本次变更涉及的真实业务；从包内 source 重建验证工程完整性。
5. 保存错误、修复、新报告和新哈希；冻结后不再改写该目录或 ZIP。后续文档修改留在工作区，下一次新包再包含。

当前没有签名安装器、自动更新/回滚或全部生产发行门。开发测试包的复制通过，不等于已经完成商业上线验收。

## 11 常见编译与配置错误

| 错误/现象 | 原因与解决方法 |
| --- | --- |
| `MSB8020` / 找不到 v142 | 安装 VS2019 C++ 工具集及固定 14.29.30133，不直接改成 v143 |
| `MSB8036` / SDK 缺失 | 安装 Windows SDK 10.0.19041.0 |
| CMake 拒绝配置 | 检查 MSVC/v142、x64、SDK 和旧缓存；使用新构建目录 |
| 中文乱码、警告视为错误 | 核对原文件编码、`/utf-8` 和真实编译告警，不全局转码或关闭 `/WX` 掩盖 |
| `LNK1168` | 关闭正在使用当前输出 EXE 的进程，再重新链接 |
| Debug 在普通机器无法运行 | 交付 Release 和匹配 Release CRT，不分发开发 Debug 运行库 |
| 浏览器找不到/启动失败 | 显式设置 `--browser`，保留 Chrome 全目录并核对版本/策略 |
| 网页资源仍为旧版本 | 重新嵌入门户资源并构建 EXE |
| 契约/SDK 不一致 | 先编译当前 CLI，再生成契约，最后编译 TS SDK并检查 |
| Python 无 `is_junction` 等接口 | 使用 Python 3.12，确认命令实际调用的解释器 |
| 打包缺 CRT 许可 | 核对 VS Redist 与本地化许可文件路径和内容 |
| 自检哈希不匹配 | 修改过冻结包；从源码生成新的完整包，不手改旧清单 |

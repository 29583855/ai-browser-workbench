## 正文

# 让 AI 真正操作网页，把重复操作变成可复用流程

你是否也有这样的工作日常：

系统更新后，重新输入帐号密码，点一遍登录、菜单、查询和提交，检查功能有没有问题。

文章准备好了，还要打开后台、找到发布入口、填写标题正文、选择分类，再确认发布结果。

想整理某个主题的信息，需要反复输入关键词、翻页、记录结果，还要切换不同帐号检查页面。

这些操作单独做并不复杂，难的是每天都做，而且每一步都要准确。

我们正在做的 **AI Browser Workbench——AI 浏览器自动化工作台**，就是把这些重复操作组织起来：由人确定目标，让脚本或 AI 调用浏览器执行，再用明确的结果判断每一步是否完成。

## 01 从“先登录”，到真正跑完业务

很多自动化需求，都是从一句很具体的话开始的：

**“先登录我的系统，然后把准备好的文章发布出去，再搜索想要的信息。”**

在工作台中，可以把它拆成一条清楚的流程：

打开网站 → 填写帐号密码 → 点击登录 → 核对当前身份 → 找到发布入口 → 填写标题和正文 → 发布 → 核对结果 → 搜索并整理列表。

如果业务还需要对指定内容点赞、评论或回复，也可以继续加入相应操作，明确目标文章、父评论和预期结果。

这里最重要的一步，是“核对结果”。按钮已经点击，不等于业务已经完成。工作台支持读取页面文本、等待状态和执行断言，让流程有依据地继续，也能在出错时停下来。

项目还提供了一个本地内容练习站，可以观察真实浏览器如何登录、发布文章、搜索翻页，以及对指定内容完成互动。从一套可控的小系统开始，更容易把自己的业务流程跑通。

## 02 测试自己的 Web 系统，操作路径更直观

对开发和测试人员来说，最常见的任务就是验证页面功能。

你可以先创建一个浏览器环境，打开自己的测试系统，再通过元素拾取、探查高亮和唯一定位，确认将要操作的输入框或按钮。

接下来，填写帐号密码、点击登录，读取页面中的身份或成功提示。注册、退出、查询、表单提交，也可以沿着相同的方法逐步测试。

这些步骤确认好后，就能保存为流程，在后续回归时重复执行。需要排查问题时，可以结合步骤状态、页面诊断和调试器，检查失败发生在哪里。

**先把一条真实业务路径验证清楚，再让它稳定复用。** 这是我们希望提供的使用体验。

## 03 人工操作可以录制，流程可以拖拽编排

不必每次都从空白脚本开始。

工作台已经提供主文档网页操作录制和原生可视化画布。你可以先手动操作一遍，再将录制结果带入画布，调整节点、连线和属性，加入分支、循环或子流程。

录制时，输入内容会转换为参数槽。帐号、文章标题、正文和关键词可以在运行时提供，同一条流程就能处理不同输入。

发布前，还需要补齐起始地址、允许访问的网站范围和关键操作后的判断条件。校验通过后发布固定版本，再进行回放。

遇到问题，可以从首节点暂停、设置断点、单步运行，或查看脱敏变量。修改后的流程作为新版本发布，便于保留原来的执行依据。

## 04 让 AI 和自己的软件，都能调用同一套能力

工作台既提供人工操作界面，也提供程序接口。

当前版本共有 **97 个共享工具**，支持 MCP、Local HTTP API、JSONL CLI，以及 Python、TypeScript 调用封装。

这意味着，你可以在支持 MCP 的 AI 客户端中接入工作台，也可以让已有自动化软件调用它，使用同一套浏览器环境、网页动作和流程能力。

AI 可以辅助查找“登录”“发布”等功能候选，也可以根据任务生成经过校验的流程草稿。操作者核对定位和步骤后，再发布执行。

对复杂业务来说，保留确认、调试和人工接管入口，能让自动化更容易管理。

## 05 多个帐号、多个环境，也能统一组织

不同测试身份、不同业务帐号，往往需要不同的登录状态。

工作台为不同环境使用独立的浏览器用户目录，分别保留 Cookie 和站点存储；配合分组、模板、配置导入导出，可以把常用环境组织起来。

同一环境重开时，可以继续使用仍然有效的登录态；新环境则从独立状态开始。网站本身的会话有效期仍然生效。

当任务需要多台 Windows 机器参与时，可以使用独立执行节点：在后台登记和审批节点，分配环境与固定流程版本，再提交任务、查看状态与回执。

取消、失联或重启后，结果不明确的业务会进入核对流程，避免未经确认就再次发布或提交。

## 06 从个人体验，到团队和资源管理

除了浏览器端，项目也提供了中文管理后台，用于管理组织成员、席位、设备、运行槽、套餐订单、续费、预付用量和账务记录。

支付宝、微信支付、Stripe 以及企业 OIDC 登录已提供适配实现，接入实际商户和企业身份服务时，需要填写对应参数并完成外部联调。

当前中央后台默认免费档为：

- **10 个独立环境容量**，按组织跨项目、设备和节点合计。
- **默认 10 个同时运行槽**，与环境容量分别管理。
- **1 个命名席位**。
- **核心 RPA、Local API、AI 调用和 Web 测试功能免费使用**。

超过环境或并发容量、购买额外资源与服务时，再按相应方案扩展。使用用户自己的执行节点，不会仅因使用节点本身要求购买。

这里的免费指工作台核心能力；第三方模型、代理或托管资源的费用，仍按对应服务确定。

## 现在适合怎样开始

如果你正在开发 Web 系统，希望减少重复登录和按钮验证；如果你有固定的发布、查询、整理流程；或者你正在给 AI 增加浏览器执行能力，都可以从一条简单流程开始体验。

推荐的第一条流程很短：

**打开测试站 → 登录 → 核对身份 → 执行一个业务动作 → 核对结果。**

先把它跑通，再逐步加入参数、分支和多节点。

完整便携包包含运行程序、固定浏览器和运行库。普通运行无需安装 Visual Studio、Python 或 Node.js；附带练习站和开发脚本需要额外的 Python。开发人员也可以使用 VS2019、C++14 工程进行编译与调试。

配套文档已经分别整理了功能说明、软件使用与运行配置、源码编译环境，方便从体验走到开发接入。

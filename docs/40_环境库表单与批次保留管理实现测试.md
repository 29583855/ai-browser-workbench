# 环境库表单与批次保留管理实现、测试与操作

日期：2026-11-05。版本：0.1.11-poc，交付增量automation-r4。工程：VC++2019/v142、C++14、x64。本文记录本地环境库工作包T052的验收；全产品及商业后台仍未完成。

## 1 逐项实施

- [x] 原生环境库管理窗口接入主菜单、CMake及VC2019工程；四页分别管理环境、分组、版本模板、批次记录。
- [x] 表单编辑名称、允许来源、代理、User-Agent、时区和语言；清空代理/运行覆盖会实际移除原设置，保存按固定revision校验。
- [x] 多窗口独立编辑；过期版本明确返回REVISION_CONFLICT，保留未保存输入，刷新后再编辑。禁止自动重试写入。
- [x] 分组成员多选、创建/更新/删除；配置模板创建/更新、不可变历史、复制历史为新revision、按指定版本创建新环境实例。
- [x] 系统文件对话框导入/导出配置；只包含白名单设置，导入生成新身份、不复制会话或凭据；批量配置先整体验证、再原子写入目录索引。
- [x] 环境归档、回收、恢复和确认永久删除；运行中拒绝配置/生命周期修改，删除分组或模板保留实际环境。
- [x] 批次active/archived/all范围、1–100条分页、稳定游标和详情查询；桌面每页30条，显示下一页状态。
- [x] 新增profile_batch_archive，明确确认相同batchId；只压缩已确认终态详情，保留ID、请求摘要、状态和计数。未知结果及未结束记录禁止压缩。
- [x] 同请求ID在压缩及重启后仍只返回回执，换参数返回BATCH_ID_CONFLICT；不重新获得执行权。
- [x] SQLite v7追加迁移，原六条迁移保持原字节/哈希；v1–v6先保存升级前索引快照，保留旧数据与批次。
- [x] 92工具契约、OpenAPI、双SDK同步；CLI/MCP/HTTP实际执行新增分页归档及去重链，便携Self-Test补充相同检查。
- [x] 原生窗口提供选中标签、双向滚动、异步回执和JSON多行显示；确认关闭/线程生命周期与控件遮挡检查通过。

## 2 测试环境和方法

本机Windows11 x64，VS2019 Enterprise 16.11、v142 14.29.30133、SDK10.0.19041.0；Debug/Release实编译，/W4 /WX，无警告及错误。受管浏览器使用固定Chrome for Testing156.0.8078.80。自动化作用于本测试新建的数据根和本地夹具，未测试用户的业务系统或外部网站。

桌面脚本通过PID识别真实窗口，向标准控件填写字段、选择成员/历史、点击按钮、操作系统文件对话框并核对落盘结果。额外检查所有可见交互控件矩形不重叠，保存并人工检查窗口截图；缩小到680×520后验证横纵滚动。测试数据、SQLite库及浏览器目录留在build，不作为交付证据公开。证据目录只归档白名单报告、构建日志和自建数据截图。

存储故障通过SQLite VFS实际返回磁盘满和提交刷盘错误；历史写入反例通过SQLite触发器注入失败，检验配置与历史/成员同事务回滚。并发由两个独立数据库连接竞争。真实进程中断测试先观察已落盘dispatching，再终止本测试CLI，重新打开同一数据根，检验outcome-unknown及禁止重放。

## 4 发现的问题及解决

| 问题/发现方式 | 原因 | 修复与复验 |
| --- | --- | --- |
| 初次Debug编译失败 | LB_SETCURSEL的-1隐式转无符号触发/WX | 显式WPARAM转换；双配置零警告 |
| 模板创建/保存与刷新布局冲突 | 连续枚举按钮ID把刷新错误放进动作栏 | 显式放置创建/保存，刷新保持左上；四模式矩形检查 |
| 回收/恢复按钮被导入/导出遮挡 | 同一坐标放置两组可见按钮，直接消息点击未发现 | 导入/导出独立一行；截图复核并新增交互矩形不重叠断言 |
| JSON详情显示成连续换行折叠文本 | 标准Edit控件需要CRLF | 仅在展示时规范换行，不改JSON存储/原文件编码；截图核对 |
| 文件对话框打开时主窗口退出存在重入销毁风险 | 原关闭保护只识别流程编辑器 | 同时识别环境库模态窗口并阻止退出；真实文件选择期间关闭回归通过 |
| 线程构造失败可能残留busy状态 | 设置busy后创建线程缺异常恢复 | 构造失败恢复控件并报错，不伪造提交结果；保存线程退出路径实测通过；未强制注入系统线程耗尽 |
| 已写入但列表刷新失败可能遮蔽成功回执 | 异步完成回调直接刷新 | 保留写入回执，附refreshError并提示不要重复提交；成功路径及冲突保留输入通过，未强制注入UI刷新失败 |
| 构建脚本SkipTests仍输出测试通过 | 固定成功提示未区分跳过 | 输出明确区分“构建通过；测试跳过”和完整测试通过 |
| 测试脚本初次失败（非产品缺陷） | 人工未知批次夹具摘要不足64位；系统对话框创建尚未完成便查找输入框 | 使用真实SHA256夹具、等待可见文件名输入框；保留失败日志，后续完整通过 |

## 5 从界面操作

1. 完整解压automation-r4，双击Start-Workbench.cmd；菜单“环境库与本地后台→环境库管理（表单）”。可打开多个独立窗口。
2. “环境配置”选择环境，编辑允许来源等设置，按“保存修改”；新建时按“新建草稿”、填写字段、按“创建”。允许来源每行一个，至少一个；当前代理支持无认证HTTP/SOCKS5。空代理/UA/时区/语言会清除旧覆盖。
3. 修改前停止该环境浏览器。发生版本冲突，先复制保留输入，再按“刷新/第一页”、核对最新配置后重新修改；不盲目重发。
4. “环境分组”新建草稿，填写组名、Ctrl/Shift选择成员并创建；保存修改会整体替换成员。删除分组不会删除环境。
5. “版本模板”填写模板名和配置环境名称；创建、保存后历史版本增加。选择历史并按“回滚成新版本”会生成新revision。填写新实例名称并按“创建环境实例”；实例有新ID/目录。删除模板会删除该模板历史，保留已创建环境。
6. 在“环境配置”选择环境，按“导出配置包”选择JSON路径；“导入配置包”选择导出的JSON。导出不含Cookie、密码、原环境身份或运行数据，不能替代备份。
7. 环境可归档、回收和恢复；永久删除前需移入回收站并勾选确认。按真实回执核对结果。
8. 批量启动/停止/归档/回收/恢复沿用主菜单的JSON参数文件入口；选择器框填写完整UTF-8 JSON路径，菜单执行“从JSON执行环境批操作”。参数示例见文档16/20。
9. “批次记录”切换范围、下一页或刷新第一页，选择批次核对详情；已确认终态勾选确认后按“归档批次详情”。压缩后详情不可恢复，摘要和去重身份保留。outcome-unknown必须先人工核对实际状态，目前没有人工改写回执接口，不能强行归档。

## 6 API与保留规则

三个入口使用同一92工具契约。新增/更新调用的arguments：

```json
{"scope":"active","limit":30}
```

```json
{"scope":"all","limit":30,"before":"上一页返回的nextCursor"}
```

```json
{"batchId":"需要归档的32位ID","confirmBatchId":"同一个32位ID"}
```

分别用于profile_batch_list、下一页list和profile_batch_archive。list返回items、hasMore、nextCursor、activeCount、archivedCount；末页nextCursor=null。游标对应持久rowid，在该记录归档后仍有效；不是分页快照，分页期间新增记录需刷新第一页查看。

每根最多1000条未归档记录、100000条终身请求身份。归档释放活跃额度，保留的摘要仍计入终身预算；不提供物理删除去重身份。到上限返回STORAGE_BUDGET_EXCEEDED；仍可查询旧回执和直接停止浏览器。未知/未结束记录不释放容量。新操作必须生成新requestId，不得把新ID当成失败操作的自动重试策略。

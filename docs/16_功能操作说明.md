## 1 第一次运行

1. 完整解压新ZIP到可写本地目录，例如`D:\Apps\AI-Browser-Workbench-0.1.13-win64-integrations-r1`。保留EXE、DLL、browser、portable.mode和source的相对关系。
2. 双击`Self-Test.cmd`。最终应显示`Self-test: passed`，报告位于`test-results/run-日期-随机号/report.json`。测试仅使用随机回环端口，不需要网站账号或公网。
3. 双击`Start-Workbench.cmd`或`workbench.exe`。桌面正常启动后可用下列路径操作自己的开发Web程序。
4. 包根`文档入口.md`可打开本手册、环境配置、开发编译与测试报告。首次运行无需安装VS/Python/Node；详细条件见[运行环境](17_运行环境搭建配置.md)。

| 中部分组 | 可见操作 |
| --- | --- |
| 网页操作 | 唯一CSS定位、填写、点击、读取文本、语义快照、探查高亮、清除高亮、预览点击、选择选项 |
| 页面与诊断 | 页面下拉框、页面列表、新页面、切换/关闭、页面事件、显式重连、开始/读取/停止诊断 |
| 流程与数据 | JSON文件路径、流程参数、校验/发布/运行、状态/暂停/恢复/取消、按Schema提取、执行动作批次 |

截图和已验收显示边界见[界面报告](27_桌面界面美化与交互验证报告.md)。

| 控件 | 操作/结果 | 说明 |
| --- | --- | --- |
| 左侧环境列表 | 单击选择要操作的环境 | 每次操作前核对环境名称/ID；新建成功自动选择新环境 |
| 环境名称 | 输入1–128个Unicode码点 | 这是标签，实际隔离由随机ID与私有目录管理 |
| 地址框 | 输入`http://127.0.0.1:3000/login`等真实地址 | 创建时由地址确定允许来源，协议/主机/端口均参与判断 |
| 新建环境 | 创建SQLite记录与独立环境目录 | 列表分两行显示名称、ID前缀及可用/已归档/回收站/删除中状态 |
| 保存名称 | 修改选中且停止环境的名称 | 用列表当前revision提交，旧版本冲突会拒绝 |
| 归档 / 回收站 | 将停止且无持久引用的环境归档或放入回收站 | 保留原ID、登录态与目录，不能直接启动 |
| 恢复 | 将归档/回收环境恢复为active | 保留原ID及数据 |
| 永久删除 | 对回收环境二次确认后删除 | 运行中、被引用或文件占用会拒绝；purging失败项可排除占用后重试 |
| 启动 | 启动该环境的受管浏览器，并自动取得5分钟控制租约 | 重复启动报PROFILE_ALREADY_RUNNING；窗口由工作台管理 |
| 打开地址 | 在当前受管主页面导航 | 输入页面必须属于创建时授权来源 |
| 唯一CSS定位 + 定位 | 例如`#username`、`button[type=submit]` | 必须匹配一个节点；重复匹配拒绝，不自动选第一项 |
| 填写值（隐藏） + 填写 | 按当前CSS重新定位并填写input/textarea | 提交后桌面值框清空，协议不回显输入；不支持文件上传/富文本等全部控件 |
| 点击 | 按CSS定位并点击 | 点击成功仅表示派发输入；须再查询业务结果 |
| 探查高亮 / 清除高亮 | 按唯一CSS探查并显示/清除原生覆盖层 | 返回可操作条件和草稿，不填写或点击 |
| 预览点击 | 按CSS只读判断当前可见/禁用/遮挡和视口 | 不点击、不聚焦、不滚动；正式点击仍重检 |
| 选择选项 | 原生select按值框中的一个精确value选择 | 值框清空；多选使用API的values数组，不按显示标签匹配 |
| 读取文本 | 按CSS读取元素innerText/textContent | 不用于读取密码；动态结果未就绪可只重读 |
| 语义快照 | 返回主帧AX树及临时ref | 快照刷新或导航后重新定位，旧ref不可盲复用 |
| 接管/撤销 | 撤销当前自动控制代数 | 旧租约不能再发送；已到达网站的提交不会被撤回 |
| 取控制 | 获取新的5分钟桌面租约 | 有效租约仍存在时可能LEASE_BUSY，先按接管/撤销再取得 |
| 停止 | 撤销并关闭本环境受管进程树 | 忙碌时排到有界当前操作之后；不终止用户普通浏览器 |
| 页面列表 / 下拉框 | 刷新当前环境页面ID，显示当前标记 | 选择后须点切换，才改变后续动作目标 |
| 新页面 / 切换 / 关闭选中页 | 使用地址框新建、选择目标页、关闭指定页 | 每浏览器32受管页；不是中央环境额度 |
| 页面事件 / 显式重连 | 查看有界元数据；重建同一实例连接 | 重连不重发原动作；先核对结果未知的业务 |

输出区显示JSON结果或错误。`ok:true`代表该命令完成，业务是否登录成功仍以页面身份/结果元素和服务器为准。关闭工作台会清理其受管浏览器；浏览器页面写入的持久Cookie和站点存储在同一环境重开后可继续使用，网站自身过期规则仍生效。

## 3 测试注册和登录

先启动自己的测试Web服务。以测试页具有以下选择器为例；其他页面需按真实DOM修改。开发人员也可使用源码的`tests/fixtures/web_app.py --port 3000`启动本项目本地夹具，该方式额外需要Python，属于可选开发工具。

1. 地址填`http://127.0.0.1:3000/login`，名称填“注册登录测试A”，点新建环境、启动、打开地址。
2. CSS填`#username`，隐藏值框填一个新测试账号，点填写；CSS改`#password`，值框填测试密码，点填写。
3. CSS改`#register`，点点击。然后CSS改`#result`点读取文本；夹具应显示`registered`。重复账号应按站点真实错误处理。
4. CSS改`#login`点点击，再读`#result`应为`logged-in`，读`#identity`应是测试账号。
5. 若结果尚未更新，只重复“读取文本”，不要反复点击注册/付款等提交按钮。CLI/MCP可用page_wait_text自动只读等待。
6. 点停止，重新启动、打开地址，再读`#identity`检查同一环境登录态。新建“测试B”再启动相同地址，其身份应为anonymous；这是隔离检查。
7. 用`.duplicate`定位项目夹具应报LOCATOR_AMBIGUOUS；禁用/隐藏按钮应拒绝点击；这些属于正确的保护行为。

本项目夹具账号保存在服务器内存，重启夹具后账号记录会消失；浏览器Cookie保留不意味着新服务器仍认识旧会话。请用测试账号验证，避免把不确定结果的提交自动重发。

## 4 外部程序调用CLI

双击`Start-CLI.cmd`，每行输入一个UTF-8 JSON请求。脚本使用`data/cli`，与桌面目录独立；默认使用JSONL。需要HTTP时双击`Start-API.cmd`，使用data/api和启动轮换令牌；实际路由及调用示例见[API参考](20_本地HTTP_API参考.md)。

```json
{"id":1,"command":"capabilities","arguments":{}}
{"id":2,"command":"profile_create","arguments":{"name":"接口测试","allowedOrigins":["http://127.0.0.1:3000"]}}
```

第二条回复包含实际`result.id`。后续将`PROFILE_ID`替换成这个ID：

```json
{"id":3,"command":"browser_start","arguments":{"profileId":"PROFILE_ID","headless":true}}
{"id":4,"command":"lease_acquire","arguments":{"profileId":"PROFILE_ID","owner":"my-test","ttlMs":300000}}
```

保存第四条返回的完整`{owner,token,generation}`对象，代入下面LEASE_OBJECT；这里是需要实际JSON对象的占位示意，不能把占位文字原样发送。标准顺序为：

```text
profile_create → browser_start → lease_acquire
→ browser_navigate(url, profileId, lease)
→ page_locate(selector, profileId, lease) 取得ref
→ page_fill(ref,value,profileId,lease) 或 page_click(ref,profileId,lease)
→ page_wait_text(selector,expected,timeoutMs,profileId,lease)
→ browser_stop(profileId)
```

| 实际工具名 | 必需参数（除说明外为对象字段） | 作用 |
| --- | --- | --- |
| capabilities | 无 | 实际版本、能力及未实现标志 |
| profile_list | 可选state，默认active | 可选archived/trashed/purging/all |
| profile_create | name、allowedOrigins数组；可选proxyServer/runtimeSettings | 创建；API可一次配置多个确切来源 |
| browser_start | profileId；可选headless布尔 | 启动 |
| profile_update | profileId、expectedRevision；至少一项name/allowedOrigins/proxyServer/runtimeSettings | 修改停止环境；proxyServer空串清除，runtimeSettings空对象恢复默认 |
| profile_archive | profileId、expectedRevision | 归档active环境 |
| profile_trash | profileId、expectedRevision | 回收active/archived环境 |
| profile_restore | profileId、expectedRevision | 恢复archived/trashed环境 |
| profile_purge | profileId、expectedRevision、confirmProfileId | 永久清理trashed/purging；确认ID必须完全相同 |
| browser_status | profileId | 进程归属、运行状态、版本 |
| browser_stop | profileId | 停止；无需有效租约 |
| lease_acquire | profileId、owner、ttlMs(1–300000) | 取得租约 |
| lease_revoke | profileId | 撤销；无需旧租约 |
| browser_navigate | profileId、lease、url | 来源范围内导航 |
| page_snapshot | profileId、lease | 主文档语义树 |
| page_locate | profileId、lease、selector | 唯一CSS，最多2048码点 |
| page_inspect | profileId、lease、selector；可选highlight | 无字段值的元素事实、原生高亮和动作草稿 |
| page_preview | profileId、lease、ref、action(click/fill/select) | 当前条件只读预览，不聚焦/滚动/执行 |
| page_clear_highlight | profileId、lease | 清除调试覆盖层，不改网页样式 |
| page_fill | profileId、lease、ref、value | 填写，最多65536码点 |
| page_click | profileId、lease、ref | 输入派发 |
| page_select | profileId、lease、ref、values数组 | 原生单多选；最多32个不同精确值 |
| page_text | profileId、lease、ref | 读取有限文本 |
| page_wait_text | profileId、lease、selector、expected、timeoutMs(1–10000) | 等待精确文本相等 |
| page_screenshot | profileId、lease | 返回PNG MIME与base64，由调用方保存 |
| page_list | profileId、lease | 列已登记页，收纳允许来源的子弹窗 |
| page_open | profileId、lease、url | 新建并选择独立页面，支持about:blank |
| page_switch | profileId、lease、pageId | 切换，全部旧ref失效 |
| page_close | profileId、lease、pageId | 关闭指定受管页面，最后一页关后可重新新建 |
| browser_events | profileId、lease；可选after/eventEpoch/limit(1–100) | 元数据游标轮询，溢出/断连有明确gap |
| browser_reconnect | profileId、lease | 同一受管进程显式重连，恢复页面会话，不重发原业务 |

请求ID支持字符串、整数、null；CLI缺ID按null回复。对象、数组、布尔或小数ID拒绝。每行不超过1MiB；未知命令/额外参数会报错。客户端应读取回复并匹配ID；关闭标准输入会使CLI退出并清理受管浏览器。

实验代理可在profile_create/profile_update传规范`http://host:port`或`socks5://host:port`；无用户名密码、尾斜杠或路径，端口明确1–65535。SOCKS5已验证域名型请求/远端解析及断代理不直连。桌面未提供代理编辑UI；HTTPS代理/认证/SSH和全网防泄漏仍待开发。

可选区域配置示例：`"runtimeSettings":{"userAgent":"My-Web-Test/1.0","languages":["zh-CN","zh"],"timezone":"Asia/Shanghai"}`。启动/状态返回runtime.requested与runtime.effective；实际网页值只覆盖当前主目标，非指纹内核。修改需先停止再按当前revision提交；非法时区启动失败会清理进程，修正后可重试。

## 5 AI客户端连接MCP

复制包根`mcp-config.example.json`中的配置，将PACKAGE_DIRECTORY替换为实际绝对目录（推荐使用`/`）。例如：

```json
{
  "mcpServers": {
    "ai-browser-workbench": {
      "command": "D:/Apps/AI-Browser-Workbench-0.1.13-win64-integrations-r1/workbench-mcp.exe",
      "args": ["--root", "D:/Apps/AI-Browser-Workbench-0.1.13-win64-integrations-r1/data/mcp"]
    }
  }
}
```

由支持MCP stdio的客户端启动服务；也可用Start-MCP.cmd检查标准输入输出。当前服务列出67个共享工具；上表是浏览器与环境工具子集，流程/诊断/提取等增量见后文。客户端先initialize并发送notifications/initialized，再列工具/调用。配置本服务不需要模型API Key；实际AI模型和客户端自身的设置在各自软件完成。配置兼容模型后可请求受限工作流草稿，人工审阅后发布运行；完整任意网站任务规划仍待开发。

桌面、CLI脚本、MCP分别使用不同根，创建的环境分别管理。目前不能把同一个data根同时开放给多个进程来共享环境；这会被ROOT_IN_USE拒绝。若需要统一调度，调用者应复用单一CLI/MCP服务，而不是绕过根锁。

## 6 错误处理、数据和边界

| 错误/现象 | 处理 |
| --- | --- |
| ROOT_IN_USE | 关闭占用相同根的服务，或为调用者指定独立根；不要删锁文件绕过 |
| REVISION_CONFLICT | 重新列环境取得当前revision，核对修改意图再提交 |
| PROFILE_RUNNING / PROFILE_REFERENCED / PROFILE_STATE_INVALID | 停止浏览器、解除实际资源引用或按允许状态转换；不可绕过保护 |
| PROFILE_BUSY / PROCESS_OWNERSHIP_UNCONFIRMED | 查看browser_status.recovery；活的未知归属进程不自动杀，先人工核对归属 |
| AUDIT_WRITE_FAILED | 若outcomeUnknown=true先核对业务结果；恢复日志写入条件后再执行新动作 |
| UNMANAGED_ROOT | 使用新的空根，不能指向现有普通Chrome配置目录 |
| ORIGIN_DENIED | 核对协议/主机/端口；127.0.0.1与localhost是不同来源；需要多个域时API创建时配置 |
| LOCATOR_AMBIGUOUS / ELEMENT_NOT_FOUND | 在目标页面核对CSS，使其唯一；检查是否位于主帧 |
| STALE_ELEMENT_REFERENCE | 导航、重启、快照或节点替换后重新定位 |
| LEASE_REQUIRED / LEASE_REVOKED / LEASE_BUSY | 核对当前环境；先撤销旧控制，再取控制，不重复提交网页业务 |
| ELEMENT_NOT_ACTIONABLE / ELEMENT_NOT_EDITABLE | 检查隐藏、禁用、遮挡、只读及控件类型 |
| PAGE_NOT_FOUND / PAGE_REQUIRED / PAGE_DETACHED | 刷新页面列表，选择已连接页或新建页；旧pageId不跨实例复用 |
| CDP_DISCONNECTED / CDP_RECONNECT_FAILED | 核对原业务后显式重连；失败仍可停止重启，不自动重复写动作 |
| EVENT_CURSOR_INVALID | 使用本实例返回的eventEpoch/after；重启后重新开始读取 |
| ASSERTION_TIMEOUT | 查询服务器/页面真实结果，再决定下一步 |
| ACTION_OUTCOME_UNKNOWN / CDP_RESPONSE_UNKNOWN | 操作可能已经提交，先人工/只读核对，不自动重试；可显式重连或停止后重开恢复通道，但不会撤回提交 |
| 自检哈希失败 | 使用原始ZIP重新解压；修改源码或包文件会改变初始校验，不能当成正常发布包继续传播 |

`data/desktop`保存桌面环境，`data/cli`/`data/mcp`/`data/api`用于相应脚本。API根的local-api.json含敏感访问令牌，不向网页/日志复制。`test-results`仅为独立自检数据。当前SQLite schema4自动升级旧v1/v2/v3并保留升级前快照；升级后不可再用旧版写同根。Windows DPAPI凭据库绑定当前用户；正常关闭后可备份自己的目录，但跨机器Cookie/加密凭据迁移尚未实现。给其他测试机分发时使用原始ZIP，避免带出已登录环境。

当前已有主文档录制、原生画布、凭据管理与流程调试窗口；账号/组织/购买/续费/席位页面、中央10免费额度/计费、iframe/OOPIF/Shadow深层动作、指纹修改、跨机同步和签名更新仍待完成。源代码的技术探测与GIF测试证据不等于产品里已有录像UI。

## 12 文件流程、数组、断言和环境库（automation-r3）

当前交付97个共享工具。使用[文件与数组样例](examples/workflow-files-v1.1.json)前，先启动`python tests/fixtures/web_app.py --port 3000`，创建允许`http://127.0.0.1:3000`的环境并取得租约。准备名为`fixture.txt`的普通文件，父目录须已存在；运行输入为：

```json
{"uploadPath":"E:/test/fixture.txt","downloadDirectory":"E:/test/downloads"}
```

样例顺序配置下载目录、打开`/extraction`、上传、断言、提取A/B列表、foreach执行、触发下载、等待完成。完成后核对`fixture.csv`实际存在、网页计数为2且最后值为B。`downloadWait`观察浏览器完成事件并核对普通文件的路径、大小，超时不重发点击。下载目录及跟踪作用于整个Profile浏览器；活动下载未结束时不能重设。页面数组标记为敏感值，不把提取结果正文写入运行记录。`upload/downloadConfig/downloadWait/assert/readTexts`五个节点可从画布中文节点库加入，当前属性使用JSON。

菜单“环境库与本地后台”提供分组、模板、配置导入导出、环境批操作、免费政策和概览。选中环境后，名称框用于创建分组或保存模板。配置导出只包含白名单设置，不包含Cookie、帐号密码、用户数据或原环境身份。导入会创建新ID和新目录；最多32项，校验或数据库事务失败时不产生部分环境。

其他菜单以“选择器/JSON文件路径”框指定UTF-8 JSON参数文件。以下分别为查看模板历史、回滚、实例化：

```json
{"id":"模板的32位ID"}
```

```json
{"id":"模板的32位ID","expectedRevision":3,"sourceRevision":1}
```

```json
{"id":"模板的32位ID","expectedRevision":4,"name":"新测试环境"}
```

回滚会把历史配置复制为新revision；原历史和已创建的环境不变。每模板最多保留100个不可变版本。旧v5只能回填当时的当前版本，不能恢复以前没有保存的版本。删除模板会删除该模板历史，已创建的环境保留。

批操作参数示例：

```json
{"requestId":"0123456789abcdef0123456789abcdef","onError":"stop","operations":[{"command":"browser_start","arguments":{"profileId":"环境的32位ID","headless":true}}]}
```

客户端应先生成并保存requestId。相同ID和相同参数再次调用只返回持久回执（receiptOnly=true），不会重启或重放；换参数会返回BATCH_ID_CONFLICT。新一批操作须使用新ID。支持启动/停止/归档/回收/恢复，最多32项，stop/continue控制已知失败后是否继续；未知结果总会停止。批次不是整批事务，不自动回滚已执行操作。

菜单“查看持久批次记录”列出最新100批；“从JSON查看指定批次”使用`{"batchId":"32位批次ID"}`。重启会把尚未派发的项记为not-run、已派发无回执的项记为outcome-unknown，保留已确认结果。此时先核对实际浏览器/环境状态，再决定下一次操作。当前最多1000未归档批次和100000终身请求身份；新表单可分页和归档已确认详情，释放活跃额度并保留摘要去重。未知结果不能归档；到上限拒绝新批次，停止浏览器仍可直接调用。完整过程、修复和测试见[本轮报告](38_未实现收口更新与回归验证.md)。

## 18 环境库管理表单与批次保留（automation-r4）

菜单“环境库与本地后台→环境库管理（表单）”打开四页原生管理窗口。环境页可编辑名称、来源、代理、UA、时区和语言，保存空覆盖会清除旧值；运行中请先停浏览器。新建草稿后创建；已有资源保存按当前revision提交。多个窗口版本冲突会保留输入，请先复制再刷新。

分组页支持Ctrl/Shift多选成员；模板页提供历史下拉、回滚成新revision和命名实例化。环境页的导入/导出使用系统JSON文件选择框。导出仅设置，不含会话和凭据；删除模板/分组不删除环境。永久删除环境须回收后勾选确认。

批次页每页30条，可切换未归档/已归档/全部、下一页及刷新第一页。选中已确认终态，勾选确认后归档详情；摘要/ID仍保留，同ID请求不会重放。未结束或outcome-unknown记录禁止归档。完整9步操作、API参数、升级及测试见[文档40](40_环境库表单与批次保留管理实现测试.md)。

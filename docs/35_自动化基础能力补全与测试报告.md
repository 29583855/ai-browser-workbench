## 3 发现的问题、处理和保留边界

| 问题 | 原因/证据 | 处理与复验 |

## 4 操作说明

### 4.1 登录和普通按钮测试

1. 从新包启动工作台，填写目标登录页地址，创建环境并启动。当前只允许环境显式配置的来源，不能自动扩权到其它站点。
2. 用“元素拾取”获得帐号框、密码框和登录按钮的唯一CSS；退出拾取后不会补发点击。也可以在选择器框填写“登录”，菜单“凭据与调试 → 查找功能”返回候选。
3. 帐号框使用普通填写；密码在“管理当前环境凭据”创建，复制返回元数据credentialId。原始值不进入流程文件。创建后密码框清空。
4. 在流程画布中将fill节点value设为`{"secretRef":"32位凭据ID"}`，selector设为刚才的密码框CSS；接上点击登录节点，并配置登录后身份/成功提示的文本后置断言。不要用“按钮被点击”作为登录成功。
5. 校验、发布。菜单勾选“下次流程从首节点暂停调试”，输入运行参数并运行。自动出现调试窗口；断点每行`main/节点ID`或`子流程名/节点ID`。
6. 单步进入、跨过、跳出分别执行执行器中的实际步骤/子流程，不能撤回已提交的登录、注册或发布动作。只有暂停时会显示变量；输入和网页输出按敏感数据隐藏。
7. 登录成功后，使用功能发现查询“发布”“搜索”等，核对候选的对象、enabled和唯一CSS，然后配置后续步骤及业务成功断言。多个相同按钮须进一步核对所在对象。真正富文本、分页结果数组、通用上传/下载和跨frame控件仍需对应适配，不能承诺任意网站直接运行。

SecretRef使用后截图阻断是实例级策略，包括其它页面和之后的导航；需要截图时先结束该实例并重启。所有字符串脱敏只是已知凭据值的保守过滤，不代替外部站点数据分类、隐私处理或完整报告脱敏系统。

### 4.2 DSL1.1节点示例

在已有合法定义上，设置schemaVersion为1.1并声明variables，例如：

```json
{"count":{"schema":{"type":"integer","minimum":0,"maximum":100},"initial":0,"sensitive":false},
 "title":{"schema":{"type":"string","maxLength":16384},"initial":"","sensitive":false}}
```

对应节点：

```json
{"id":"increase","type":"set","variable":"count","value":{"op":"add","args":[{"var":"count"},1]},"next":"read"}
```

```json
{"id":"read","type":"readText","selector":"#title","variable":"title","next":"done",
 "onError":{"codes":["ELEMENT_NOT_FOUND"],"next":"fallback"}}
```

fallback和done必须是真实可达节点。支持add/sub/concat/length/trim、输入引用、变量引用和有界字面量Schema。foreach.items可引用声明的必填输入列表或变量，maxIterations最多32；循环结束恢复原item值，其它变量结果共享。新版编辑器Schema仅用于结构提示，实际类型、深度、图、预算和来源仍由C++统一验证。

### 4.3 模型和知识包

模型配置先查询model_status取得revision，在选择器框填配置JSON文件路径，再用“模型与知识包 → 从JSON文件配置模型”。参数包括expectedRevision、完整endpoint、model、timeoutMs、maxCalls、maxOutputTokens、maxTotalTokens；远程HTTPS提供model用途的credentialId，来源须与端点一致。无模型配置时可继续手工录制、编排和回放。

生成请求JSON包含task、allowedOrigins，可按工具Schema提供其它已支持参数。生成成功返回draft、validation、requiresReview，并打开画布。配置文件、模型名称和密钥引用应按实际服务填写；不会提供假支付、OIDC或签名通过状态。budget按请求JSON字节数加输出token预算保守预留，属于准入上界，不是供应商账单的精确token用量。

知识包先preview确认origin、routes、requiredCapabilities、locators、工作流及摘要和差异，再以expectedLatestVersion导入。用export指定packageId/version精确取回。工作流必须通过相同校验且来源与包一致，navigate路径含子流程全部受路由白名单约束；单包1MiB、最多64包、每包16版本，总8MiB。导入不创建凭据、不加载扩展、不运行工作流。

定位修复JSON包括definition、expectedSha256、stepId、selector，可选flow；菜单读取后仅生成新草稿。来源必须与当前Profile一致，新selector必须当前唯一。先前失败runId保持不变。

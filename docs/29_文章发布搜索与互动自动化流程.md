## 1 本次补充的目标与当前状态

用户准备好文章和任务要求后，软件应能在选定浏览器环境中登录、识别当前界面、找到创作/发布入口、填写并发布文章；也能按关键词搜索信息，整理文章列表，再按任务指定的对象和内容执行点赞、回复及评论，并逐项验证实际结果。

这里的“发布”指把文章提交到目标网站，与工作台“发布流程”保存不可变自动化定义是两个动作。文章由用户提供；回复/评论可使用用户给定文字，或在任务明确要求时生成草稿。网页内容作为待处理数据，不替代用户给出的目标、帐号、文章或任务范围。

| 能力 | 0.1.8当前可复用部分 | 本轮仍需开发/站点验证的部分 |
| --- | --- | --- |
| 登录和会话 | 独立环境、持久登录态、主文档CSS填写/点击、身份文本核对 | 完整登录模板、跨站认证、MFA接续及会话策略 |
| 识别页面功能 | 主文档AX快照、唯一CSS定位、探查/高亮、点击预览 | 内置AI规划器、语义候选排序、功能发现面板和站点适配 |
| 文章发布 | 对普通input/textarea填写，对已定位按钮点击，精确文本后置断言 | 富文本编辑器、附件/封面上传、站点发布状态核对和发布任务UI |
| 信息搜索 | 定位搜索框/按钮、填写、点击，读取已知结果元素 | 搜索结果列表结构化采集、分页/懒加载、URL采集、去重和筛选UI |
| 点赞/回复/评论 | 对已确定目标的已适配控件填写/点击 | 互动状态读取、目标/父评论绑定、结果去重、持久业务回执 |
| 执行流程 | DSL1.0顺序/条件/有界循环、子流程、状态及检查点 | 按搜索结果数组循环、运行时结果变量、站点知识包和完整调度 |
| AI调用 | CLI、MCP、鉴权本地HTTP的44个共享工具 | 产品内模型Provider、任务编排/列表展示与完整预算管理 |

这些目标均可通过浏览器页面交互实现，但不能据此声称当前程序已经支持任意网站的一句话全自动发布。当前外部AI客户端可调用已实现工具逐步控制已适配页面；工作台自身尚无完整的自然语言业务规划器。前轮只补充设计，本轮已在自建回环网站真实发布、点赞、评论和回复，没有操作外部真实业务网站。

## 2 完整自动操作路径

任务配置 → 选择环境与帐号 → 登录并核对身份 → 观察当前页面 → 发现功能入口 → 定位并预览 → 执行业务动作 → 核对结果 → 保存逐项记录。

发布分支：读取准备好的文章 → 打开创作/新建文章 → 填标题/正文/分类等 → 核对草稿 → 按设定保存草稿或正式发布 → 打开文章详情/管理列表核对状态。

搜索分支：输入关键词及筛选条件 → 发起搜索 → 读取结果 → 按规则分页/去重 → 罗列文章 → 按任务指定的文章/评论执行互动 → 核对每一项回执。

发布、搜索和互动是三个可组合子任务。仅搜索时不自动执行互动；发布完成不自动替用户增加点赞或评论。任务已经包含的自动操作按预设范围连续执行，无需每个步骤再次确认。未配置的站点、帐号、文章或互动对象不由页面提示自行扩展。

## 3 启动前需要准备的内容

| 信息 | 应填写的内容 | 示例含义 |
| --- | --- | --- |
| 环境与帐号 | profileId/环境名称、站点来源、预期登录身份 | 同一身份在同一环境操作，多帐号各用独立环境 |
| 文章 | 本地稿件、标题、正文、分类/标签、可见性、封面/附件要求、修订号 | 正文是要发布的内容，文件路径只是本地输入位置 |
| 发布方式 | 保存草稿或自动正式发布，目标栏目/帐号 | 自动发布必须是任务明确选择的输出 |
| 搜索要求 | 关键词、站内/站点、时间/分类等实际筛选条件 | 关键词相同但时间范围不同，是不同搜索任务 |
| 结果范围 | 最大页数、最大条数、去重规则、结果字段 | 用明确上限控制结束条件 |
| 互动对象 | 指定articleId/URL，或明确的筛选规则和最大数量 | 不把搜索到的所有文章自动当作已选目标 |
| 互动内容 | 点赞目标状态、评论文字、回复的parentCommentId与正文 | “回复文章”和“回复某条评论”分别记录 |
| 运行策略 | 总时长、每项等待时限、最小操作间隔、失败处理 | 遇到站点限流或权限拒绝停止并记录，不改帐号续发 |
| 证据 | 保存哪些文章链接、状态、截图和错误码 | 不保存密码、Cookie、会话令牌 |

新建环境时填页面地址，再启动并登录；详细步骤沿用[从零到一手册](28_Web系统从零到一测试操作流程.md)。当前没有“选择本地文章并自动导入”的产品面板：普通文本可由用户填入隐藏值框，或由外部调用程序读取文件、作为运行输入传给已支持的填写步骤。文件上传和富文本要单独适配。

## 4 登录后如何自动找到功能入口

### 4.1 功能发现顺序

1. 核对选中环境、活动页面和当前登录帐号，确认该帐号具有创作或互动权限。
2. 获取页面语义快照，识别导航、按钮、链接、表单和弹窗，记录当前页面/实例代数。
3. 根据目标找候选，例如“创作中心/写文章/发布/新建内容”“搜索/检索”“点赞/已赞”“评论/回复”。文案只是候选信号，不能把所有“发布”都当作文章提交。
4. 结合页面区域、元素角色、可访问名称、相邻标签和站点约定筛选。文章详情中的“回复”须绑定具体评论行，不能只靠全页第一个同名按钮。
5. 为候选建立唯一CSS，调用定位、探查/高亮和动作预览。存在多个候选时继续观察表单/区域，不能直接取首个节点。
6. 每次导航、打开菜单/弹窗或切换标签页后重新观察和定位。旧ref不能跨页面/重启复用。
7. 将经过验证的定位规则、版本和成功条件归入站点适配定义；页面变化后重新核验，不能把旧坐标长期复用。

当前已实现的基础链路可写成：`page_snapshot → 外部AI/用户筛选候选 → page_locate → page_inspect/page_preview → page_fill/page_click → page_wait_text/读取业务结果`。这是现有工具的组合，不是新增了名为“自动找发布按钮”的内置工具。

### 4.2 需要补齐的发现能力

设计上支持基于role/name/区域的候选清单、列表行与业务对象绑定、菜单展开后再观察、元素状态变化和站点适配版本。多frame、Shadow深层、Canvas/OCR及拖拽编辑器走各自能力门；没有匹配能力时返回具体缺项，不能虚报已找到或已执行。

## 5 自动发布准备好的文章

### 5.1 浏览器中的实际动作

| 顺序 | 页面动作 | 需要验证的业务事实 |
| --- | --- | --- |
| 1 | 登录并读取用户菜单/身份 | 是目标帐号，具有发布权限 |
| 2 | 找到创作入口，打开编辑页 | 当前是新建文章，不是编辑其他文章或设置发布规则 |
| 3 | 填写标题 | 标题与准备稿件一致，长度符合网站要求 |
| 4 | 填写正文 | 正文完整，段落/格式与编辑器支持的格式一致 |
| 5 | 设置分类、标签、可见性等 | 按任务配置设置，不继承不明确的默认值 |
| 6 | 如任务要求，上传封面/附件 | 上传完成且页面显示正确资源；当前完整上传能力未实现 |
| 7 | 核对草稿预览 | 帐号、标题、正文、栏目、可见性与稿件修订一致 |
| 8 | 按任务配置保存草稿或点击正式发布一次 | 保存草稿不能报告为公开发布 |
| 9 | 处理站点业务确认弹窗（如有） | 核对文章目标和发布方式后完成该步骤 |
| 10 | 打开详情或文章管理列表 | 获得articleId/详情URL、作者、实际状态、站点时间等 |
| 11 | 保存最终记录 | 已公开、待审核、草稿、失败或结果未知分别记录 |

示例定位约定是`[data-testid="create-article"]`、`[data-testid="article-title"]`、`[data-testid="article-body"]`、`[data-testid="article-publish"]`；这是自有系统可以提供的测试属性，实际网站必须替换并验证。正式发布前的“发布流程”按钮只保存自动化定义，不会替你提交文章。

### 5.2 当前编辑器能力边界

普通标题input和正文textarea可复用page_fill。contenteditable、iframe富文本、Markdown/HTML双模式、图片粘贴、文件上传、编辑器自动保存均需站点适配与测试；当前不能宣称通用支持。自动填入正文后还要核对编辑器实际内容，不能只凭输入事件派发成功判断全文完整。

首次开发适配时，先在自己的测试内容系统逐项验证，再组合自动流程。对跨域创作中心或认证跳转，环境/流程来源需匹配；当前来源约束不等同于全网网络防火墙。

### 5.3 发布结果和重复提交

“按钮点击成功”“出现成功Toast”“提交接口返回200”都不是文章已经公开的充分证据。需要核对作者、标题、内容修订、文章详情及站点状态；审核中的文章记为pending-review，按任务要求算“提交成功”或“尚未完成公开发布”。

设计记录由taskId、帐号/站点、稿件修订和目标栏目等构成任务标识。公开结果保存articleId/规范详情URL、状态与核验时间；内容摘要不能单独作为去重键，因为不同任务可能合法发布相同内容。发生超时、断连或提交后无回执时，先查文章管理列表，确认上次是否已经发布；未知状态不自动再次提交。当前完整持久业务去重与恢复仍待实现，不能把本地标识说成目标网站支持exactly-once。

## 6 搜索信息并罗列文章

### 6.1 搜索和结果整理步骤

1. 在任务允许的站点打开搜索入口，找到搜索框、筛选条件和提交按钮。
2. 输入关键词，选择实际支持的时间、分类、作者或排序条件，点击搜索一次。
3. 等待结果区域或“无结果”状态，核对显示的关键词/条件与任务一致。
4. 读取每个结果的标题、文章ID/规范URL、作者、摘要、发布时间、来源和可见互动状态；页面没有的字段标为缺失。
5. 优先以站点articleId去重，其次使用保留内容身份参数的规范URL；不能随意删除所有查询参数导致不同文章合并。
6. 在最大页数/条数/时长以内继续翻页；记录下一页游标/页码，页面无新项、到末页、无结果或达到上限时结束。
7. 将结果罗列成可选择的清单，保留来源和观察时间；排序/相关性评分由任务规则决定，并说明依据。

| 序号 | 标题 | 作者 | 时间 | 来源/详情链接 | articleId | 匹配原因 | 选定操作 | 实际结果 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 待采集 | 待采集/缺失 | 待采集/缺失 | 待采集 | 待采集/缺失 | 关键词/筛选条件 | 仅查看/点赞/评论/回复 | 未执行 |

结果页变更、虚拟列表复用和下一页重复数据都要重新绑定对象，不能按“第3行”长期指定文章。“搜索全网”需要配置具体搜索入口及允许访问的站点；当前未实现通用搜索引擎连接器或任意页面采集器。

### 6.2 当前提取工具的限制

page_extract当前支持有界标量对象及text/count/checked/受限attribute读取；不支持直接输出文章数组，attribute仅允许title、aria-label、data-testid，不能用它直接读取任意href。现有工作流没有搜索结果数组变量/动态foreach，输入计数循环也不等于“遍历刚搜索到的文章”。

因此，完整“搜索→结果数组→分页去重→选中项互动”仍需扩展列表采集/URL归属校验和编排层。当前可由用户或外部AI在已适配页面读取明确元素逐项操作，不能把规划中的列表接口当作已经可调用。T029已验收的标量提取/有界批处理保持原范围，新增列表能力单独验收。

## 7 对选定文章点赞、评论及回复

### 7.1 目标选择与执行模式

支持两种产品目标：先搜索列出、由用户选定后执行；或启动任务时给出确定的筛选规则和数量上限，自动选择并执行。可按任务一次性设置auto-publish/auto-like/auto-comment/auto-reply及指定内容，已授权的动作连续运行，不增加逐项重复确认。

每项操作绑定站点、帐号、articleId/URL，以及回复需要的parentCommentId。搜索结果与操作清单分开保存；条目标题相同不代表同一对象。互动文本可逐项提供；若要求AI生成回复，应先读取对应文章/父评论，再按任务约束生成，任务记录绑定最终实际发送的正文摘要和版本。

### 7.2 点赞

1. 打开目标文章，核对文章与帐号；读取当前帐号的“已赞/未赞”状态。
2. 任务设定目标为“已赞”。如果已经点赞，记录already-satisfied并跳过点击；不能再次点击导致取消点赞。
3. 未点赞时定位目标文章的点赞按钮，预览后点击一次。
4. 重新读取该帐号的点赞状态；计数可能受其他用户影响，不能只看总数增加1。
5. 记录确认成功、已满足、失败或未知。当前通用aria-pressed/站点点赞状态读取需要补齐，不能仅凭按钮文字猜测。

### 7.3 评论文章

1. 核对目标文章，在该文章评论区域找到输入框。
2. 填写任务提供或按任务生成的评论正文，核对内容及目标。
3. 选择正确“发送/发表评论”按钮，仅提交一次。
4. 查新评论的作者、正文、articleId/归属、commentId和状态。待审核或仅本地乐观显示要单独标记。
5. 如回执丢失，先按目标文章、帐号、任务记录、文本摘要和时间范围查询，不直接再次发送。网站没有足够核对条件时保留未知。

### 7.4 回复某条评论

1. 找到parentCommentId对应评论，核对作者和正文摘要。
2. 点击该评论行自己的“回复”，确认编辑区显示正确的回复对象。
3. 填写回复正文，提交一次。
4. 验证新回复属于正确父评论和文章，并记录replyId/commentId及状态。

页面出现多个“回复”“发送”按钮时，必须限定文章和评论区域。回复成功不能只判断“列表里出现相同文字”，还要检查作者、父级关系和服务端/页面实际状态。

## 8 AI和现有接口如何配合

| 业务阶段 | 已实现工具可承担的部分 | 额外编排/适配 |
| --- | --- | --- |
| 观察 | page_snapshot、page_inspect、page_locate | 外部AI/用户理解界面并选择唯一目标 |
| 输入 | page_fill、page_select | 富文本、附件和复杂控件适配 |
| 执行 | page_preview、page_click、page_batch | 业务对象绑定及执行范围校验 |
| 核验 | page_wait_text、page_text、page_extract | 动态文章URL/ID、列表/点赞状态及评论父级查询 |
| 跨页面 | page_list/open/switch、browser_events | 新标签归属和目标文章身份核验 |
| 流程 | workflow_validate/publish/run/status/control | 搜索结果驱动的动态循环、变量与业务恢复 |
| 证据 | browser_diagnostics_*、page_screenshot | 任务结果页、业务回执和导出功能 |

工具参数仍按当前MCP/API契约传递，不新增未实现的publish_article、search_articles、like、comment或reply工具名。现有流程click必须有文本postcondition；动态UI状态不满足这一契约时，应先设计可验证的适配，不能删掉后置断言来冒充通过。

附[内容自动化任务配置草案](examples/content-automation-task.example.json)，用于明确任务范围、稿件引用、搜索及选定对象。它标为design-only，**不是当前DSL1.0输入，也不能直接导入“校验流程/执行动作批次”**。draft://标记也不是已实现的文件读取/凭据服务。实际运行要先将任务转成站点适配后的现有工具调用，或开发对应执行层。

已提供独立的[可执行DSL1.0流程](../examples/content-lab/workflow-publish-search.json)和[站点脚本](../examples/content-lab/runner.py)。后者逐行读取本站公开文本列并编排分页/互动，不新增page_extract数组或任意href能力，也不改变上述design-only草案的格式含义。

“取消”停止后续项，不撤回已发布内容或评论；取消点赞、删除文章/评论是另一个明确配置的业务动作，不能当作失败后的默认回滚。UI必须区分草稿、已提交、待审核、已公开、已满足、失败和未知，不使用单一绿色成功掩盖差异。

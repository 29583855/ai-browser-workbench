## 2 标准部署步骤

1. 获取`AI-Browser-Workbench-0.1.13-win64-integrations-r1.zip`及同级`.zip.sha256.json`。
2. 将两者复制到测试机，使用系统PowerShell核对ZIP哈希。以下为示例目录：

```powershell
Set-Location 'D:\Downloads'
$awbMeta = Get-Content '.\AI-Browser-Workbench-0.1.13-win64-integrations-r1.zip.sha256.json' -Raw | ConvertFrom-Json
$awbStream = [IO.File]::OpenRead((Join-Path (Get-Location) $awbMeta.file))
$awbSha = [Security.Cryptography.SHA256]::Create()
try {
    $awbActual = [BitConverter]::ToString($awbSha.ComputeHash($awbStream)).Replace('-', '').ToLowerInvariant()
    if ($awbActual -ne $awbMeta.sha256 -or $awbStream.Length -ne $awbMeta.bytes) { throw 'Archive mismatch' }
} finally { $awbStream.Dispose(); $awbSha.Dispose() }
```

3. 用资源管理器完整解压到`D:\Apps`等可写本地目录。不要覆盖现有版本目录。
4. 双击Self-Test.cmd，应显示passed。报告路径由窗口输出，可保留report.json及对应日志反馈。
5. 双击Start-Workbench.cmd；按[操作说明](16_功能操作说明.md)创建环境和访问站点。运行过程中新数据保存在包内data，而非原开发机器路径。

SHA-256用于发现复制损坏/文件变化，不构成数字签名或发行者认证；本包尚未代码签名。遇到企业策略拦截应按企业的应用批准流程处理，不要求关闭系统防护。

## 4 自检、数据保护与版本更换

自检核对初始包全部文件，执行核心/存储/窗口及回环网页填写点击，并检查MCP、包内VC库、默认便携数据。自检将默认根探针放在自己的test-results中，可在桌面已打开时执行，避免修改/争用正在使用的桌面data。

修改包文件或源码后初始哈希会失效。开发时可显式用`Self-Test.ps1 -SkipHashCheck`检查行为；分发时应重新打包生成新清单，不能把跳过校验作为部署验收结果。

新版本用新目录解压。旧版data不自动搬迁；需要复用同机测试环境时先正常关闭旧程序，备份完整旧目录，再通过`--root`指向同机所属旧根进行有针对性验证。当前本地数据库schema7，自动事务迁移早期版本并保留升级前快照，升级后不能用旧程序写同根；没有对降级/跨机数据迁移作承诺，也无自动回滚机制。跨机器测试分发应复制原始ZIP，避免传出Cookie或登录态。

## 5 常见部署问题

| 现象 | 检查/处理 |
| --- | --- |
| 缺MSVCP140/VCRUNTIME140 | 重新完整解压；确认DLL与EXE同级、未被隔离；不要从未知网站下载单个DLL |
| 程序无窗口/立即退出 | 先运行自检查看日志；确认x64系统、目录可写、marker完整、browser完整；企业策略需单独核对 |
| 浏览器启动失败 | 看BROWSER_START_FAILED/PROFILE_BUSY；检查完整运行时、端口与受管进程权限，确认不是系统普通用户目录 |
| ROOT_IN_USE | 另一进程正在用同一根；关闭它或选新根，不删锁绕过 |
| 定位失败 | 确认当前选中环境、目标URL、来源、CSS唯一且位于主帧；这属于操作/页面适配问题 |
| 自检提示包校验失败 | 与原始ZIP比对；文档/源码被编辑也会失败；使用新目录重解压核对 |
| 登录态换机器后消失 | 跨机加密凭据迁移尚未实现；在新机器新建环境并按站点重新登录 |

反馈时提供系统版本、包版本、复现操作、report.json及相关日志。不要发送整个data、Cookie、真实账号密码或页面中的业务秘密。

## 6 本地API及外部服务参数

双击Start-API.cmd后在data/api/local-api.json读取当前url/token；端口仅回环、每次启动换令牌，无需IIS、URLACL或管理员。正常退出删除端点文件；保留local-api-audit.jsonl及最多3份轮换日志。调用示例见[API参考](20_本地HTTP_API参考.md)。UA/语言/时区由环境runtimeSettings配置，非系统全局设置。

支付、OIDC、签名和第二台机目前均未提供；这些不是当前本地运行必需条件。对应后台/签名功能尚未接入，不能靠填参数宣称商业联调通过。

0.1.3多页面仍使用同一个环境数据目录/Chromium进程树；显式重连不增加环境或收费席位。元数据事件是256条进程内缓冲，服务/浏览器重启不能恢复历史游标。完整Space、实时订阅和工作流恢复尚未实现。


## 0.1.5 流程运行配置

执行内置C++14流程不需要Python、Node、模型API或商业后台。仍使用包内浏览器和VC142运行库。workflow-register-login.json的默认来源是http://127.0.0.1:3000；夹具仅在开发测试时用Python启动，实际站点需修改流程allowedOrigins/URL并创建来源完全相同的Profile。当前租约最长5分钟，不自动续租。

私有data根增加workflows/versions和workflows/runs，只保留发布定义和无输入值的元数据检查点。运行时输入/租约不跨重启恢复。达到256发布版本或256运行记录时明确拒绝，当前无产品归档清理界面；测试新批次可使用新的独立data根，不能手动删除未决任务来伪造成功。详见[流程边界](23_流程执行器与检查点测试报告.md)。


0.1.6诊断使用现有CDP/WinHTTP，不增加运行时依赖。新增src/browser/diagnostics.cpp已加入原生工程和CMake，保持v142/C++14；功能及验证见[诊断报告](24_诊断收集与步骤关联测试报告.md)。


0.1.7提取与批次复用包内程序和浏览器，不新增终端运行依赖。桌面导入文件须为UTF-8且位于可读本地路径；演示需按操作文档启动自建回环Web夹具。

0.1.7-r2修正当前固定Chrome在较长Profile路径中CacheStorage失败的问题。浏览器数据始终留在所选data目录；路径超过100个UTF-16单元时，程序在当前用户LocalAppData/AWB-Paths内创建仅指向该目录的短路径连接。该私有目录不保存Cookie/密码副本；退出时仅移除连接本身，异常退出遗留的连接下次核验目标后复用。无需用户手动配置，不能手工把其他目录连接当作Profile传入。

运行账户需能写LocalAppData并创建目录连接，当前在本机Windows本地磁盘验证。如果用户目录过长、目录连接策略禁止或存在不同目标的同名连接，启动返回BROWSER_STORAGE_PATH_TOO_LONG、BROWSER_STORAGE_ALIAS_FAILED或BROWSER_STORAGE_ALIAS_CONFLICT；选择较短本地data根或修正权限后重试，不静默换Profile。这里不承诺其他浏览器版本/文件系统或跨机器Cookie迁移已验收。


## 0.1.8 桌面显示条件

界面使用Windows原生Common Controls/GDI，无需安装WebView、额外主题引擎或字体包。优先Microsoft YaHei UI，结果区Consolas，缺失时由Windows字体映射回退。默认窗口按工作区裁剪，可调整大小；内容按DPI换算，较小客户区提供原生横纵滚动条实现。建议优先在常规桌面尺寸运行。

本机正常尺寸下四组界面及键盘焦点已观察验证；缩小窗口滚动、不同缩放比例、跨显示器移动、高对比度与完整读屏矩阵尚未完成实测，不能据代码存在宣称兼容矩阵通过。代码包含启动时高对比度配色回退与WM_DPICHANGED处理。当前仍有独立浏览器窗口，不是内嵌浏览器产品壳。详见[界面报告](27_桌面界面美化与交互验证报告.md)。

凭据库使用Windows DPAPI绑定当前Windows用户，无需外部服务；秘密不会随原始便携ZIP分发。配置兼容模型时，远程端点须HTTPS并引用model用途凭据；本机测试端点可HTTP。未配置模型时录制/编排/手动及SDK自动化正常可用。产品不需要Python/Node，只有开发测试或调用相应SDK时才安装。详见文档35。

## 10 当前配置与升级说明（automation-r4）

文件/数组/断言、分组、模板历史和批次持久记录均在C++程序内实现，运行不需要Python、Node或数据库服务器。Python只用于启动练习网站、开发测试和打包；外部模型、支付、OIDC及证书配置均为可选的后续联调项，未配置不会伪装成生产服务可用。

SQLite索引为v7。首次打开旧v1–v6数据根前，程序先创建`.before-v7.<随机ID>.sqlite3`备份再迁移，保留原迁移记录与哈希。升级后不要再用旧版程序写同一数据根。备份仅覆盖索引，浏览器会话文件和DPAPI凭据需要另行保留；复制索引或导出配置不等于会话迁移。DPAPI仍绑定当前Windows用户。

旧v5模板升级时仅回填当时当前revision，未保存的历史无法补造。模板最多100个不可变版本，库最多1000项，分组最多100成员；批次最多1000未归档记录和100000终身请求身份；API每页1–100条，桌面每页30条。已确认详情可归档释放活跃额度，摘要/请求ID保留去重；未知结果不可清理。单批操作或配置导入最多32项。

上传仅接受最多100 MiB的普通单文件；下载目录位于可写本地路径，其父目录需已存在。重解析点、目录代替文件和硬链接等会拒绝。下载目录配置作用于Profile浏览器，超时不取消下载，也不自动再次触发。第二台Windows/干净机、长稳和跨浏览器版本完整矩阵仍需后续验收。

环境库表单已在本机680×520尺寸验证双向滚动，文件选择期间阻止主窗口退出，保存期间退出会等待真实请求结束。此结果仅覆盖本轮新增面板，不能替代主桌面/画布的多DPI和实体多屏完整验收。无新增产品运行依赖；升级与保留规则见[文档40](40_环境库表单与批次保留管理实现测试.md)。

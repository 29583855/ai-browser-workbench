## 3 原生VS2019编译和调试

打开AIBrowserWorkbench.sln，选择x64/Debug或Release；默认首项目workbench。9项目包括awb_sqlite、awb_core、workbench、workbench-cli、workbench-mcp、workbench-admin、workbench-node、awb-core-tests、awb-storage-tests。

```powershell
Set-Location 'E:\project\webexploer_codex' # 复制源码时换成实际source目录
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-vs2019.ps1 -Configuration Both
```

也可双击Build-VS2019.cmd，或传`-VsRoot 'D:\Program Files (x86)\Microsoft Visual Studio\2019\Enterprise'`指定实例。脚本自动发现vswhere时支持不同安装盘；无需先把cl加入普通PATH。

产物位于`build/native-vs2019/x64/Debug`和`Release`，中间文件按项目/配置隔离。编译参数包括C++14、Unicode、/utf-8、/Zc:__cplusplus、/W4 /WX、/permissive-；链接启用ASLR/DEP/高熵VA。Debug统一MDd、Release统一MD；SQLite C目标单独保留上游告警设置。

脚本构建后运行核心、SQLite和Win32 smoke，日志保存在`build/evidence/native-时间`。不要只看输出目录中存在旧EXE判断成功。Visual Studio调试时可在workbench属性“调试/命令参数”设置：

```text
--root "E:\MyTests\desktop-debug" --browser "D:\Apps\AI-Browser-Workbench-0.1.13-win64-integrations-r1\browser\chrome-win64\chrome.exe"
```

父目录E:\MyTests需先存在，根应空或属于本项目。复制源码的编译输出旁未附浏览器时，程序会查已安装Edge/Chrome，也可显式给包内浏览器；这与构建成功是两个条件。Debug产物需开发机Debug CRT，不用于复制给普通测试机；便携包只打Release。

## 6 浏览器来源与重新打包

本次固定官方归档：`https://storage.googleapis.com/chrome-for-testing-public/156.0.8078.80/win64/chrome-win64.zip`，208152768字节，SHA-256为`16edb57d6107bf1c48a7c149b8d78b155fe614410093796dd72441fd6640540f`。不要用当前正在运行的浏览器用户目录替代原始归档。

开发根通常使用build/runtime/runtime-origin.json和chrome-win64.zip；复制包的source没有重复大ZIP，打包器可回退读取相邻browser/runtime-origin.json，再用-BrowserArchive提供已校验归档。归档变化、依赖锁变化、非x64PE或缺匹配Redist均明确拒绝，即使Python使用-O也不会跳过发布输入校验。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/package-portable.ps1 `
  -VsRoot 'D:\Program Files (x86)\Microsoft Visual Studio\2019\Enterprise' `
  -Python '.\build\review-venv\Scripts\python.exe' `
  -BrowserArchive 'D:\RuntimeArchives\chrome-win64.zip' `
  -OutputDirectory 'D:\NewPackages\AI-Browser-Workbench-0.1.2-win64-mytest'
```

Python需3.12或更高以支持使用到的Path API；本轮只验收3.12.3。默认输出路径从version.hpp读取版本。每次输出目录和ZIP必须不存在；不要覆盖旧测试包。打包脚本先Release编译并测试，再复制5EXE、官方Redist中的9DLL、原始固定浏览器、全部当前源码和文档，生成逐文件manifest、ZIP及ZIP校验。安装的VS必须提供匹配`VC/Redist/MSVC/14.29.30133/x64/Microsoft.VC142.CRT`及Licenses/2052/Redist.txt；本次使用中文VS安装，其他语言布局应明确验证许可文件路径。

新ZIP部署验证：

```powershell
& $awbPython tests/integration_package.py --archive 'D:\NewPackages\AI-Browser-Workbench-0.1.2-win64-mytest.zip' --output build/evidence/manual-package-1 --vs-root 'D:\Program Files (x86)\Microsoft Visual Studio\2019\Enterprise'
```

这会解压到中文/空格路径，从系统目录启动，验证桌面并行自检、桌面/CLI/MCP入口、篡改/缺运行库拒绝，并重建复制源码Release。新增API与生命周期还应分别对最终解压包执行integration_api.py/integration_lifecycle.py。最后原始交付目录应保持data为空、无test-results；验证只操作解压副本。

## 7 常见编译问题

| 现象 | 排查 |
| --- | --- |
| MSB8020/缺v142 | Installer补装VS2019 C++工具，核对实例与VCToolsVersion |
| MSB8036/SDK不存在 | 补装10.0.19041.0，不静默改成26100等版本 |
| C++14/__cplusplus或MSC检查失败 | 使用本方案v142与/Zc:__cplusplus，不能用v143冒充 |
| Debug/Release CRT不匹配 | 清理受影响配置并统一MDd/MD；不混接不同配置lib |
| CMake实例冲突 | 使用新的build目录或按本机流程重新配置相同VS实例，不混用旧缓存 |
| BROWSER_NOT_FOUND | 构建已完成但机器无浏览器；传--browser或用完整便携包 |
| Python模块缺失 | 核对运行测试的解释器路径及venv；SDK按锁安装，Pillow单独安装 |
| 哈希/许可/源码审计失败 | 查输入实际变化，恢复固定依赖或重新验收；不能直接改清单宣称通过 |

尚未建立自动CI、签名/自动更新、第二台/三台干净Windows验收流水线。商业浏览器再分发、完整SBOM与内核维护仍按NOTICE及T065/T078/T094后续门处理。

## 2 固定构建矩阵

| 维度 | 首轮基线 | 发布要求 |
| --- | --- | --- |
| IDE/编译器 | VS2019 16.11 servicing、v142 14.29.30133 | 记录具体 cl/link 版本、实例、升级原因和日志 |
| 语言 | `/std:c++14`，CXX_STANDARD 14、required | 检查最终命令，没有 `/std:c++17`、`c++latest` 或特定目标偷偷提升 |
| 平台 | x64；主程序/Qt/直接链接依赖一致 | x86/ARM64 不在首版；不能把 x86 库混到 x64 |
| SDK | 10.0.19041.0 候选 | 头文件、库、资源/签名工具完整，干净机验证 |
| 配置/CRT | Debug `/MDd`；Release `/MD` | Qt、静态库中使用 CRT 的部分及应用配置匹配；Debug CRT 不随 Release 分发 |
| 编译选项 | `/W4 /permissive- /Zc:__cplusplus /EHsc` | 自有代码告警基线；第三方告警隔离，不全局压制 |
| 安全链接 | DEP/ASLR、Release 配置与 PDB 分离 | 用最终 PE/构建日志验证，不仅看模板 |
| 构建系统 | VS2019 内置 CMake 3.20 命令行 + MSBuild | 生成器 `Visual Studio 16 2019`，`-A x64 -T v142` |
| 编码 | 每文件检测并保持原编码/BOM/换行 | 已确认 UTF-8 的目标才加 `/utf-8`；遗留 GBK 采用正确源字符集或窄范围单独构建 |
| 配置存储 | 本机路径/令牌不写入仓库 | 使用本地配置和安全凭据；制品不带开发机绝对路径和秘密 |

`/Zc:__cplusplus` 使 `__cplusplus` 反映语言模式；它不是整个源码符合标准的证明。CMake compile feature 可能请求更高标准，因此 T003/T077 同时检查各目标属性和实际编译参数。严禁为了省事关闭 CXX_STANDARD_REQUIRED 或全局覆盖到 C++20。

不把 v142 与 v143 理论上的某些二进制兼容性当发布依据。直接 C++ 链接依赖原则上用同一工具链构建；采用 Qt 预编译包时，必须有其工具链/CRT 兼容依据和 Debug/Release 实测。跨 DLL 避免暴露 STL、异常、分配器与 Qt 私有 ABI；内存谁创建谁释放。SQLite/CivetWeb 等优先稳定 C API；现代 Node/Java/OCR/浏览器通过进程协议连接。

## 4 CMake 与命令模板

以下保留T003规划阶段的示意模板，不能直接替代当前工程。实际可运行命令以tools/build.ps1与文档13为准；源码目标使用当前CMakeLists.txt，未创建的正式模块不得添加虚假路径。

```cmake
cmake_minimum_required(VERSION 3.20)
project(AIBrowserWorkbench VERSION 0.1.0 LANGUAGES C CXX)

set(CMAKE_CXX_STANDARD 14)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
set(CMAKE_MSVC_RUNTIME_LIBRARY "MultiThreaded$<$<CONFIG:Debug>:Debug>DLL")

if(NOT MSVC OR NOT MSVC_TOOLSET_VERSION STREQUAL "142")
    message(FATAL_ERROR "主程序必须使用 MSVC v142；日期：2026-11-03")
endif()

add_library(awb_core STATIC src/core/application.cpp)
target_compile_options(awb_core PRIVATE /W4 /permissive- /Zc:__cplusplus /EHsc)

# 用途：仅在确认本目标所有源文件均为 UTF-8 后启用；日期：2026-11-03。
target_compile_options(awb_core PRIVATE /utf-8)
```

模板只演示标准和 CRT，不是完整 CMake 工程。MSVC 版本范围、SDK 完整性、依赖 pin、链接选项和路径门由 T003/T077 补齐；自有每个目标都应继承同一受控配置。对于遗留混合编码文件，不复制模板的 `/utf-8`，先按文件设置源字符集并做运行时文本验证。

PowerShell 配置/构建候选（采用显式实例，避免 Enterprise/Community 选择漂移）：

```powershell
$awbVsRoot = 'D:\Program Files (x86)\Microsoft Visual Studio\2019\Enterprise'
$awbCmake = Join-Path $awbVsRoot 'Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe'
& $awbCmake -S . -B build/vs2019-x64 `
    -G 'Visual Studio 16 2019' -A x64 -T v142 `
    "-DCMAKE_GENERATOR_INSTANCE=$awbVsRoot" `
    -DCMAKE_SYSTEM_VERSION=10.0.19041.0
& $awbCmake --build build/vs2019-x64 --config Debug --parallel 4
& $awbCmake --build build/vs2019-x64 --config Release --parallel 4
```

固定工具集补丁目录的参数在 T003 根据实际生成器支持验证，首次日志应确认选择 14.29.30133；若选择不同版本必须失败或更新记录，不能静默接受。环境初始化可使用 VS2019 Developer PowerShell 或对应 vcvars64.bat；PowerShell 子进程运行 bat 不会自动把环境回传到父 PowerShell，不能据此假定 cl 已进入当前 PATH。

当前 CMake 为 3.20，不使用需要 3.25 的 Presets schema v6。后续若增加 Presets，先确定 CMake 最低版本和 VS2019 IDE 对所选 schema 的支持；命令行可运行不等于 IDE 一定可加载。不得使用 `latest` vcpkg baseline 自动更新依赖；先固定兼容 v142 的工具/ports/release，审查传递依赖标准与构建日志。

## 6 编码、中文注释与格式化

修改前逐文件记录 SHA-256、编码来源、BOM、换行方式和是否存在混合换行；无法可靠识别的编码不整文件重写。现有规划 Markdown 为 UTF-8 无 BOM、LF，本次继续保持。新增自有代码建议 UTF-8，是否带 BOM在 T002 冻结；资源编译器 `.rc`、脚本和生成工具分别验证，不能假定 `/utf-8` 覆盖全部工具。

每个新增/修改函数在定义处提供中文用途、日期、重要边界；对接口补充线程、输入/输出、所有权、超时/取消、错误含义。示例约定：

```cpp
// 用途：校验受管 Profile 是否允许提交动作；日期：2026-11-03。
// 边界：只检查状态，不派发动作；失效租约返回 false，不自动刷新 generation。
bool CanDispatchAction(const ProfileState& profile, const Lease& lease);
```

这是未来接口示例，不是现有实现；实际函数写入当天记录实际日期，不机械改动无关代码。第三方原件保留版权/编码；补丁说明来源，不把中文注释要求扩展成批量重写上游代码。

clang-format 固定版本，配置 `Standard: Cpp14`；先格式化小范围，再比较语义与编码。若工具默认重写为 UTF-8/LF，与原格式不同，采用临时副本格式化并按原编码/换行安全回写，检查字符可往返；无法往返则停止该编辑。CI 拒绝新增 C++17 标准库/语言特性，但关键证据仍是 v142 `/std:c++14` 实编译。

## 8 CI、制品与后续维护

选择固定 VS2019/v142 的 Windows agent，自托管或可固定的合法镜像；公共 runner 预装 VS2022 不等于已满足 v142。CI 不依赖已退出维护的历史 runner 标签，运行前检查实例/工具集/SDK/架构，失败时报告清晰原因。所有依赖缓存键包含源 commit、工具链、CRT、架构与配置，不让不同编译器产物共用缓存。

发布记录源码提交、契约 hash、工具版本、依赖/SBOM、浏览器/Worker 版本、制品 SHA-256、签名证书身份及时间戳、数据 schema、可回滚范围和验收报告。CRT 分发按微软许可与维护策略选择受支持兼容版本，不能凭开发机 DLL 拷贝推定可分发；干净机验收决定准入。签名密钥不进入源码/普通 CI 日志，签名与实际发布仍是后续工作。

VS2019 servicing、Qt5 维护、SDK/CRT、浏览器和 Worker 各有更新责任；主程序工具链受用户约束，浏览器不能因此停止安全更新。触发更新时重跑受影响的构建/协议/隔离/安装用例，来源许可变动先做准入。若安全更新需要不兼容工具链，提出具体替代与影响，再修改 ADR，不静默升级语言标准。

先实测源码/缓存/产物峰值、带宽、冷/热构建、故障恢复及并发预算，再确定机器规格；本次未下载 Chromium、未购买资源、未执行现代内核构建。自动更新不能把有已知高危漏洞的旧内核作为无限期回滚目标；安全分级、受影响能力暂时关闭/替代运行时及数据 schema 兼容都需明确策略。持续维护成本独立，不计入本地 29 周容量。

# ADR003：原生流程画布技术验证与选型

日期：2026-11-04。结论：VE002技术样例采用Direct2D/DirectWrite+Win32原生控件，继续VC2019/v142/C++14。Qt/nodeeditor及WebView2仍是未接入备选；本次没有新增第三方运行时或修改许可清单。

画布已经实际接入workbench.exe菜单，使用同一个Service校验/发布流程。界面提供节点库、画布、原生EDIT属性和结果、主/子流程及端口选择。输入和属性保留系统IME承载方式，不自绘候选窗；实体键盘输入、多个显示器和屏幕阅读完整矩阵仍由VE027负责。

技术验证由`workbench.exe --flow-self-test <绝对报告路径>`创建真实窗口并通过Win32消息验证节点移动、框选、库拖入、滚轮缩放、中键平移、箭头键、属性中文、撤销重做和共享非法图拒绝。200节点作为多流程草稿性能夹具，不因此扩大DSL1.0单flow128步预算。

测试使用真实窗口96DPI、Direct2D目标96/144DPI、0.5/1/2缩放命中，记录60次绘制及p95。初轮发现列表框内部捕获影响库拖放，已改为显式LB_ITEMFROMPOINT命中/捕获并复验。数据与原始失败见[统一测试文档](../32_可视化RPA实施与测试记录.md)。技术样例不代表实体150%显示器或完整IME候选窗矩阵已经验收。

选择理由：当前平台已固定Windows，系统图形接口符合C++14；原生属性控件可复用现有输入、焦点和字体；样例达到200节点<2秒打开、绘制p95<50毫秒目标，因而没有证据要求引入第二套正式画布。

本ADR关闭VE002的技术样例与路线决策，不关闭VE027的全部平台测试、VE010/VE011/VE012的完整编辑器范围，也不提高全项目商业可用结论。

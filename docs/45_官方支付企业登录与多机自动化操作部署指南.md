# 官方支付、企业登录与多机自动化操作及部署指南

日期：2026-11-05。版本：0.1.13-poc。适用：Windows x64、VC++2019/v142、C++14。程序包括 workbench.exe、CLI、MCP、独立后台 workbench-admin.exe 和独立执行节点 workbench-node.exe。源码新增函数带中文用途及日期，原有文件保持UTF-8无BOM/LF，解决方案保持原换行。

## 1 从空参数开始

1. 解压完整部署包到可写的独立目录，运行 `Self-Test.cmd`，再运行 `Start-Admin.cmd`。
2. 后台默认仅监听127.0.0.1，首次在 `data/admin` 生成 `bootstrap.key`、`payment-config.json`、`official-payments.json`、`oidc-config.json`、`server-config.json` 和数据库。首次管理员使用bootstrap.key初始化，无默认账号或口令。
3. 官方支付和OIDC默认关闭，字符串参数为空；缺参数时操作明确返回 `PAYMENT_NOT_CONFIGURED` / `OIDC_NOT_CONFIGURED`，不会虚构支付成功或SSO身份。线下收款和本地免费自动化仍可使用。
4. 外部服务准备好后编辑对应配置，关闭并重启后台加载。不要把真实配置、数据库、DPAPI文件、浏览器登录态或初始化密钥放入源码或发给别人。
5. 本机节点测试可用回环HTTP；跨电脑节点、官方渠道和正式IdP使用HTTPS，并由Windows验证服务端证书。不提供忽略证书错误的开关。

## 2 官方支付

进入管理门户“概览与套餐”选套餐创建订单，再到“订单与账务”，填写订单号、选择渠道与操作，点击“执行官方渠道操作”。创建付款返回二维码内容或Stripe受信HTTPS付款链接；付款后查询，或者由官方异步通知入账。页面跳转成功不能发放权益。

| 渠道 | 已实现操作 | 配置必要参数 |
| --- | --- | --- |
| 支付宝开放平台 | RSA2签名预创建、查单、全额退款、退款查询、原始JSON响应/表单通知验签 | appId、sellerId、PKCS8 privateKeyPem、支付宝SPKI publicKeyPem、baseUrl、notifyUrl |
| 微信支付API V3 | Native下单、out-trade-no查单、全额退款/退款查询、商户RSA签名、平台签名验证、AES-256-GCM通知解密 | appId、merchantId、merchantSerial、PKCS8 privateKeyPem、32字节apiV3Key、platformKeys序列号到SPKI/JWK公钥、baseUrl、notifyUrl |
| Stripe | Checkout Session创建/查询、全额退款/查询、原文Webhook HMAC与多签名密钥轮换 | secretKey、webhookSecrets数组、liveMode、apiVersion、baseUrl、successUrl、cancelUrl |

模板由程序生成；支付接口所有金额采用整数人民币分，当前仅CNY和全额退款。生产baseUrl只允许代码列明的官方地址（支付宝含官方沙箱），HTTP夹具必须显式allowLoopbackTest且地址为127.0.0.1。生产配置保持allowLoopbackTest=false。

通知地址：`/payments/alipay/notify`、`/payments/wechat/notify`、`/payments/stripe/notify`。支付宝成功回复纯文本success，微信成功204，Stripe成功200。验签使用收到的原始字节，重复通知只产生一次对应的账本/权益事实；金额、币种、商户、模式或渠道不一致拒绝。迟到来款进入平台核对列表。

退款：客户先申请全额退款，平台运营员执行渠道退款，再查询其状态。预付包必须在发出官方资金指令前冻结仍可退的秒数，未知结果期间不释放冻结额，确认退款不重复扣秒；已消费或被运行槽预留的秒数不能通过此接口退款。商户后台另行退款产生的已验签资金事实会如实入账、撤销权益，必要时余额可成为欠额并阻断新增付费使用。

网络超时或响应验签失败显示unknown，先查单/退款查询。同一个业务操作键不会重复发起已记录操作；同订单不跨渠道创建。Stripe创建响应丢失仅在23小时窗口内按固定官方Idempotency-Key及相同订单快照恢复；窗口外要求人工查商户账单。不要把换一个幂等键当作可以重复扣款的理由。支付宝和微信使用固定商户订单/退款号。

人工商户对账、拒付争议、部分退款、多币种、自动扣款委托等属于另行验收范围，当前入口不显示这些动作。现有订阅续费仍是明确下单付款续期。

## 3 企业OIDC登录及桌面连接

1. 在IdP注册OIDC Web客户端，授权码模式，S256 PKCE；配置RS256/JWKS。回调必须精确为 `https://门户域名/auth/callback`。注册退出回跳 `https://门户域名/`。
2. 编辑oidc-config.json：enabled=true，issuer精确发行方、clientId、clientSecret、redirectUri、tokenAuthMethod。支持client_secret_basic、client_secret_post和none（公共客户端）。额外端点来源只有明确加入allowedEndpointOrigins才接受。生产allowLoopbackTest=false。
3. allowAutoProvision=true时允许verified email的新身份自动创建普通本地组织；不是平台管理员。若邮箱已有本地账号，禁止自动合并。先登录原账号，再到“账户安全”点击“绑定当前企业身份”。issuer/sub绑定唯一，不能借同邮箱取得他人账号。
4. 门户点击“通过企业身份服务登录”，完成IdP登录后回到门户。后台核验state、浏览器HttpOnly绑定、nonce、PKCE、签名、issuer、audience/azp、期限、可选at_hash/c_hash，再签发本地HttpOnly/SameSite Cookie。正式入口附Secure；原始IdP令牌不返回前端或写入URL。
5. 进入“账户安全”，生成120秒单次桌面连接码。在workbench.exe菜单“后台账号与授权”中，后台地址填门户HTTPS地址、邮箱栏填 `sso`、密码栏粘贴连接码，点击登录。代码同样可调用新工具 `account_connect_code({url,code})`，旧账号密码登录继续兼容。共享工具总数为97。
6. 普通退出吊销本地会话；“退出企业身份登录”先吊销本地会话，再按受信发现文档生成RP发起退出地址。IdP不可达仍完成本地退出；IdP是否接受不带id_token_hint的client_id退出由服务自身决定，可能要求确认或额外登录策略。没有宣称所有IdP都保证全局单点退出。

OIDC新建账号默认禁用本地密码，使用SSO或连接码。账号/组织/成员在本地停用后旧会话、连接码、节点准入重新检查状态。MFA、组织目录同步、企业IdP真实兼容及恢复流程需在实际身份服务中验收；没有将IdP组直接映射为平台管理员。

## 4 多机自动化：从0到1

1. 在门户“多机自动化”创建项目，填写名称和目标网站来源，例如 `https://测试系统.example.com`。来源不包含路径。项目权限默认组织管理员可管，API还可设置authorizedUsers。
2. 选项目和节点容量，生成5分钟一次性注册码。每台节点机器安装同一版本完整包；复制 `source/examples/deployment/node-config.example.json` 到自己的私有配置目录，填写root、browser、url、name、enrollmentToken，按需headless。root父目录必须存在；两个节点使用不同root。
3. 本机演练url可填 `http://127.0.0.1:17861`；跨机器填正式HTTPS入口，例如 `https://nodes.example.com`。执行：

```powershell
.\workbench-node.exe --config D:\PrivateWorkbench\node-a.json
```

便携脚本也可使用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Node.ps1 -Config D:\PrivateWorkbench\node-a.json`；节点后台启动，日志写在配置文件旁，先检查启动日志再到门户审批。配置绝对路径、中文和空格路径均可；不要把注册码写在命令行。

4. 节点生成独立RSA密钥和随机身份凭据，DPAPI保存，首次注册后处于pending。门户核对节点名称与公钥后点“批准/启用”。同版本、工具契约、能力、会话与心跳均可查看。每个节点只向中央主动出站，不开远程命令端口。
5. 在“分配环境”选项目、节点、环境名称。中央先预留环境容量，固定配置摘要、节点、所属账号和generation。环境数据/登录态留在所属节点。配置/密钥文件不能直接复制到另一Windows用户冒充原节点；换机器需重新注册并创建新环境分配。
6. 从本地画布发布/查看已验证流程定义，粘贴到“发布不可变流程版本”。后台复用同一DSL校验器，拒绝项目范围外的网站。填写环境、版本、输入JSON、超时秒数，加入队列。环境所属账号提交任务；项目成员使用分配给自己账号的环境。
7. “刷新数据”查看queued、dispatched、accepted、running、succeeded/failed/cancelled/unknown。节点容量不足或中央权益不足时排队；中央按持久FIFO序号领取，环境同一时间只接收一项未决运行。同一幂等提交返回原任务，不重做网页业务。
8. 节点先持久Inbox再ACK，使用真实Chromium和既有流程引擎执行登录/填写/点击/发布/断言；结果回执带原命令与固定版本。每条实际CDP发送还检查中央epoch、环境代数和本地单调租约；中央租约20秒，节点保留2秒保护量。
9. 取消会撤销新的派发资格并停止浏览器。网络请求失败即撤销该运行，本地租约到期也自动停止。协调器或节点重启时旧任务进入unknown，不自动重放。槽只有节点确认进程及受管Job全部退出后才释放；unknown的业务结果仍需人工到目标系统核对。
10. unknown且“确认已停止”为真时，点击“核对业务结果”，填写真实结果说明。此动作结束核对，不重试点击或发布。节点未确认停止时不能强制当成功释放；先修复/重启该节点核对持久进程身份。
11. 节点“维护”停止新领取，已有正常任务继续；“撤销”停止租约且身份不可恢复，需重新注册。项目禁用、成员停用、来源缩小、设备撤销、权益撤回均会在下次准入/心跳拒绝继续派发。
12. 正常停机：先维护节点并等待完成，或明确取消后执行：

```powershell
.\workbench-node.exe --stop --config D:\PrivateWorkbench\node-a.json
```

脚本入口为 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Stop-Node.ps1 -Config D:\PrivateWorkbench\node-a.json`，配置必须属于该运行Windows用户。

停止命令有界等待由主线程执行，持久保留未发完回执；重启补报结果。强杀节点时Windows Job回收浏览器，重启核对后回报unknown，绝不重新运行旧命令。

组织级免费10环境/10并发/1席位与付费扩展沿用现有中央权益；跨设备/节点合计。节点进程自己的capacity不会提高组织配额。免费RPA、Local API、AI/Web测试不要求购买。节点本地文件、凭据和网站登录权限受执行Windows账号及项目信任边界约束；只给可信项目登记节点。

## 5 HTTPS和可选mTLS部署

后台自身始终绑定回环HTTP。部署可信HTTPS反向代理，参考 `source/examples/deployment/Caddyfile.example`，配置域名、证书及转发到127.0.0.1:17861。`server-config.json.publicOrigin`填写精确门户HTTPS origin；只允许该Host及本地回环Host，浏览器JSON POST校验Origin，不无条件信任Forwarded标头。

节点启用mTLS时使用独立nodes域名入口：门户入口拒绝node.enroll/open/poll/ack/complete/event六个执行协议接口；node.enrollment.create、node.state等用户管理接口仍由门户账号权限保护，管理员无需节点证书。节点入口要求客户端CA认证，只开放这六个出站协议接口，转发时覆盖Host及私有X-AWB-Node-Transport证明。后台同时设置requireNodeTransportProof=true和至少32字节随机nodeTransportSecret，与代理私有环境变量AWB_NODE_PROXY_SECRET一致。公开门户必须删除客户端自带的该标头。缺证明的节点协议请求后台拒绝，不能从公开门户绕过mTLS。

在节点运行Windows用户的“个人/MY”证书库中导入有私钥及客户端认证用途的证书，配置clientCertificateThumbprint为40位证书指纹。这里SHA1仅用于Windows查找证书标识，业务签名仍是RSA-SHA256。WinHTTP选择此证书完成mTLS，不放宽服务端链校验。不要把PFX口令写进配置；使用系统证书工具导入。

证书轮换：维护并排空节点；代理同时信任新旧CA/有效证书；将新证书导入运行用户MY，更新指纹并重启节点；验证节点心跳后收回旧证书/旧CA信任。节点RSA身份保持，未决任务按重启核对；紧急撤销先在门户撤销节点，再撤销网关证书信任。CA证书发行、到期续签和网关安装是环境配置，需要实际证书联调，当前没有捆绑伪造的正式证书。

本轮实现单个持久协调器服务多Windows节点。不是多协调器HA；PostgreSQL、多地域弹性、Windows服务跨会话桌面代理、跨节点浏览器用户数据迁移、长稳/灾备SLA需独立建设和验收。两个本机节点证明真实进程协议和浏览器行为，不等同两台物理机证据。

## 6 开发和复测

VS2019 Enterprise/Community均可，v142 14.29.30133、SDK10.0.19041.0、x64/C++14、/MD（Debug /MDd）。打开AIBrowserWorkbench.sln，新增workbench-node项目；原有程序仍共享awb_core。链接新增Windows原生ncrypt.lib，无额外支付/OIDC运行时安装包。

```powershell
.\tools\build-vs2019.ps1 -Configuration Both
python tools/generate_contract.py --executable build/native-vs2019/x64/Release/workbench-cli.exe --check
python tests/integration_official_oidc_nodes.py --bin build/native-vs2019/x64/Release --browser build/runtime/browser/chrome-win64/chrome.exe --output build/my-integrations-test
python tests/integration_backend_extensions_edges.py --bin build/native-vs2019/x64/Release --browser build/runtime/browser/chrome-win64/chrome.exe --output build/my-integrations-edge-test
```

Python只用于开发验收，需cryptography（测试RSA/AES，不是产品实现）。脚本创建全新隔离目录，已有目录不覆盖；所有临时密钥/账号/浏览器数据只写build下。协议夹具独立校验C++请求签名，正/负向结果写JSON。门户资源更新后运行 `python tools/embed_admin_portal.py` 再编译。

推荐在独立Python3.12虚拟环境运行 `python -m pip install -r tests/official-requirements.lock.txt`。本机实际验证cryptography48.0.0、cffi2.0.0、pycparser3.0，锁文件只用于夹具；复制程序运行不需要安装这些包。便携节点脚本单独测试：`python tests/integration_node_launchers.py --package <完整解压目录> --output build/my-node-launcher-test`。

版本和契约统一由include/awb/version.hpp、Service::Tools生成。新工具及客户动作已经同步Python/TypeScript薄SDK和OpenAPI；不允许只改前端按钮而不接后台。测试详情、缺陷及证据见[实施验收](44_官方支付OIDC与多机调度实施验收.md)。

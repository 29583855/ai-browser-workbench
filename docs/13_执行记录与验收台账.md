## 2 可以运行什么

原生构建输出在 `build/native-vs2019/x64/Release`，CMake构建输出在 `build/vs2019-x64/Release`。独立可复制包见[文档14](14_VC2019工程与便携测试包.md)：

| 程序 | 实际作用 | 当前边界 |
| --- | --- | --- |
| workbench.exe | 环境创建/修改/归档/回收/恢复/删除、启动停止、打开地址、AX 快照、CSS 定位、填写/点击/读文本、撤销/取控制 | 原生界面已有主文档拾取/录制、流程画布及恢复；完整产品导航、账号和购买页面仍待开发 |
| workbench-cli.exe | JSONL stdio 请求/回复，可被外部程序驱动 | 显式--http启用鉴权回环REST；一个私有根只允许一个服务进程 |
| workbench-mcp.exe | 实际 MCP stdio 服务，87 个共享工具 | 不声明取消/订阅/资源等未实现能力；不是中央节点 Agent |
| awb-core-tests.exe | 真实核心/契约/平台行为验证 | 不能替代浏览器、后台或商业联调 |
| awb-storage-tests.exe | SQLite迁移、事务、故障、备份恢复及WAL崩溃验证 | 注入仅在测试目标；未覆盖断电或跨机器环境迁移 |

先启动本地夹具，再启动桌面程序：

```powershell
Set-Location E:\project\webexploer_codex
python tests/fixtures/web_app.py --port 3000
# 在另一个终端执行：
& .\build\vs2019-x64\Release\workbench.exe --root E:\project\webexploer_codex\.run\desktop --browser E:\project\webexploer_codex\build\runtime\chrome-win64\chrome.exe
```

首次使用前创建 `.run` 父目录；根目录必须为空或属于该 POC，不能指向已有浏览器用户目录。现使用 workbench.sqlite3；打开旧 POC 根时保留 workbench-poc.json 和只读 .pre-sqlite.bak 并事务导入，保留 Profile ID 及原会话目录；不要再用旧程序写同一根。桌面中用 `http://127.0.0.1:3000/login` 新建环境、启动、打开地址；选择 `#username`/`#password` 填写，再选 `#register`/`#login` 点击，通过 `#result` 与 `#identity` 读取业务结果。填写值控件隐藏输入并在提交后清空。重复匹配拒绝操作。控制租约有效期 5 分钟，过期后使用取控制；已有控制权时先接管/撤销。切换 Profile 不共享租约。

CLI/MCP 使用独立根目录，通过参数 `--root` 和 `--browser` 启动。JSONL 示例：

```json
{"id":1,"command":"capabilities","arguments":{}}
```

标准执行次序为 `profile_create → browser_start → lease_acquire → browser_navigate → page_locate → page_fill/page_click → page_wait_text → browser_stop`。页面动作必须带 profileId 和完整 lease，填写不回显内容。87 工具由 `Service::Tools()` 统一生成 schema，CLI/MCP/HTTP共用处理入口；未知命令和多余参数拒绝。SecretRef、模型草稿、知识包和页面发现边界见文档35。

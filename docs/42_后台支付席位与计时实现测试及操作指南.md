# 后台、支付、席位与计时实现、测试及操作指南

日期：2026-11-05。版本：0.1.12-poc。编译：VC++2019 v142、x64、C++14。

本次新增独立的 `workbench-admin.exe`、中文客户/运营门户、独立控制面数据库及工作台账号表单。现在可以实际完成：注册组织 → 发布套餐 → 下单 → 核实线下收款或验签网关回调 → 开通权益 → 邀请成员 → 浏览器申请全局运行槽 → 记录用量 → 续费或退款。必要的支付参数默认留空，未配置渠道明确拒绝发起支付。

本文件中的勾选表示下述具体功能已实现并通过测试。原 ADM/COM/BR 工作包有更广的验收范围；其余工作继续保留在原计划，不能把本次单机业务链交付等同于完整商业发布。

## 2 从零使用后台

1. 将新便携包完整解压到可写目录，例如 `E:\WorkbenchTest`。旧 r4 包保持不变。不要只复制单个 EXE。
2. 双击 `Start-Admin.cmd`，默认后台地址 `http://127.0.0.1:17861`。浏览器会打开管理中心。服务后台运行，日志在 `data\admin\startup*.log`。
3. 用记事本打开 `data\admin\bootstrap.key`，复制初始化密钥。在门户选择“初始化平台管理员”，填写邮箱、至少12字符的密码、组织/昵称、初始化密钥。首次初始化成功后服务永久关闭该入口。
4. 平台账号会拥有自己的组织和平台运营权限。实际客户用“注册客户组织”建立独立组织，注册完成立即有免费额度；无需绑卡或充值。
5. “平台运营 → 发布套餐版本”填写产品标识、名称、价格（分）、有效天数、环境数、并发数和席位数。包时订阅选择 subscription；预付时长选择 prepaid，并填写包内秒数，至少300秒。
6. 客户在“概览与套餐”点击“购买/续费”，订单会出现在“订单与账务”。重复点击保护之外，API调用必须自行提供稳定的幂等键。
7. 未配置网关时使用线下收款：客户查看订单号及金额，按运营方另行提供的真实收款指引付款。平台核对银行/渠道流水后，在“线下收款/退款确认”填订单号、成交金额、唯一流水及说明，确认收款。
8. 刷新客户门户，检查授权和席位。只创建订单、打开支付页面或点击按钮不会开通权益。
9. 续费购买同一产品。新订单支付后，授权从现有付费期末接续。当前实现按明确的天数 × 86400 秒计算，不按自然月自动扣款。
10. 申请全额退款后，由平台实际退款并核对流水，再确认退款。权益及账本同时回收。发票如已开具，按“待冲红”处理并登记实际冲红编号。

## 3 席位与成员

组织 owner/admin 在“成员与席位”填写被邀请人的邮箱和角色。邀请成功即占一个席位，令牌只显示一次；自行交给对应用户，本软件不会自动发送邮件。对方注册相同邮箱的账号，在“接受邀请”填写令牌即可加入。组织切换菜单会出现新组织。

邀请过期或撤销会释放预占名额；停用成员释放席位，并在后续动作和巡检时撤销其执行资格。恢复成员需要有空闲席位。admin 不能将自己提升为 owner；涉及 owner 的变更必须由 owner 执行，组织必须保留至少一位有效 owner。

平台运营权限独立于组织角色。普通组织管理员不能确认到账、发布平台价格或读取其他客户账务。finance 可以下单、支付、申请退款/发票；普通 member 可以使用获授环境，不能代组织下单或分配席位。

## 4 连接桌面浏览器及AI自动化

先启动后台，再启动工作台。进入“环境库与本地后台 → 后台账号与授权（表单）”，填写后台地址、客户邮箱和密码；组织ID留空时使用个人默认组织，加入团队后可从门户复制目标组织ID。纯本地已运行的浏览器应先停止，再连接商业账号。

连接成功后，浏览器启动会先申请组织环境登记和全局并发槽。网页动作、流程步骤和巡检检查当前会话、成员、组织、设备及权益。关闭浏览器后才释放运行槽。退出账号或切换账号前必须停止已跟踪的浏览器；会话过期但仍有未决槽时，可以用同一组织/账号重新认证后核对停止。

CLI JSONL示例（密码由调用者安全输入，不要把真实口令放进日志或提交源码）：

```json
{"id":1,"command":"account_connect","arguments":{"url":"http://127.0.0.1:17861","email":"YOUR_EMAIL","password":"YOUR_PASSWORD","deviceName":"开发机"}}
{"id":2,"command":"account_status","arguments":{"remote":true}}
{"id":3,"command":"account_action","arguments":{"action":"snapshot","body":{}}}
```

随后使用既有 `profile_create/browser_start/lease_acquire/browser_navigate/page_* /workflow_*` 流程，工具名称与参数不变。后台采用 `POST /api/{action}` JSON API，返回 `{ok,result}` 或 `{ok:false,error}`。认证使用 `Authorization: Bearer ...`。组织动作可以指定 `tenantId`，服务端必须再次检查成员资格。

账号的本地文件是 `commercial.dpapi`，绑定当前Windows用户。复制程序到另一台机器后重新登录；不要复制正式浏览器账号数据或会话密钥作为测试包。独立离线开发模式保持免费，商业客户端协议不是防篡改许可证或付费浏览器内核。

## 5 支付参数与适配协议

首次启动自动生成 `data\admin\payment-config.json`：

```json
{
  "enabled": false,
  "checkoutBaseUrl": "",
  "merchantId": "",
  "webhookSecret": "",
  "contract": "awb-signed-checkout-v1"
}
```

参数由用户后续填写，修改后重启后台。启用时要求 HTTPS 收银台地址、仅字母/数字/下划线/短横线的商户ID，以及至少32字节的独立回调密钥。服务启动时校验配置；错误配置不能悄悄退成“已支付”。文件在当前Windows用户私有目录内，请勿放入版本库。

本次提供的是可接自有支付中间层的通用签名协议；支付宝、微信、Stripe等官方商户签名格式、主动查单、自动退款调用及对账文件下载仍需相应适配器。仅填写某支付平台的商户号不会自动变成该平台的原生渠道。

收银台链接由 `payment.prepare` 生成，包含 `payload`（UTF8 JSON的十六进制字节）和 `signature`（对原始payload做HMAC-SHA256的十六进制结果）。payload固定包含 merchantId、orderId、amountMinor、currency、expiresAt。网关必须验签并核实真实渠道结果后回调，不能信任浏览器跳转返回的成功参数。

回调：`POST /api/webhook`，Content-Type application/json。头 `X-AWB-Timestamp` 是UTC秒，`X-AWB-Signature = hex(HMAC_SHA256(webhookSecret, timestamp + "." + 原始正文))`。正文：

```json
{"merchantId":"YOUR_MERCHANT","eventId":"UNIQUE_EVENT","transactionId":"UNIQUE_CHANNEL_TRANSACTION","orderId":"ORDER_ID","amountMinor":19900,"currency":"CNY","type":"paid"}
```

退款使用 `type=refunded`，且订单必须先申请全额退款。相同事件重试必须保持相同正文；重试可以使用新的当前时间和签名。重复事件/交易不会重复入账；金额、币种或商户不匹配会拒绝。已关闭订单的有效来款标记 `reconciliationRequired`，平台从核对列表使用 `payment.reconcile` 补记。

## 6 运行与开发环境

运行：Windows 10/11 x64、可写目录、包内VC142运行库。工作台真实浏览器功能使用包内Chromium；后台只使用Windows API和内置SQLite。后台默认仅监听回环，不需要管理员权限，端口冲突时可以运行 `Start-Admin.ps1 -Port 17862`，客户按实际地址连接。

当前未交付公网HTTPS反向代理配置、域名证书、远程节点部署与跨机验收；不要把当前回环服务直接当成公网商业站点。接入网关回调需后续配置受控HTTPS入口并验证Origin/Host转发策略。本次没有真实商户或公网回调验收。

停止：运行 `powershell -NoProfile -ExecutionPolicy Bypass -File Stop-Admin.ps1`。脚本请求正常关闭，待进程退出后再复制数据库；旧admin-endpoint.json可保留，重启时以新进程PID替换，不能仅凭文件存在判断服务在线。控制台方式也可 Ctrl+C。确认进程退出后，完整备份 `data\admin`（数据库、WAL/SHM若存在、支付配置及初始化信息）。恢复必须在停止服务后复制完整目录；不支持运行时直接覆盖数据库。用测试副本启动并验证账本后再切换，不能把已消耗的正式账务恢复成旧余额。

源码：VS2019“使用C++的桌面开发”、v142 14.29.30133、Windows SDK 10.0.19041.0。直接打开 `AIBrowserWorkbench.sln`，选择x64 Debug/Release，新增项目为 `workbench-admin`。CMake入口也已加入。生成程序无需Python/Node；开发测试和编辑门户使用Python、Node、Pillow。

门户源码在 `src/admin/web/index.html` 和 `portal.js`。修改后执行 `python tools/embed_admin_portal.py`，再编译；`--check`可核验源文件与嵌入资源一致。生成器切分原始字符串以兼容v142长度限制，不改变页面字节。所有自有源码使用原有UTF8无BOM/LF，新增函数带中文用途与日期。

| 未决启动恢复调用准入接口可能产生新的预留 | 增加只读slot.lookup，恢复查询不再申请新槽；不存在/存在的启动键均验证 |
| Windows PowerShell 5.1的默认HTTP头与BOMless中文注释解析影响停止/自测脚本 | 使用明确Content-Length且禁用Expect的HttpWebRequest；中文注释以ASCII句号结尾，保持UTF8无BOM/LF；启动、停止、实际订单收款自测通过 |
| 后台正常退出后保留的旧端点被启动轮询短暂打开，重启时原子替换报MoveFileEx failed:5 | PowerShell读取允许删除共享；后台只对相同端点元数据作最长约2秒有界重试；补充占住旧端点后重启的部署回归 |
| 部署测试捕获后台启动器输出管道时，Windows子进程继承管道导致communicate等待 | 启动器日志写文件，按启动器退出码和实际进程句柄分别验收；保留有界超时与私有停止 |
| 原生组织ID说明文字被截断、静态标签背景不一致 | 缩短标签，统一白色背景，补充可读的额度摘要；原生截图复核 |

## 9 后台API动作索引
